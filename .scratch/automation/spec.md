# Breath 自动化

Status: ready-for-agent

## Problem Statement

Breath 用户可以在工作会话中手动启动 Agent CLI，但无法把重复性的 Agent 工作保存下来，并在指定时间、固定间隔或外部命令到达时自动执行。当前活动栏中的“任务”入口只有空面板，而任务、任务分支、工作会话和托管工作树所表达的是可持续修改代码并接受评审的工作流，并不适合只想定期获得一次 Agent 分析结果的场景。

用户需要一个本地优先的自动化入口：保存固定 Prompt、选择一个已安装且兼容的 Agent、绑定一个 Workspace 并配置触发方式。自动化应在 Breath 仍运行时无头执行，直接读取真实 Workspace，但不能修改项目文件、创建工作会话、终端、分支或 Worktree。用户只关心本次运行最终产生的 Agent 输出，不希望保存临时副本、对话、工具日志、文件差异或大量历史。

自动运行还必须有清晰而保守的边界。调度不能依赖 Breath 云端、账户、后台服务或系统通知；应用完全退出时不能假装仍在运行。并发、睡眠、错过计划、Agent 或 Workspace 不可用、应用退出与崩溃都要有确定行为。外部触发应使用简单的 `breath trigger <短码>`，而不是要求用户启动 HTTP 服务、记忆 localhost 地址或处理 webhook payload。

## Solution

Breath 用“自动化”替换活动栏中尚未实现的“任务”入口。自动化页面采用高密度的列表与详情双栏布局，展示所有已保存自动化，按创建时间从新到旧稳定排列。用户通过新建或编辑表单配置名称、Workspace、固定 Prompt、执行 Agent、触发方式和最大运行时长；创建后默认启用，但不会立刻执行。

自动化支持仅手动、单次、每日、每周、固定间隔、自定义 Cron 和外部命令七种触发方式。日历计划使用当前 macOS 时区，Cron 使用标准五字段表达式；固定间隔以启用或修改规则的时间为锚点。Breath 只在应用进程仍运行时调度，不安装守护进程，也不补跑离线期间的工作；错过的计划只形成聚合的“已错过”记录。

每次运行通过对应 Agent 的无头执行适配器启动，当前真实 Workspace 作为只读工作目录。Agent 及其子进程受进程级 macOS 沙盒约束，只能写入本次运行专属的临时目录和临时 HOME；运行结束即销毁临时环境。运行不会创建 Work Session、Terminal Pane、Agent Conversation、Managed Worktree 或 Git 分支，也不会把结果写回 Workspace。

Breath 只持久化最终 Agent 输出、最小运行元数据和每个自动化最近五次运行记录。最终输出以 Markdown 渲染，可复制原始文本，但不提供“查看原文”模式。运行完成后只通过自动化活动栏图标上的数字角标提示未查看结果；成功、失败、超时和中断都不发送 macOS 系统通知。

外部触发使用 `breath trigger <短码>`。短码只属于外部触发类型，通过仅限当前用户的 Unix Domain Socket 发送给已经运行的 Breath；命令不会启动应用、不会接收动态输入，也不会等待或输出 Agent 最终结果。Breath 可在用户明确操作后把 CLI 安装到 `~/.local/bin/breath`，但不会静默安装、请求管理员权限或修改 PATH。

## User Stories

1. 作为使用 Breath 的开发者，我希望活动栏中的任务入口被自动化入口替换，从而不会进入一个尚未实现的任务空页面。
2. 作为使用现有导航习惯的用户，我希望自动化入口保持在原任务入口的位置，从而无需重新学习活动栏顺序。
3. 作为没有选中工作会话的用户，我希望仍能打开自动化页面，从而管理全局保存的自动化。
4. 作为没有添加 Workspace 的用户，我希望仍可浏览自动化库并打开创建表单；“所属工作区”下拉没有可选项，选择前不能保存自动化。
5. 作为没有自动化的用户，我希望列表保持安静留白，并始终可从顶部“新建自动化”按钮开始创建。
6. 作为已有大量自动化的用户，我希望使用左侧列表和右侧详情查看内容，从而高效浏览。
7. 作为窗口较窄的用户，我希望页面保持可读并使用适合窄宽度的详情呈现，从而不被强制双栏挤压。
8. 作为查找自动化的用户，我希望按名称或 Prompt 搜索，从而快速定位目标。
9. 作为搜索不到内容的用户，我希望看到无匹配结果并可一键清除搜索，从而返回完整列表。
10. 作为关注创建顺序的用户，我希望最新创建的自动化始终排在最上面，从而首先看到最近配置。
11. 作为不希望列表跳动的用户，我希望运行状态和编辑不会改变创建顺序，从而保持位置稳定。
12. 作为需要相似配置的用户，我希望允许多个自动化使用同名名称，从而不被人为唯一性限制。
13. 作为系统维护者，我希望每个自动化拥有不展示的唯一 ID，从而可靠关联配置、短码和运行历史。
14. 作为创建自动化的用户，我希望名称默认使用当前界面的本地化“未命名 / Untitled”，并可继续编辑，从而减少必填操作。
15. 作为创建自动化的用户，我希望必须选择一个 Breath Workspace，从而明确 Agent 要读取的项目。
16. 作为创建自动化的用户，我希望填写固定的多行 Prompt，从而定义每次运行的工作。
17. 作为使用 Markdown 的用户，我希望 Prompt 接受普通文本和 Markdown，从而保留清晰结构。
18. 作为希望结果可重复的用户，我希望 Prompt 不包含变量、模板或运行时输入，从而每次使用同一指令。
19. 作为创建自动化的用户，我希望只能选择已安装的 Agent，从而不看到无法运行的选项。
20. 作为 Agent 版本过旧的用户，我希望该 Agent 显示为禁用并说明当前版本和升级方式，从而知道如何恢复兼容。
21. 作为使用受支持 Agent 的用户，我希望选择器遵循 Breath 的 Agent 兼容矩阵，从而获得经过验证的无头运行能力。
22. 作为使用 Agent 默认模型的用户，我希望表单不增加模型选择器，从而沿用 Agent 自身配置。
23. 作为创建自动化的用户，我希望选择一种触发方式，从而定义自动运行时机。
24. 作为需要控制失控运行的用户，我希望配置最大运行时长并默认 60 分钟，从而自动终止过久任务。
25. 作为新建自动化的用户，我希望保存后默认启用，从而不必再次打开开关。
26. 作为新建自动化的用户，我希望创建动作本身不立即运行，从而先检查配置。
27. 作为编辑自动化的用户，我希望修改名称、Workspace、Prompt、Agent、触发规则和最大时长，从而持续维护配置。
28. 作为运行中编辑自动化的用户，我希望当前运行继续使用启动时配置，而修改只影响后续触发，从而避免中途改变语义。
29. 作为编辑自动化的用户，我希望已排队但未启动的运行直接取消，从而不会按旧配置稍后执行。
30. 作为禁用自动化的用户，我希望已排队运行直接取消，从而停止尚未开始的计划。
31. 作为禁用自动化的用户，我希望正在运行的实例继续执行，除非我另行点击取消，从而避免开关产生隐式终止。
32. 作为手动禁用自动化的用户，我希望仍可使用“立即运行”，从而临时执行而不恢复计划。
33. 作为手动运行已禁用自动化的用户，我希望运行后仍保持禁用，从而不意外恢复调度。
34. 作为依赖不可用的用户，我希望自动化自动暂停并显示具体原因，从而不会反复失败。
35. 作为 Workspace 路径暂时不可用的用户，我希望自动化保留而不是被删除，从而可在路径恢复后继续使用。
36. 作为 Workspace 已从 Breath 移除的用户，我希望自动化保留最后的绑定信息并要求改选 Workspace，从而不会静默绑定其他项目。
37. 作为 Agent 被卸载或版本变得不兼容的用户，我希望自动化自动暂停，从而不会启动无效运行。
38. 作为依赖恢复的用户，我希望 Breath 不自动重新启用自动化，从而由我确认后恢复执行。
39. 作为依赖仍不可用的用户，我希望“立即运行”不可用并显示原因，从而不会产生已知失败。
40. 作为删除自动化的用户，我希望看到确认提示，从而理解配置、短码和历史会永久删除。
41. 作为确认删除的用户，我希望已排队运行被取消、正在运行的实例被终止，从而彻底停止该自动化。
42. 作为确认删除的用户，我希望对应外部触发短码立即失效，从而不能再触发已删除对象。
43. 作为确认删除的用户，我希望项目文件完全不受影响，从而删除只作用于 Breath 数据。
44. 作为只需按需执行的用户，我希望选择“仅手动”，从而不配置计划。
45. 作为需要临时验证的用户，我希望任何可运行自动化都提供“立即运行”，从而无需等待计划时间。
46. 作为需要未来执行一次的用户，我希望选择单次日期和时间，从而安排一次运行。
47. 作为配置单次计划的用户，我希望过去时间不能保存，从而避免无意义计划。
48. 作为单次计划用户，我希望计划触发后无论成功、失败、超时、取消或中断都自动禁用，从而不会重复运行。
49. 作为单次计划用户，我希望错过计划后生成一条已错过记录并自动禁用，从而明确知道它没有执行。
50. 作为已经消费单次计划的用户，我希望“再次运行”只进行一次手动运行而不恢复原计划，从而避免误解。
51. 作为提前手动测试单次自动化的用户，我希望手动运行不消费未来的单次计划，从而保留原定执行。
52. 作为每天执行固定工作的用户，我希望选择每日时间，从而无需编写 Cron。
53. 作为每周执行工作的用户，我希望选择一个或多个星期和时间，从而表达常见周计划。
54. 作为需要复杂日历计划的用户，我希望填写标准五字段 Cron 表达式，从而配置月份等高级规则。
55. 作为使用 Cron 的用户，我希望只支持分钟、小时、日、月、星期五个字段，从而保持规则明确。
56. 作为使用 Cron 的用户，我希望不支持秒字段和 `@daily` 等宏，从而避免不同实现间的歧义。
57. 作为输入 Cron 的用户，我希望获得实时校验并在无效时禁止保存，从而及时修正。
58. 作为检查 Cron 的用户，我希望看到当前系统时区下未来三次预计时间，从而验证表达式。
59. 作为需要每月执行的用户，我希望使用 Cron 表达月份规则，从而不需要独立“每月”表单。
60. 作为按固定节奏执行的用户，我希望选择正整数和分钟、小时或天作为间隔，从而配置简单周期。
61. 作为配置间隔的用户，我希望最短为 1 分钟、最长为 30 天，从而避免无效或失控频率。
62. 作为启用间隔计划的用户，我希望首次运行等待完整间隔，从而不会因启用立即执行。
63. 作为修改间隔规则的用户，我希望修改时建立新锚点并等待完整新间隔，从而获得可预测节奏。
64. 作为重新启用间隔计划的用户，我希望重新启用时建立新锚点，从而不补算禁用期间的间隔。
65. 作为使用日历计划的用户，我希望每日、每周和 Cron 跟随当前 macOS 时区，从而适应时区变化。
66. 作为使用单次计划的用户，我希望单次时间保存为绝对时刻，从而切换时区不会改变真实执行时刻。
67. 作为使用间隔计划的用户，我希望间隔按持续时间计算而不受时区变化影响，从而保持固定节奏。
68. 作为重新启用每日、每周或 Cron 的用户，我希望等待下一个未来时刻，从而不立即运行。
69. 作为重新启用已过期单次计划的用户，我希望必须先编辑为未来时间，从而不意外补跑。
70. 作为应用窗口已关闭但 Breath 仍运行的用户，我希望计划继续执行，从而无须保持窗口可见。
71. 作为 Breath 已完全退出的用户，我希望计划不会执行，从而符合无守护进程的本地边界。
72. 作为电脑睡眠期间到达计划时间的用户，我希望该次计划不在唤醒后补跑，从而避免突然执行过期工作。
73. 作为错过多次重复计划的用户，我希望只看到一条带次数和时间范围的“已错过”记录，从而减少历史噪声。
74. 作为查看错过计划的用户，我希望错过记录不增加未查看角标，从而角标只代表实际完成的运行。
75. 作为使用外部系统的用户，我希望选择“外部命令触发”，从而在本机脚本中启动自动化。
76. 作为外部触发用户，我希望获得简短的 `breath trigger <短码>` 命令，从而不处理 localhost 地址。
77. 作为外部触发用户，我希望每个外部触发自动化拥有稳定短码，从而编辑其他配置不破坏脚本。
78. 作为安全维护短码的用户，我希望通过确认操作重新生成短码，从而立即废止旧值。
79. 作为切换离开外部触发的用户，我希望原短码立即失效，从而不保留无用入口。
80. 作为再次切回外部触发的用户，我希望获得新短码，从而旧脚本不会意外恢复。
81. 作为复制触发命令的用户，我希望详情和更多菜单提供复制操作，从而避免手工输入。
82. 作为外部触发调用者，我希望命令只触发已保存 Prompt，不接受参数、payload 或 stdin，从而保持运行定义固定。
83. 作为外部触发调用者，我希望命令快速返回已启动或已排队结果，而不等待 Agent 完成，从而适合脚本调用。
84. 作为 Breath 未运行时调用 CLI 的用户，我希望得到非零退出码和“Breath is not running”，从而明确失败原因。
85. 作为使用无效或已删除短码的用户，我希望得到非零退出码且不创建运行，从而不会误以为触发成功。
86. 作为触发已禁用自动化的用户，我希望得到禁用错误且不创建运行，从而尊重配置状态。
87. 作为尚未安装 Breath CLI 的用户，我希望创建外部触发时看到一键安装选项，从而完成本机配置。
88. 作为谨慎的用户，我希望 CLI 只在明确点击后安装到 `~/.local/bin/breath`，从而不被静默修改环境。
89. 作为没有管理员权限的用户，我希望 CLI 安装不需要管理员权限，从而可在个人环境使用。
90. 作为管理 Shell 环境的用户，我希望 Breath 不修改 PATH，从而保留现有配置控制权。
91. 作为本机用户，我希望 CLI 通过仅限当前用户的 Unix Domain Socket 通信，从而不开放 HTTP 端口。
92. 作为不希望启动 GUI 的脚本用户，我希望 CLI 在 Breath 未运行时不自动启动应用，从而保持调用可预测。
93. 作为运行自动化的用户，我希望 Agent 在后台无头执行，从而不创建终端窗口或抢占焦点。
94. 作为 Workspace 用户，我希望 Agent 直接读取当前真实项目文件，从而分析最新本地状态。
95. 作为不希望复制项目的用户，我希望 Breath 不为自动化建立项目副本或快照，从而避免额外存储与过期内容。
96. 作为运行期间继续编辑项目的用户，我希望自动化允许观察到运行中的真实变化并标明该语义，从而理解结果不是固定快照。
97. 作为保护代码的用户，我希望 Workspace 对 Agent 及其子进程严格只读，从而自动化不能修改项目文件。
98. 作为保护本机的用户，我希望运行不能写入 Workspace 之外的任意本地路径，从而限制副作用。
99. 作为 Agent 需要缓存的用户，我希望每次运行拥有独立临时可写目录和临时 HOME，从而满足必要运行时写入。
100. 作为隐私敏感用户，我希望临时目录在运行结束、失败、取消、超时或中断后销毁，从而不留下运行副本。
101. 作为已配置 Agent 的用户，我希望自动化复用该 Agent 的认证、配置和全局 Skills，从而无需再次登录。
102. 作为凭据敏感用户，我希望 Breath 不额外读取、展示或持久化 Agent 凭据，从而保持现有认证边界。
103. 作为需要联网分析的用户，我希望 Agent 可以进行出站网络访问，从而使用其正常在线能力。
104. 作为保护本机的用户，我希望自动化不开放入站网络服务、不启动 GUI、不执行系统设置变更，从而保持固定权限边界。
105. 作为不在场用户，我希望运行不弹出交互授权请求，从而不会无限等待。
106. 作为沙盒无法建立的用户，我希望运行在启动 Agent 前失败并说明原因，从而绝不降级为非沙盒执行。
107. 作为项目维护者，我希望自动化不创建 Work Session、Terminal Tab、Terminal Pane、Agent Conversation、Managed Worktree 或 Git 分支，从而与交互工作台边界分离。
108. 作为同时运行不同自动化的用户，我希望默认最多并行运行 2 个，从而平衡吞吐与资源。
109. 作为需要调整资源的用户，我希望全局并发上限可配置为 1 至 4，从而适配设备能力。
110. 作为并发已满的用户，我希望其他自动化按触发时间先进先出排队，从而顺序可预测。
111. 作为等待中的用户，我希望可以取消排队运行，从而不必等到启动。
112. 作为同一自动化已经排队或运行的用户，我希望新的触发被记为“已跳过”而不再排队，从而避免自身重叠。
113. 作为同一自动化正在运行的用户，我希望“立即运行”按钮禁用，从而避免重复点击。
114. 作为调整并发上限的用户，我希望降低上限不会终止现有运行，而提高上限会继续消费队列，从而行为安全可预测。
115. 作为取消运行的用户，我希望 Breath 终止 Agent 及其子进程、销毁临时目录并标记“已取消”，从而完整停止工作。
116. 作为取消运行的用户，我希望不保存部分输出，从而只把完整最终回答当作结果。
117. 作为运行超时的用户，我希望 Agent 被终止并标记“已超时”，从而释放资源。
118. 作为电脑自动睡眠的用户，我希望正在运行的自动化阻止空闲系统睡眠但不阻止显示器睡眠，从而兼顾完成工作与节能。
119. 作为主动让电脑睡眠的用户，我希望运行暂停并在唤醒后继续，从而尊重手动睡眠。
120. 作为经历睡眠的用户，我希望最大运行时长不计算睡眠时间，从而不会因系统暂停而误超时。
121. 作为退出 Breath 的用户，我希望存在运行中自动化时看到确认提示，从而理解退出会中断它们。
122. 作为确认退出的用户，我希望运行中实例终止、排队实例取消、临时目录销毁，从而不留下孤儿进程。
123. 作为确认退出的用户，我希望运行中记录标记为“已中断”，从而与主动取消区分。
124. 作为 Breath 崩溃后重新启动的用户，我希望残留的运行中记录修复为“已中断”，从而数据库不长期显示运行中。
125. 作为崩溃恢复用户，我希望 Breath 不自动恢复或重跑中断实例，从而避免未知副作用。
126. 作为查看运行状态的用户，我希望看到已排队、运行中、成功、失败、已超时、已取消、已中断、已跳过和已错过九种明确状态，从而理解结果。
127. 作为判断成功的用户，我希望只有 Agent 正常退出且提供非空最终输出时才标记成功，从而避免空成功。
128. 作为运行失败的用户，我希望启动失败、非零退出或缺少最终输出被标记失败，从而状态真实。
129. 作为查看失败的用户，我希望没有最终输出时只保存清理后的简短错误摘要，从而获得信息且不泄露环境。
130. 作为查看成功结果的用户，我希望最终 Agent 输出以 Markdown 渲染，从而正确阅读标题、代码和表格。
131. 作为需要复用结果的用户，我希望复制按钮复制原始文本，从而粘贴到其他工具。
132. 作为只想看结果的用户，我希望不出现“查看原文”或编辑模式，从而减少无用操作。
133. 作为不希望保存过程的用户，我希望 Breath 不保存中间对话、流式片段、工具日志、命令日志或 stderr，从而只保留最终输出。
134. 作为不希望产生文件成果的用户，我希望运行不提供 Diff、Artifact、导出文件或应用变更功能，从而保持只读分析定位。
135. 作为面对超长结果的用户，我希望持久化输出上限为 256 KiB，并保留开头、结尾及明确截断标记，从而兼顾上下文与存储。
136. 作为查看运行详情的用户，我希望看到状态、触发来源、开始与结束时间、时长、Agent，以及可靠可知时的模型，从而理解运行背景。
137. 作为查看项目版本的用户，我希望在可解析时看到启动时 Workspace 根仓库的 Git Commit，并看到 Workspace 可能在运行中变化的提示，从而正确解释结果。
138. 作为控制本地存储的用户，我希望每个自动化只保留最近 5 次运行，从而不积累大量历史。
139. 作为产生第 6 次运行的用户，我希望最旧记录自动淘汰，从而历史上限无需手工维护。
140. 作为删除自动化的用户，我希望其最近 5 次历史一起永久删除，从而不留孤立结果。
141. 作为查看自动化列表的用户，我希望每行看到名称、单行 Prompt、Agent、Workspace、触发摘要、下次时间、最近状态和时间，从而无需打开详情即可判断。
142. 作为列表操作用户，我希望每行提供启用开关和“立即运行”，从而完成高频操作。
143. 作为详情用户，我希望看到完整 Prompt、Agent、Workspace、触发规则、下次时间和最近 5 次历史，从而集中检查配置与结果。
144. 作为查看历史的用户，我希望只有点击具体运行记录才打开其结果并标为已查看，从而不会误清未读状态。
145. 作为只打开自动化详情的用户，我希望未读结果保持未读，从而角标准确。
146. 作为已经看过最新记录的用户，我希望它可以默认展开，从而快速回到最近内容。
147. 作为等待运行完成的用户，我希望自动化活动栏图标显示未查看完成结果数量，从而无需系统通知。
148. 作为有大量未读结果的用户，我希望角标超过 99 时显示 `99+`，从而保持图标整洁。
149. 作为查看某条未读记录的用户，我希望角标只减少这一条，从而不会清除其他结果。
150. 作为重启 Breath 的用户，我希望未读状态继续保留，从而不会漏看完成结果。
151. 作为关注有效结果的用户，我希望成功、失败、超时和中断计入角标，而取消、跳过、错过、排队和运行中不计入，从而数字代表需要查看的结束结果。
152. 作为不希望被打扰的用户，我希望成功、失败、超时和中断都不发送 macOS 系统通知，从而所有反馈留在应用内。
153. 作为 VoiceOver 用户，我希望自动化入口读出未读数量，且表单、状态、禁用原因和历史拥有明确语义，从而不依赖视觉理解。
154. 作为键盘用户，我希望能够完成导航、创建、编辑、运行、取消、查看结果和删除，从而不依赖鼠标。
155. 作为中英文环境用户，我希望自动化页面、调度摘要、状态和错误遵循应用语言，从而保持一致体验。

## Implementation Decisions

- 更新项目领域词汇：新增“自动化（Automation）”“自动化运行（Automation Run）”“自动化短码（Automation Shortcode）”和“运行沙盒（Run Sandbox）”；活动栏顺序改为“工作区、自动化、Git、Skills、额度”。任务及其分支、执行和评审能力不在本 PRD 中实现。
- 自动化是全局主内容模式，但每个自动化必须绑定一个现有 Workspace。它不属于 Work Session，也不在 Workspace 会话树中创建节点。
- 为自动化领域建立独立模块，拥有配置、触发规则、调度状态、运行状态机、并发队列、依赖可用性、未读状态和运行编排；App Shell 只调用公开用例并渲染快照。
- 自动化配置包含不展示的稳定唯一 ID、名称、Workspace 绑定、固定 Prompt、Agent 标识、触发规则、最大运行时长、启用状态、依赖暂停状态、创建时间和更新时间。
- 名称不要求唯一。列表按创建时间降序；创建时间相同时使用内部 ID 作稳定排序。编辑和运行永不改变排序。
- Prompt 是固定的多行纯文本/Markdown，不支持变量、模板、附件、运行参数或上下文注入。Breath 可以附加固定系统说明，告知 Agent Workspace 只读、只能写临时目录并要求提供单个最终回答。
- Agent 选择来源于 ADR 0008 的受支持 Agent CLI 兼容矩阵和自动化无头运行能力契约。未安装 Agent 不显示；已安装但版本低于最低兼容版本的 Agent 显示为禁用并附升级说明。
- Codex、Claude Code、Gemini CLI、GitHub Copilot CLI、Qwen Code、Cursor Agent、Factory Droid、OpenCode 和 Pi 分别提供无头运行适配器。某个适配器不能可靠启动、取消并提取最终回答时，该 Agent 不得作为可选项伪装可用。
- 不提供模型选择器。运行使用所选 Agent 当前默认模型与用户配置；只有适配器能从可靠结构化结果确认模型时才写入运行元数据。
- 最大运行时长使用正整数分钟，默认 60 分钟。计时只累计系统清醒期间的实际运行时间，不累计睡眠暂停。
- 新建自动化默认启用，但创建不产生运行。日历规则等待下一未来时刻，间隔规则等待完整间隔，外部触发等待命令，手动规则等待用户操作。
- 自动化的用户启用状态与依赖暂停状态分离。用户禁用仍允许立即运行；Workspace 或 Agent 不可用导致的依赖暂停禁止任何运行。
- Workspace 路径不可用、Workspace 被移除、Agent 被卸载或 Agent 版本不兼容时进入依赖暂停，并保留自动化。被移除的 Workspace 使用空绑定和最后可展示摘要，必须由用户编辑选择 Workspace。
- 依赖恢复不自动启用。用户必须显式重新启用；重新启用按当前时间重新计算下一次计划，间隔规则建立新锚点。
- 编辑或禁用自动化会取消属于它的全部排队运行并记录为已取消。正在运行的实例持有启动配置快照并继续，除非用户显式取消。
- 删除是永久操作，需要确认；它取消排队运行、终止活动进程树、销毁临时目录、删除最多五条历史和配置，并使短码立即失效。
- 触发规则是封闭枚举：仅手动、单次日期时间、每日时间、每周星期集合与时间、固定间隔、自定义 Cron、外部命令。
- 单次计划保存绝对时间。保存时必须位于未来；系统时区变化不改变执行时刻。只有计划触发本身会消费单次规则，提前的“立即运行”不消费。
- 单次计划触发后，无论成功、失败、超时、取消或中断都自动禁用；错过时创建一条已错过记录并禁用。“再次运行”是普通手动触发，不恢复计划。
- 每日、每周和 Cron 使用当前 macOS Calendar 与 TimeZone 动态计算。时区变化后重新计算下一个未来时刻，不修改规则本身。
- Cron 只接受标准五字段“分钟 小时 日 月 星期”，不接受秒字段和宏。编辑时实时校验，并展示当前时区下未来三次 occurrence。
- 不提供专门的每月规则；每月、每月某日等需求使用 Cron。
- 固定间隔由正整数和分钟、小时、天组成，最短 1 分钟、最长 30 天。锚点是创建后首次启用、重新启用或修改触发规则的时刻，不以运行完成时间重新计时。
- 对日历重复时间，每个计划 occurrence 最多触发一次；因夏令时不存在的本地时间视为错过，重复出现的本地分钟只执行一次。调度记录稳定 occurrence 标识以防系统时钟回拨重复运行。
- 调度只存在于正在运行的 Breath 进程中。关闭主窗口不停止调度；完全退出后没有 launchd、登录项守护进程或云端调度器继续运行。
- 应用启动、恢复活动或系统唤醒时执行计划对账。离线或睡眠期间不补跑；重复计划的一个或多个过期 occurrence 聚合成一条已错过记录，包含数量、最早和最晚计划时间，然后计算下一个未来时刻。
- 已错过记录进入最近五次历史但永不计入未读角标。禁用期间不创建已错过记录，也不追踪未执行次数。
- 每个自动化最多有一个 in-flight 运行，in-flight 包括已排队和运行中。任何触发遇到自身已有 in-flight 运行时立即产生已跳过记录，不加入队列。
- 全局并发上限持久化为应用级设置，默认 2，可选 1 至 4。空闲槽位按触发时间先进先出启动不同自动化；时间相同时用运行 ID 稳定排序。
- 降低并发上限不终止活动运行；在活动数降到新上限前不再启动队列。提高上限立即按 FIFO 消费队列。
- 运行状态机只包含：已排队、运行中、成功、失败、已超时、已取消、已中断、已跳过、已错过。已排队和运行中是非终态，其余是终态。
- “立即运行”在没有 in-flight 且依赖可用时创建运行。用户禁用不阻止它，也不改变启用状态；依赖暂停阻止它。
- 外部触发仅在触发类型仍是外部命令、自动化已启用且依赖可用时接受。无效短码、用户禁用或依赖暂停直接返回错误且不创建运行。
- 外部触发为每个相关自动化生成高熵、不含业务含义、便于复制的稳定短码。短码与内部自动化 ID 分离；编辑名称、Prompt、Agent、Workspace 或时长不改变短码。
- 重新生成短码需要确认并原子废止旧码。离开外部触发类型会删除短码；再次选择时生成新码。
- `breath trigger <短码>` 只发送触发请求并等待 Breath 确认接受、排队或拒绝，不等待 Agent 完成，也不输出最终结果。接受或排队返回零；应用未运行、短码无效、禁用、依赖暂停或自身 in-flight 返回非零和清理后的短消息。
- CLI 使用版本化、本机、同一 macOS 用户可访问的 Unix Domain Socket 协议，不启动 HTTP listener、不使用自定义 URL scheme，也不启动 Breath GUI。Socket 文件权限为 `0600`。
- 自动化触发协议与现有 Agent 事件协议共享本地 Socket 基础设施和实例发现方式，但使用独立的版本化消息类型，不能伪造 Work Session 或 Terminal Pane 身份。
- Breath 提供显式的一键 CLI 安装，将入口写入 `~/.local/bin/breath`。存在非 Breath 管理的同名文件时不覆盖；安装失败显示可操作原因。安装不请求管理员权限，不修改 Shell 配置或 PATH。
- 自动化运行不创建 Work Session、Terminal Tab、Terminal Pane、Agent Conversation、Managed Worktree、Session Branch 或 Task Branch，也不向现有 Agent 对话注入 Prompt。
- Agent 进程的工作目录是绑定 Workspace 的真实路径。Breath 不复制、克隆、stash、checkout 或快照项目；运行期间看到的文件可能随用户或其他进程变化。
- 在可解析时记录运行启动时 Workspace 根 Git 仓库的 HEAD Commit；同时始终标记“实时 Workspace，运行期间可能变化”。无法解析 Git 时该字段为空而不使运行失败。
- 每次运行建立独立进程级 macOS 沙盒。Workspace 和其他用户文件只读；唯一通用可写位置是本次运行专属临时目录和临时 HOME。权限必须继承到 Agent 启动的全部子进程。
- 沙盒允许启动所选 Agent 及其正常所需的本地开发工具，允许出站网络；禁止入站监听、GUI 自动化、系统设置修改、写 Workspace、写其他本地目录和额外放宽 Keychain 访问。
- Agent 沿用其已存在的认证、配置和全局 Skills。实现只把运行所需的普通文件与目录投影到临时 HOME，跳过符号链接、Unix Socket、FIFO 等特殊文件，或让 Agent 通过其既有受控认证机制读取；Breath 不解析、展示、记录或上传凭据。
- Breath 的外层进程沙盒是唯一权限边界。Agent 适配器不得在其中再次创建 macOS 沙盒；Codex 使用由外部环境提供沙盒且不交互审批的执行模式，但整个进程树仍继承 Breath 的只读 Workspace、临时目录可写和其他拒绝规则。
- 固定权限策略不提供交互批准。被沙盒拒绝的操作保持拒绝；如果无法建立强制沙盒，运行在启动 Agent 前失败，绝不退化为普通进程执行。
- 运行时创建防空闲系统睡眠断言，但不阻止显示器休眠，也不阻止用户主动睡眠。断言只覆盖运行中实例，不覆盖排队。
- 用户主动睡眠暂停进程，由系统唤醒后继续。运行超时使用排除睡眠时段的有效时长。
- 取消、超时、删除和确认退出都终止 Agent 完整进程树；先请求正常终止，短暂宽限后强制结束，并在确认进程退出后销毁临时目录。
- 应用退出时若存在活动运行则确认。确认后活动运行标记已中断、排队运行标记已取消；取消退出则一切继续。
- 启动恢复把上次崩溃遗留的已排队或运行中记录修复为已中断或已取消，清理可识别的遗留临时目录，不恢复、不重试。
- Agent 正常退出且产生非空最终回答才是成功。非零退出、启动失败、适配器无法提取最终回答或空回答是失败；达到最大时长是已超时。
- 不保存流式内容、部分回答、工具调用、命令、stdout/stderr 全量日志、环境变量、进程参数、Agent Conversation 或临时文件。
- 没有最终回答时只保存经过清理的短错误摘要，例如未安装、认证失败、退出码、空输出、沙盒失败或超时；摘要不得包含环境变量、凭据、完整命令行和无关路径。
- 最终输出按 UTF-8 最多持久化 256 KiB。超限时在上限内保留尽可能均衡的开头和结尾，并插入明确截断标记；正常退出且非空时仍标记成功，并设置输出已截断元数据。
- 每条运行最小元数据包含内部运行 ID、自动化 ID、状态、触发来源、计划 occurrence 信息、排队/开始/结束时间、有效时长、Agent、可靠可知的模型、起始 Git Commit、实时 Workspace 标记、截断标记、错误摘要和已查看状态。
- 已排队和运行中的记录可以显示持续变化的相对时间；成功、失败、超时、取消、中断、跳过和错过等终态记录必须显示固定结束时间，不能继续增长而造成仍在运行的误解。
- 每个自动化最多保留最近五条运行，包括已跳过和已错过。创建第六条时淘汰最旧终态记录；不会为了上限删除当前 in-flight 记录，待其终结后再收敛到五条。
- 成功、失败、已超时和已中断的新终态记录默认未查看并计入活动栏角标；已取消、已跳过和已错过不计入，已排队与运行中尚未完成也不计入。
- 未读状态和角标在 SQLite 中持久化。只有用户打开具体运行记录才将其标记已查看；打开自动化详情、切换页面或重启应用不批量清除。
- 活动栏角标显示总未读数，超过 99 显示 `99+`。VoiceOver 名称包含未读数量。
- 最终输出使用完整的 GitHub Flavored Markdown 块级渲染，覆盖标题、段落、嵌套有序/无序与任务列表、引用、分隔线、代码块、表格、强调、删除线、行内代码、链接、图片替代文本和换行，并允许复制原始文本；原始 HTML 只按代码展示、远程图片不自动请求，不提供“查看原文”切换、编辑、Diff、Artifact、导出或应用到 Workspace。
- 自动化页面左侧列表按创建时间降序，行展示名称、Prompt 单行摘要、Agent、Workspace、触发摘要、下次计划、最近状态与时间、启用开关和立即运行。
- 双栏模式下，左侧搜索栏与右侧详情标题栏使用相同固定高度和普通内容边距；详情标题与启用状态在同一行，不为窗口红绿灯重复预留左侧空间。
- 行点击打开右侧详情；更多菜单提供编辑、定位历史、在外部触发时复制命令和删除。详情头部提供名称、状态、立即运行、取消运行和编辑。
- 详情展示完整 Prompt、Agent、Workspace、触发规则、当前时区、下次计划、依赖暂停原因及最近五条历史；点击具体历史后展示最终输出或清理后的错误摘要。
- 没有 Workspace 时仍可浏览自动化库并打开创建表单；表单中的“所属工作区”下拉显示无可选项，选择 Workspace 前不能保存。没有兼容 Agent 时在表单中说明需安装或升级 Agent，而不是展示不可保存的空选择。新建名称默认使用当前界面的本地化“未命名 / Untitled”。
- “Agent 直接读取真实工作区，但 macOS 沙盒会阻止它修改项目文件。”属于静态解释，只能通过新建/编辑标题后紧邻的 `ExplanationLabel` 信息图标展示，提供 300ms tooltip 和 VoiceOver 提示，不得作为表单正文或页脚。
- 使用原生 SwiftUI 语义、键盘焦点和应用现有中英文资源。状态、暂停原因、角标和错误不能只依赖颜色或图标。
- Persistence 模块增加自动化配置、外部短码、全局并发设置和运行记录的 GRDB migration 与 repository；SwiftUI 不依赖数据库 row 类型。
- 自动化与 Workspace 的持久化关系允许 Workspace 记录被移除后保留自动化和最后显示摘要，避免级联删除。重新绑定必须由用户显式编辑。
- 本功能遵守 ADR 0001 的通用终端与可选适配器边界、ADR 0005 的站外发行边界、ADR 0008 的 Agent 支持矩阵、ADR 0009 的非侵入式集成、ADR 0010 的本地 Socket、ADR 0012 的本地优先、ADR 0013 的 GRDB 隔离、ADR 0017 的单窗格单对话，以及 ADR 0020 的 Work Session 所有 Worktree 边界。
- 在实现前补充架构记录，固化“自动化不属于工作会话”“真实 Workspace 的强制只读进程沙盒”和“本地 CLI 短码通过 UDS 触发”三项跨模块决策。

## Testing Decisions

- 主要测试 Seam 是公开的自动化用例服务。测试只通过创建、编辑、启停、删除、推进时间、手动触发、外部触发、取消、依赖变化、睡眠、唤醒、退出和启动恢复等公开行为驱动系统，并观察服务快照、运行历史、Runner 调用、持久化重启结果和 Workspace 最终内容。
- 主要测试使用临时真实 SQLite 数据库和临时真实 Workspace，并注入虚拟时钟、Agent 可用性注册表、记录型 Automation Runner、沙盒执行器、电源断言和应用生命周期。这样在一个最高可行 Seam 覆盖状态机、调度、并发、保留、未读和恢复，而不测试私有 helper。
- 创建与编辑测试覆盖必填字段、重复名称、隐藏 ID、默认启用、不立即运行、Agent 隐藏/禁用规则、配置快照、排队取消和依赖暂停。
- 调度测试覆盖单次、每日、多星期、间隔和五字段 Cron，包括未来三次预览、时区变化、系统时钟前后跳、夏令时不存在/重复分钟、重新启用锚点和禁用期间不留记录。
- 离线对账测试覆盖应用退出、窗口关闭、系统睡眠、一个与多个错过 occurrence、聚合次数/范围、单次自动禁用、重复计划下次时间和不补跑。
- 并发测试覆盖默认 2、设置 1 至 4、FIFO、提高/降低上限、不同自动化并行、同一自动化排队或运行时跳过、排队取消，以及编辑、禁用、删除和退出对队列的影响。
- 状态机测试覆盖九种公开状态和所有允许转换，特别验证空最终回答不能成功、手动取消不计未读、退出/崩溃是中断、计划错过不是失败。
- 生命周期测试覆盖关闭窗口仍调度、确认或取消应用退出、崩溃后的 stale record 修复、临时目录清理、不恢复运行和排队取消。
- 输出测试覆盖完整 GFM 块级与行内结构、Markdown 原始文本、非 UTF-8 清理、空输出、256 KiB 边界、首尾截断标记、错误摘要脱敏、最近五条淘汰和删除级联清理。
- 未读测试覆盖四种计数状态、其他状态排除、点击具体记录单条清除、只打开详情不清除、重启保留以及 `99+`。
- Workspace 只读测试在真实临时项目中放置已跟踪、未跟踪和嵌套文件，运行试图创建、修改、删除、重命名和执行子进程写入的 sentinel，断言全部项目内容与权限语义保持不变。
- 必要的运行边界契约测试遍历每个受支持 Agent 的无头适配器，验证版本检测、命令启动、最终回答提取、正常退出、非零退出、空输出、认证错误、取消、超时和完整进程树结束。
- macOS 沙盒契约测试使用真实受限进程验证 Workspace 与其他用户路径不可写、临时 HOME 可写、子进程继承限制、出站网络策略、入站监听拒绝、无法建立沙盒时 fail closed，以及清理后无临时内容。
- CLI/UDS 契约测试覆盖显式安装、已有文件冲突、Socket `0600`、应用未运行、有效/无效/旧短码、禁用、依赖暂停、排队、in-flight 跳过、协议版本错误和不携带动态输入。它属于运行边界契约，不建立第二套业务状态机测试。
- App Shell 使用现有可访问性渲染验证器作为唯一 UI 验收 Seam，覆盖活动栏入口替换、角标、紧凑空状态、搜索、稳定排序、表单、列表、详情、历史点击、取消、禁用原因和 VoiceOver 名称。自动化列表和未选择详情属于被动状态，不使用带大图标、大标题或说明文案的 `ContentUnavailableView`。
- Persistence 不建立重复业务测试；主要用例测试直接使用临时真实 GRDB repository，并补充 migration、Workspace 删除后绑定保留、短码唯一性、五条历史和未读 round-trip 等不可替代契约。
- 现有全局 Skills 用例服务测试提供“公开服务 + 临时真实目录 + 注入 Provider/时钟/repository”的主要先例；Agent 额度服务提供可注入 Agent 能力与进程 Runner 的先例；启动恢复测试提供真实临时 SQLite 与应用模型重启先例；App Shell 空状态验证器提供导航与可访问性先例。
- 测试断言用户可观察结果，不绑定 actor 划分、私有方法、SQL 文本、具体 Swift 类型布局、定时器实现、队列容器或进程命令拼接顺序。
- 人工验收至少覆盖一个日历计划、一个间隔计划、一个 Cron、一次外部 CLI 触发、窗口关闭、应用退出、系统睡眠、两个并行 Agent、真实取消、只读写入拒绝、历史截断、未读角标、VoiceOver 和键盘操作。

## Out of Scope

- 任务视图、任务状态、任务分支、任务执行、验收目标、任务评审和评审意见。
- 为自动化创建 Work Session、Terminal Tab、Terminal Pane、Agent Conversation、Managed Worktree 或任何 Git 分支。
- 复制、快照、克隆、stash、checkout 或保存 Workspace 副本。
- 允许 Agent 修改项目、自动应用结果、展示或提交 Diff、创建 Artifact、导出文件或回写代码。
- 保存中间对话、流式输出、工具调用、命令日志、完整 stdout/stderr、环境变量或 Agent 原生会话。
- Prompt 变量、模板、附件、运行时参数、stdin、payload、动态上下文或不同自动化间的输出传递。
- HTTP webhook、localhost 端口、自定义 URL scheme、文件变化、Git 事件、Agent 生命周期事件或远程云事件触发。
- 专门的每月规则、Cron 秒字段、Cron 宏或完整 Unix/Vixie Cron 环境变量语法。
- Breath 完全退出后的调度、launchd 守护进程、登录项执行器、云端调度、账户、同步、远程控制或服务端。
- 离线计划补跑、自动重试、失败退避、断点恢复、运行续接或崩溃后自动重跑。
- 自动化链、依赖图、条件分支、审批步骤、共享输入或结果导出 API。
- 同一自动化并行运行或为同一自动化保留多个待执行队列项。
- 按自动化配置不同网络策略、交互权限审批、GUI 自动化、系统设置或任意本机写权限。
- Agent 模型选择、Agent 会话恢复、任意未进入支持矩阵的 CLI 或无法可靠提取最终回答的 Agent。
- macOS 系统通知、邮件、声音、Webhook 回调或其他完成通知。
- 超过最近五次的长期历史、历史搜索、归档、恢复、原始日志查看或“查看原文”模式。
- 自动安装 CLI、自动修改 PATH、管理员级安装、全局 HTTP 服务或 Breath 未运行时由 CLI 启动应用。
- Windows、Linux、移动端或 Mac App Store App Sandbox 支持。

## Further Notes

- 本 PRD 中的“Workspace”使用现有领域定义：用户添加到 Breath 的一个本地项目目录。自动化绑定 Workspace，但不是 Workspace 会话树中的工作会话。
- “自动化运行”是一次无头、不可恢复、只产出最终回答的执行，不是 Agent Turn、Agent Conversation、Task Execution 或终端进程记录。
- 真实 Workspace 只读和运行期间可变化必须同时成立：结果反映 Agent 实际读取到的实时内容，但 Breath 保证 Agent 进程树不能通过自动化权限修改这些内容。
- 出站网络意味着 Agent 仍可能访问其正常在线服务；本 PRD 的只读保证针对本机文件和系统能力，不把远程第三方服务声明为只读。
- 短码是本机同一用户范围内的触发标识，不是互联网 webhook 凭据。仍应使用高熵随机值，并在日志与错误中避免无必要暴露。
- 本 PRD 的测试 Seam 已由用户确认：公开自动化用例服务是主 Seam；真实 Agent/沙盒/CLI 是窄契约边界；App Shell 可访问性渲染器只验证 UI。
- 本 PRD 已综合当前已确认的产品决策，可直接交给 Agent 拆分实施；本次发布不包含功能实现。
