# 按单次、每日和每周计划运行自动化

Status: ready-for-agent

## Parent

[Breath 自动化](../spec.md)

## What to build

建立只随 Breath 应用进程运行的本地 Automation 调度器，并交付单次、每日和每周三类常用计划。计划触发进入统一并发队列；应用关闭窗口后继续调度，完全退出或系统睡眠期间不执行、不补跑，只记录聚合的“已错过”结果。

本切片覆盖 PRD User Stories 46–53、65–66、68–74，并为 Interval 和 Cron 切片提供共同的时区、occurrence、错过对账和下一次计划能力。

## Acceptance criteria

- [ ] 创建和编辑表单支持单次绝对日期时间、每日时间、一个或多个星期与时间，并展示当前时区和下一次计划
- [ ] 单次计划只能保存未来时刻，保存为绝对时间；系统时区变化不改变其真实执行时刻
- [ ] 每日和每周计划使用当前 macOS Calendar 与 TimeZone 动态计算，时区变化后选择下一个未来 occurrence
- [ ] 创建和重新启用不会立即运行，单次、每日和每周都等待下一未来 occurrence
- [ ] 提前“立即运行”不会消费未来单次计划；计划 occurrence 触发后无论成功、失败、超时、取消或中断都自动禁用
- [ ] 已过期单次计划必须先编辑为未来时刻才能重新启用；“再次运行”只进行手动运行
- [ ] 调度器在 Breath 窗口关闭但应用进程仍运行时继续工作；完全退出后没有守护进程、登录项或云端继续运行
- [ ] 应用启动、恢复活动和系统唤醒时对账过期 occurrence，不补跑；单次创建一条已错过记录并禁用
- [ ] 每日或每周错过一个或多个 occurrence 时只创建一条包含次数、最早和最晚时间的已错过记录，并计算下一个未来时刻
- [ ] 禁用期间不创建错过记录；已错过记录进入最近五次历史但不增加未读角标
- [ ] 因夏令时不存在的本地计划时间视为错过，重复的本地分钟最多触发一次；系统时钟回拨不会重复同一 occurrence
- [ ] 所有计划触发都进入统一并发队列，并在启动前重新验证启用状态、Workspace 和 Agent
- [ ] 公开用例测试使用虚拟时钟覆盖创建、重新启用、时区变化、时钟前后跳、睡眠、离线聚合、单次消费和窗口关闭
- [ ] App Shell 验证覆盖三类表单、下一次时间、时区、已错过历史、单次禁用和可访问性语义
