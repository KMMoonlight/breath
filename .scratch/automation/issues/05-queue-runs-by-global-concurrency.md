# 按全局并发上限排队运行自动化

Status: ready-for-agent

## Parent

[Breath 自动化](../spec.md)

## What to build

让不同 Automation 在全局资源上限内并行运行，并把超出容量的触发变成可见、可取消的 FIFO 队列。同一个自动化始终最多只有一个已排队或运行中实例，重复触发产生“已跳过”记录。

本切片覆盖 PRD User Stories 29–30、108–114、126，并把所有后续计划和 CLI 触发统一接入同一个运行入口。

## Acceptance criteria

- [ ] 全局并发上限作为应用级设置持久化，默认 2，用户可选择 1 至 4
- [ ] 有空闲槽位时运行立即启动；容量已满时不同自动化按触发时间 FIFO 排队，相同时间使用运行 ID 稳定排序
- [ ] 提高并发上限会立即按 FIFO 消费队列；降低上限不终止活动运行，在活动数降至新上限前不再启动队列
- [ ] 每个自动化最多有一个 in-flight 运行，in-flight 同时包含已排队与运行中
- [ ] 自动化已有 in-flight 时，手动或统一触发入口产生一条“已跳过”记录而不加入队列
- [ ] 自动化正在运行或排队时“立即运行”不可再次启动，并提供可理解状态
- [ ] 用户可以取消单个排队运行并标记“已取消”，不会启动 Agent 或创建运行沙盒
- [ ] 编辑或禁用自动化会直接取消它的全部排队运行；活动运行仍按启动时配置继续
- [ ] 删除自动化和确认退出应用会取消相关排队记录，并继续遵守既有活动运行终止语义
- [ ] 任一活动运行终结后自动释放槽位并启动下一条有效队列项；启动前重新验证自动化和依赖状态
- [ ] 公开用例测试通过记录型 Runner 验证默认并发、1–4 设置、FIFO、上限调整、重复跳过、取消和依赖失效
- [ ] App Shell 验证覆盖全局设置、排队状态、排队取消、立即运行禁用、已跳过历史和可访问性语义
