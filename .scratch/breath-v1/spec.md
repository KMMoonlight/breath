# Breath v1：macOS 多 Agent 工作台

Status: ready-for-agent

## Problem Statement

使用多个 Agent CLI 进行本地软件开发时，用户需要在多个项目目录、多个 Agent 对话和多个终端之间频繁切换。普通终端或终端复用器能够承载进程，却不了解 Agent 回合、是否需要用户处理、原生对话标题以及可恢复会话标识；面向单一 Agent 的桌面应用又无法同时容纳不同 Agent CLI 和普通 Shell 工作流。

用户因此难以在一个原生 macOS 界面中组织多个项目和工作会话，无法快速判断哪个 Agent 正在运行、哪个需要处理、哪个已经完成当前回合，也无法在正常退出应用后可靠地按需续接 Agent 对话。现有工具还可能要求用户接受 Web 技术栈、云端账户、遥测、项目级配置污染，或把终端样式与应用样式混在同一套配置中。

Breath 需要解决的是“多个 Agent 如何共同工作”的组织与观察问题，而不是再造一个只强调多窗格的通用终端。

## Solution

Breath 将提供一个 macOS 原生多 Agent 工作台。左侧会话树按照“工作区 → 工作会话 → 终端窗格”组织本地项目和并行工作，右侧使用基于 libghostty 的原生终端承载任意 Shell 命令。用户自行在空终端中启动 Agent CLI；通用终端核心不依赖任何 Agent，而可选 Agent 适配器通过官方 hooks 或 plugin 提供四态展示、原生标题、原生会话标识和对话恢复。

一个工作会话可以递归横向或纵向分屏，每个终端窗格完全独立。关闭主窗口不会停止工作；正常完全退出时，Breath 在用户确认后保存结构与 Agent 恢复信息并停止进程。再次启动只处理退出前选中的工作会话，其他会话在用户切换到时才按需实例化。归档由用户明确触发，并只在设置窗口的归档管理页查看和恢复。

Breath 完全本地优先，不需要账户、后端、云同步或遥测；不保存终端滚动历史和 Agent 对话内容。应用使用 SwiftUI 原生外壳、GRDB/SQLite 本地持久化、Developer ID 签名与 Apple 公证，并通过 GitHub Releases、GitHub Pages 和 Sparkle 2 提供站外发行与应用内更新。

## User Stories

1. 作为同时使用多个 Agent CLI 的开发者，我希望在一个 macOS 原生应用中管理它们，从而不必在大量独立终端窗口之间寻找当前工作。
2. 作为重视系统体验的 Mac 用户，我希望 Breath 使用原生界面和终端渲染，从而获得符合 macOS 的窗口、输入法、键盘和性能体验。
3. 作为开发者，我希望把一个本地项目目录添加为工作区，从而以项目边界组织相关工作会话。
4. 作为开发者，我希望同一个规范化目录不能被重复添加，从而避免同一项目出现两份互相冲突的工作区记录。
5. 作为开发者，我希望一个工作区可以拥有多个工作会话，从而在同一项目中并行处理不同目标。
6. 作为开发者，我希望新建工作会话时得到一个空终端，从而自行决定运行 Agent、构建命令或普通 Shell 命令。
7. 作为开发者，我希望 Breath 不自动替我启动任何 Agent，从而保持对命令、参数和工作方式的控制。
8. 作为开发者，我希望新终端默认位于工作区根目录，从而可以立即运行项目命令。
9. 作为依赖本地工具链的开发者，我希望终端使用我的默认 Shell 并作为交互式 login shell 启动，从而继承已有 PATH、Shell 初始化和开发工具配置。
10. 作为开发者，我希望左侧以工作区和工作会话展示当前工作，从而快速切换项目和目标。
11. 作为只有一个终端窗格的用户，我希望会话树只展示到工作会话层级，从而避免没有信息价值的额外缩进。
12. 作为使用分屏的用户，我希望会话树在分屏后展示终端窗格层级，从而单独识别每个 Agent 或 Shell。
13. 作为使用多个分屏 Agent 的用户，我希望父工作会话不汇总子窗格状态，从而不会被一个模糊的聚合状态误导。
14. 作为开发者，我希望单窗格工作会话节点直接显示其终端状态，从而无需展开额外节点即可了解当前进展。
15. 作为开发者，我希望当前 Agent 类型与运行状态分开显示，从而区分“它是谁”和“它在做什么”。
16. 作为开发者，我希望将当前终端横向分屏，从而并排运行独立工作。
17. 作为开发者，我希望将当前终端纵向分屏，从而上下组织独立工作。
18. 作为复杂任务的开发者，我希望任意窗格可以继续递归分屏，从而构造适合当前工作的布局。
19. 作为调整布局的用户，我希望新分屏默认等分，从而获得可预测的初始布局。
20. 作为调整布局的用户，我希望拖动各层分隔线，从而为不同终端分配合适空间。
21. 作为返回既有工作的用户，我希望递归分屏方向与比例被保存，从而无需重新整理布局。
22. 作为创建新分屏的用户，我希望新窗格始终从工作区根目录启动空 Shell，从而不会意外继承另一个窗格的内部状态。
23. 作为并行工作的用户，我希望不同终端窗格不共享 cwd、进程或 Agent 对话，从而让每个窗格保持独立。
24. 作为多窗格用户，我希望可以关闭其中一个窗格，从而结束不再需要的局部工作。
25. 作为仍有前台进程的用户，我希望关闭窗格前得到确认，从而避免误停正在执行的命令或 Agent。
26. 作为工作会话用户，我希望最后一个窗格不能被单独关闭，从而不会留下一个没有终端的无效工作会话。
27. 作为普通终端用户，我希望可以运行任意 Shell 命令，从而让 Breath 在没有 Agent 的场景中仍然可用。
28. 作为使用未适配 Agent CLI 的开发者，我希望它仍能作为普通终端程序运行，从而不会被支持矩阵限制基本使用。
29. 作为 Agent 用户，我希望自己输入 Agent CLI 命令，从而可以使用别名、参数和个人启动习惯。
30. 作为 Agent 用户，我希望 Breath 通过官方生命周期机制识别 Agent，而不是解析终端文本，从而避免因输出格式变化产生错误状态。

44. 作为管理多个 Agent 的用户，我希望 Agent 完成当前回合时状态变为回合完成，从而知道它仍可继续对话而不是已经退出。

46. 作为开发者，我希望工作会话名称复用 Agent 官方生成的原生标题，从而获得与 Agent 自身一致的对话摘要。
47. 作为开发者，我希望 Breath 不读取原始对话或调用额外模型生成标题，从而保护内容并避免额外成本。
48. 作为开发者，我希望工作会话获得的第一个原生标题成为父名称，从而在包含多个 Agent 的分屏中保持稳定标识。

52. 作为希望名称稳定的用户，我希望工作会话和窗格名称不能手动修改，从而始终保持与 Agent 官方来源或固定占位规则一致。

54. 作为替换窗格 Agent 的用户，我希望旧 Agent 对话仍保留在原 CLI 数据中，从而不会因 Breath 改变绑定而丢失对话。
55. 作为需要同时保留多个自动恢复目标的用户，我希望可以通过新分屏或新工作会话承载它们，从而保持一窗格一绑定的清晰关系。
56. 作为谨慎的用户，我希望每个 Agent 集成都由我单独明确启用，从而不会在不知情时修改个人配置。

58. 作为配置敏感的用户，我希望 Breath 修改 Agent 配置前创建备份并展示目标文件，从而可以审查和恢复变化。
59. 作为不再使用集成的用户，我希望完整卸载 Breath 管理的 hooks 或 plugin，从而恢复启用前的 Agent 环境。

64. 作为隐私敏感用户，我希望提示词、回复、工具输入输出和 transcript 永不进入 Breath 事件通道或数据库，从而保护工作内容。
65. 作为多会话用户，我希望切换到另一个已启动工作会话时原会话继续运行，从而让多个 Agent 真正并行工作。
66. 作为关闭主窗口的用户，我希望 Breath 和所有已实例化终端继续在后台运行，从而关闭界面不会终止工作。
67. 作为重新打开主窗口的用户，我希望继续看到原有运行终端，从而无缝返回当前工作。
68. 作为完全退出应用的用户，我希望按下 `⌘Q` 时总是看到二次确认，从而明确知道所有终端进程即将停止。

70. 作为确认退出的用户，我希望 Breath 先保存布局、Agent 会话标识、绑定与运行恢复标记，再停止全部终端进程，从而为下次续接提供可靠信息。

110. 作为准备更新的用户，我希望“安装并重启”复用正常退出的确认、保存和停止流程，从而不会绕过终端安全边界。
111. 作为取消更新的用户，我希望所有进程保持不变，从而继续当前工作。
112. 作为完成更新重启的用户，我希望仍只立即处理更新前选中的工作会话，从而保持与普通冷启动一致。
113. 作为安全敏感用户，我希望更新同时通过 Apple Code Signing 与 EdDSA 验证，从而防止安装被篡改的版本。
114. 作为无需账户的用户，我希望 Breath 直接从 GitHub 读取公开更新信息和下载包，从而不需要 GitHub Token 或 Breath 后端。

## Implementation Decisions

- 产品定位为 Agent 工作台，而不是通用终端复用器；终端是通用交互核心，Agent 能力通过可选增强叠加。
- v1 只提供一个主窗口，使用左侧会话树和右侧终端布局。
- 平台最低版本为 macOS 14 Sonoma，发布 arm64 与 x86_64 Universal Binary。
- 应用外壳、会话树、设置和窗口生命周期使用 SwiftUI；高频终端区域使用 AppKit 或 Metal，并通过原生视图桥接嵌入 SwiftUI。
- 禁止使用 Electron、WebView 终端或其他 Web UI 技术替代原生终端区域。
- 终端引擎使用固定验证 revision 的 libghostty，并由内部 TerminalEngine 窄接口隔离其尚未稳定的嵌入 API；cmux 只作为技术参考，不作为产品依赖。
- 新工作会话和新分屏均启动用户默认 Shell 的交互式 login shell，初始 cwd 为工作区根目录。
- Breath 只为终端环境注入关联所需的工作区、工作会话、终端窗格和应用实例标识，不重写用户的 Shell 环境。
- 工作区以规范化路径唯一；目录不可用时不自动移除或重新定位。
- 会话树采用“工作区 → 工作会话 → 终端窗格”领域模型，单窗格时折叠第三级，多窗格时展开第三级。
- 分屏布局使用带稳定窗格 ID 的版本化递归二叉树，保存方向和比例；窗格之间不共享运行状态。
- 最后一个窗格不能单独关闭，结束整个工作会话通过归档完成。
- 终端状态严格限制为“空闲、运行中、需要处理、回合完成”，Agent 身份单独建模。
- 多窗格工作会话不计算父级聚合状态，以各终端窗格状态为唯一展示来源。
- 工作会话父标题取该会话获得的第一个 Agent 官方原生标题；终端窗格标题取当前绑定 Agent 的官方原生标题。
- 标题不能手动修改；官方标题不可用时使用确定性的会话和窗格占位名称。
- 通用终端核心不检测 Agent 命令或解析终端输出；Agent 状态完全来自官方 hooks、plugin 或等价本地扩展接口。
- 首版支持矩阵包含 Codex、Claude Code、Gemini CLI、GitHub Copilot CLI、Qwen Code、Cursor Agent、Factory Droid、OpenCode 和 Pi。
- 每个 Agent 适配器声明最低兼容版本及状态、标题、会话标识和恢复能力；官方未提供的能力必须采用既定降级路径。
- Agent 集成按 Agent 显式启用，安装到用户级配置；安装器执行结构化合并、修改前备份、目标文件展示和可逆卸载，不写项目配置。
- Agent hooks 通过当前用户可访问的 Unix Domain Socket 向应用发送最小事件；关联变量或应用通道不可用时静默结束。
- Agent 事件契约只允许 Agent 类型与版本、生命周期事件与时间、官方会话标识、官方标题、cwd 和 Breath 关联 ID。
- 禁止事件契约接收提示词、Agent 回复、工具输入输出、transcript 内容或 transcript 路径。
- 一个终端窗格最多绑定一个可恢复 Agent 对话；同窗格启动新的受支持 Agent 时，以新绑定替换旧绑定。
- 主窗口关闭只改变窗口可见性；应用进程、终端引擎状态和已启动子进程继续存活。
- 正常完全退出由应用拥有的终端进程生命周期负责，不引入跨应用退出存活的独立会话宿主。
- `⌘Q` 总是确认；确认后必须在停止进程前以事务方式持久化布局、Agent 绑定、会话标识、运行恢复标记和最后选择。
- 冷启动只实例化正常退出前选中的工作会话；其余活跃工作会话仅加载元数据，并在首次选择时实例化。
- 已实例化工作会话在切换离开后继续运行；按需实例化只控制首次启动时机。
- 最后选择无效时保持无会话选择，不自动选择或启动其他工作。
- Agent 恢复调用对应 CLI 的原生恢复能力，不尝试恢复已终止的 PTY 或 Shell 进程。
- 只有干净退出快照中仍在运行且具有可用恢复信息的 Agent 绑定自动恢复；其他窗格创建空 Shell。
- 崩溃和强制退出属于不保证恢复完整性的故障边界。
- 归档是显式用户操作；归档停止工作会话全部进程并保留结构与可恢复元数据。
- 已归档工作会话只出现在设置窗口的归档管理页，不出现在主会话树。
- 恢复归档只清除归档状态并重新加入活跃列表，不改变设置窗口、当前选择或进程状态；首次选择时才实例化。
- 永久删除归档和移除工作区只删除 Breath 元数据，绝不删除项目文件或 Agent CLI 自身数据。
- Breath 使用 GRDB 管理 SQLite，持久化工作区、工作会话、分屏树、归档状态、Agent 恢复元数据、退出快照、最后选择及两类样式配置。
- SwiftUI 与领域用例只依赖 Repository 接口和领域模型，不直接依赖 GRDB 记录。
- 数据库不保存终端输出、滚动历史、原始对话或凭据。v1 不引入 SQLCipher，使用当前用户应用数据目录权限并依赖 macOS/FileVault；未来保存敏感内容时重新评估 Keychain 或字段加密。
- 应用配置只负责终端之外的应用界面样式；终端配置只负责终端内部样式。Shell、快捷键、分屏和 Agent 行为不属于这两类配置。
- Breath 拥有自己的两类样式配置，不读取、导入或同步 Ghostty 配置。
- v1 不需要 Breath 账户、服务端、云同步或遥测。
- 应用不进入 Mac App Store，不启用 App Sandbox；使用 Developer ID 签名和 Apple 公证站外分发。
- GitHub Actions 负责测试、Universal Binary 构建、签名、公证和发布。
- 公开 GitHub Releases 托管安装包和 Sparkle 更新包，同仓库 GitHub Pages 托管签名 appcast。
- Sparkle 2 负责应用内自动检查、用户确认、Apple Code Signing 与 EdDSA 验证、安装和重启；不允许静默强制更新。
- 更新重启复用正常退出协调器，重启后的实例化策略与普通冷启动完全一致。

## Testing Decisions

- 好测试只断言用户可观察行为和稳定外部契约，不断言 SwiftUI 内部视图层级、GRDB SQL 细节、libghostty 内部类型或私有实现方法。
- 主要测试边界只有一个：工作台应用用例边界。测试通过工作区、工作会话、分屏、选择、归档、退出、启动和 Agent 事件等领域操作驱动系统，并观察会话树快照、终端启动/停止效果、持久化快照和用户确认请求。
- 主要测试边界使用可替换的 TerminalEngine、AgentEventSource、Repository 和 Updater 端口，从最高层覆盖大部分产品规则，而不是为每个模块建立重复的低层测试体系。
- 工作区测试覆盖规范化路径去重、目录不可用、确认移除、元数据删除和项目文件不受影响。
- 会话树测试覆盖单窗格两级、多窗格三级、父状态不聚合、占位标题、首个原生标题固定父名称和窗格独立标题。
- 分屏测试覆盖横向、纵向、递归、默认等分、比例调整、稳定窗格 ID、持久化往返和新窗格工作目录。
- 终端生命周期测试覆盖多窗格关闭、最后窗格禁止关闭、前台工作确认、会话切换后继续运行和主窗口关闭后继续运行。
- Agent 状态测试用统一事件场景验证四态映射，并确保普通 Shell、已退出 Agent 和恢复失败均表现为空闲。
- 每个 Agent 适配器使用官方事件样例执行相同的契约测试套件，验证最低版本、关联 ID、状态映射、官方标题、会话标识、恢复命令和缺失能力降级。
- Agent 集成测试在隔离的临时用户配置中验证启用、结构化合并、备份、重复启用幂等、卸载只删除 Breath 片段、应用不可用静默失效和项目目录零修改。
- 事件通道契约测试拒绝未允许字段，并证明提示词、回复、工具内容和 transcript 不会进入领域状态或数据库。
- 窗格绑定测试覆盖首次 Agent 绑定、同窗格新 Agent 替换、旧 CLI 数据不删除以及恢复只使用最新绑定。
- 干净退出测试使用受控子进程验证保存先于停止、取消退出零副作用、全部进程终止和滚动历史不持久化。
- 冷启动测试覆盖只实例化最后选择、其他会话懒加载、首次选择时恢复、切走后持续运行和最后选择无效时保持空白。
- 归档测试覆盖显式归档、活动进程确认、停止全部窗格、从主树消失、仅在设置中出现、恢复不启动、后来选择时恢复以及永久删除边界。
- 持久化测试覆盖数据库迁移、事务回滚、递归布局往返、干净退出快照原子性和敏感字段不存在。
- 原生 TerminalEngine 另设必要的集成边界，验证 PTY 输入输出、中文输入法、复制粘贴、调整尺寸、焦点、滚动和 arm64/x86_64 链接；这些无法由工作台用例替身证明。
- 少量 XCUITest 冒烟测试验证主窗口、工作区添加、会话树切换、分屏操作、确认对话框、设置中的两类配置与归档管理；不把所有领域组合重复到 UI 层。
- 更新测试使用签名测试 feed 验证发现、取消、安装确认、活动进程协调和重启后的最后选择策略。
- 发布验证检查 Universal Binary 架构、Developer ID 签名、公证票据、Sparkle/EdDSA 签名、公开 appcast 和 Release Asset 下载。
- 当前仓库只有设计文档，没有既有测试或代码先例；实现应首先建立上述工作台用例测试工具，然后让后续模块复用同一测试语言。

## Out of Scope

- 自动化工作流、定时任务或 Agent 编排。
- Breath 内置的普通聊天界面。
- Computer Use 或桌面操作代理。
- Git worktree 创建、切换或管理。
- 远程项目、SSH 会话、容器工作区或云端开发环境。
- Breath 账户、团队协作、后端服务、云同步和遥测。
- Mac App Store 发布和 App Sandbox 兼容。
- 终端进程在 `⌘Q`、更新退出、崩溃或强制终止后继续存活。
- 终端滚动历史跨退出或归档持久化。
- 读取、导入或同步 Ghostty 配置。
- 手动修改工作会话或终端窗格名称。
- 系统通知、菜单栏通知中心或声音提醒。
- 解析终端输出以推断 Agent 状态、标题或会话标识。
- 保存提示词、Agent 回复、工具内容或 transcript。
- 自动支持未来所有 Agent CLI；新增 Agent 必须进入明确兼容矩阵。
- 在 v1 数据库中保存凭据、令牌或需要应用级加密的原始内容。
- 为应用配置或终端配置加入 Shell、快捷键、分屏及 Agent 行为选项。
