# Breath 安静空状态：禁止大块提示占据工作台

Status: ready-for-agent

## Problem Statement

Breath 当前在主窗口没有工作区、没有选中工作会话时，使用居中的图标、粗体标题和说明文字填满侧栏或终端区域。这样的空状态提示视觉体量过大，把“尚无内容”表现成页面主内容，形成与 Agent 工作台不相称的强提示感。

用户已经可以通过侧栏顶部的添加工作区入口理解并完成下一步；右侧没有选中工作会话时也没有必须立即执行的操作。继续展示大块居中提示会制造重复信息、抢占视觉注意力，并让尚未使用的终端区域显得像错误页或引导页。

这个问题不只取决于某一个系统组件。任何以大面积居中图标、标题、说明或卡片占据空白区域的等价实现，都会产生相同问题。Breath 需要一条稳定的空状态视觉规则，而不是简单替换一段文案。

## Solution

Breath 的被动空状态保持安静：当某个区域只是暂时没有内容，并且用户已能从固定工具栏、侧栏标题或既有操作入口完成下一步时，该区域不展示大块居中提示。

主窗口没有工作区时，侧栏保留“工作区”标题和添加工作区按钮，列表区域保持留白，不再显示居中的文件夹图标、“还没有工作区”标题和说明文字。没有选中工作会话时，右侧终端区域保持与正常终端画布一致的空白背景，不再显示终端图标、“选择一个工作会话”标题和说明文字。

这条规则同时约束其他被动空列表和空内容区域：如确实需要说明，只能使用低强调、紧凑、就地的单行信息，不能形成占据可用区域中心的大型空状态。确认框、错误提示、启动恢复进度和需要用户立即处理的阻塞状态不属于被动空状态，仍可使用清晰、足够醒目的反馈。

## User Stories

1. 作为首次启动 Breath 的开发者，我希望主窗口保持简洁，从而不会被两块巨大的引导文案同时吸引注意力。
2. 作为尚未添加工作区的用户，我希望仍能看到固定的添加工作区按钮，从而可以直接开始使用而不依赖大块说明。
3. 作为尚未添加工作区的用户，我希望侧栏列表区域保持安静留白，从而理解这里尚无内容而不是发生错误。
4. 作为已经熟悉 Breath 的用户，我希望空状态不重复解释显而易见的操作，从而减少每次启动时的视觉噪声。
5. 作为没有选中工作会话的用户，我希望右侧区域保持空白，从而不会把未选择状态误认为必须处理的警告或任务。
6. 作为在会话树中切换工作的用户，我希望未选择状态与真实终端画布保持一致的背景，从而让界面切换更稳定。
7. 作为拥有工作区但暂时没有活跃工作会话的用户，我希望右侧仍不出现大块提示，从而保持与其他未选择状态一致。
8. 作为恢复启动后没有有效选择的用户，我希望 Breath 遵守按需实例化规则且保持安静，从而不会暗示应用会自动选择或恢复其他工作会话。
9. 作为工作区目录不可用的用户，我希望既有移除提示逻辑继续工作，从而不会因为空状态简化而失去必要反馈。
10. 作为使用 VoiceOver 的用户，我希望添加工作区按钮仍有明确的可访问名称，从而无需依赖被移除的视觉说明完成操作。
11. 作为使用 VoiceOver 的用户，我希望空白终端区域仍能以不可见的语义说明当前没有选中工作会话，从而获得状态信息但不增加视觉噪声。
12. 作为管理归档工作会话的用户，我希望空列表只使用紧凑信息或留白，从而不会在设置窗口再次遇到同类大块空状态。
13. 作为等待启动恢复的用户，我希望恢复进度仍清晰可见，从而不会把真正的进行中状态误认为普通空白。
14. 作为遇到错误的用户，我希望错误信息仍正常展示，从而不会因“安静空状态”规则而隐藏需要处理的问题。
15. 作为执行破坏性操作的用户，我希望归档、移除工作区、关闭窗格和退出确认仍保持醒目，从而不会降低安全性。
16. 作为维护 Breath 的开发者，我希望空状态规则针对视觉行为而不是某个 SwiftUI 类型，从而避免未来换组件后重新引入相同问题。
17. 作为维护 Breath 的开发者，我希望通过应用外壳的渲染行为验证空状态，从而避免只测试内部布尔值却遗漏真实界面回归。
18. 作为偏好原生简洁界面的 Mac 用户，我希望 Breath 的视觉重点始终落在会话树和终端内容上，从而符合多 Agent 工作台的核心用途。

## Implementation Decisions

- 修改范围位于 App Shell 的空状态呈现，不改变工作区、工作会话、终端窗格或按需实例化领域规则。
- 主窗口侧栏没有工作区时保留固定标题和添加工作区操作；列表内容区域不渲染图标、标题、说明、卡片或其他居中占位内容。
- 主窗口没有选中工作会话时，终端区域只渲染正常的空白画布背景；不渲染视觉占位图标、标题、说明或行动按钮。
- “没有选中工作会话”不触发自动选择，不创建 Shell，不恢复 Agent 对话，也不改变持久化的最后选择。
- 如果工作区存在但没有活跃工作会话，使用与“没有选中工作会话”相同的右侧安静空状态；创建工作会话仍从会话树既有入口完成。
- 被动空状态不得使用占满父区域的系统空状态视图或等价自定义实现，不得以垂直和水平居中的图标、标题、说明组合构成视觉焦点。
- 被动空列表如果业务上必须说明，可使用普通列表行或邻近现有操作的单行次要文字；不得使用标题字号、独立大图标、卡片背景或大面积弹性占位。
- 设置窗口中的空归档列表遵循同一规则，改为紧凑信息或留白，避免只修复主窗口后在其他区域保留同类模式。
- 视觉留白不等于删除可访问语义。固定操作保留明确的辅助功能标签；纯空白内容区可提供不参与视觉布局的辅助功能说明。
- 启动恢复进度、错误、权限或输入请求、危险操作确认不属于被动空状态，不受本规格的低强调限制。
- 不新增应用配置项。该规则是 Breath 的固定界面规范，不提供恢复“大块提示”的开关。
- 不修改应用配置或终端配置的数据结构，不新增数据库字段或迁移。
- 不修改终端引擎、Agent 适配器、Agent 集成、会话树层级或终端状态模型。

## Testing Decisions

- 最高测试缝是 App Shell 的实际 SwiftUI 渲染行为。新增一个聚焦的应用界面测试入口，用可控工作台快照渲染主窗口，而不是测试某个私有视图或空状态布尔值。
- 测试“没有工作区”快照：侧栏添加工作区操作仍存在且可访问；渲染和辅助功能层级中不存在视觉标题“还没有工作区”及其说明，也不存在占满列表区域的空状态容器。
- 测试“有工作区但没有选中工作会话”快照：会话树内容正常存在；右侧不出现“选择一个工作会话”、终端占位图标或说明文字；测试不得因此触发终端启动。
- 测试“没有活跃工作会话”快照：右侧使用同一安静空状态，不自动创建或选择工作会话。
- 测试设置窗口的空归档列表：不出现大面积居中图标、标题和说明组合；如保留文字，它必须作为紧凑列表内容呈现。
- 测试必要反馈不受影响：启动恢复进度、错误提示和破坏性确认仍可从现有高层交互测试或人工验收中观察到。
- 测试关注外部可见行为和可访问语义，不断言具体 SwiftUI 组件类型、视图私有层级、像素坐标或硬编码尺寸。
- 现有工作台用例测试继续负责验证没有选择时不实例化终端、工作区和工作会话领域状态不变；新测试只补足 App Shell 视觉呈现这一当前缺失的测试缝。
- 人工验收覆盖最小窗口、默认窗口和放大窗口三种尺寸，确认空状态不会因可用空间增大而重新变成居中大块提示。

## Out of Scope

- 重新设计会话树的信息架构、工作区标题栏或添加工作区流程。
- 新增首次启动向导、教学浮层、演示项目或 onboarding 页面。
- 自动添加工作区、自动创建工作会话或自动选择其他工作会话。
- 改变按需实例化、冷启动恢复、归档恢复或工作区不可用规则。
- 改变终端区域的字体、颜色、光标、分屏或 libghostty 行为。
- 改变错误、恢复进度、权限请求或破坏性确认的视觉层级。
- 建立完整的全应用截图基线或像素级视觉回归系统。

## Further Notes

- 参考问题是主窗口中同时出现的两块大面积提示：侧栏的“还没有工作区”和右侧的“选择一个工作会话”。两者都应从正常视觉布局中移除。
- 本规格中的“禁止大块提示”是行为约束，不是禁止所有文字。必要信息可以保留为紧凑、低强调、就地或仅辅助功能可见的语义。
- 本规格不与“只恢复当前选中的工作会话”决策冲突；相反，右侧留白应准确表达当前没有被实例化的工作会话，而不暗示自动恢复其他会话。
- 测试缝已经在规格生成前明确为主窗口 App Shell 的空状态渲染行为，符合用户要求从最终界面而非实现细节验证该约束。
