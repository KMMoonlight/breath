# Breath 托管工作树会话

Status: ready-for-agent

## Problem Statement

Breath 当前所有工作会话和终端窗格都直接使用工作区的本地检出。同一工作区中同时运行多个 Agent 时，它们会读写同一批文件、共享同一个 Git working tree，容易互相覆盖未提交修改、打断用户正在进行的工作，或让多个独立目标的代码状态混在一起。

用户希望保留现有的默认本地工作流，同时能够明确创建一个与其他工作隔离的工作树会话。该会话应拥有独立文件状态，但仍共享原仓库的提交历史；其中的所有终端窗格、Agent 对话、Git 状态与 Diff 都应围绕同一个托管工作树运行。

工作树可能包含尚未提交或尚未被分支保护的代码，因此创建、归档、永久删除、移除工作区、崩溃恢复和外部 Git 操作都具有数据安全风险。Breath 需要提供明确、可恢复且不会越界删除用户目录的完整生命周期，而不只是执行一次 `git worktree add`。

## Solution

Breath 为工作会话增加两种会话工作目录：本地会话继续使用工作区的本地检出；工作树会话使用 Breath 为该会话专门创建和管理的 Git worktree。同一工作会话中的全部终端窗格共享同一个会话工作目录，不允许不同窗格各自绑定不同工作树。

普通“新建工作会话”、侧栏 `+` 和 `⌘T` 继续默认创建本地会话。只有用户在工作区选项菜单中明确选择“新建工作树会话”时，Breath 才从操作开始时捕获的当前 `HEAD` 创建 detached worktree。创建不会复制本地未提交或 ignored 文件，不会运行 checkout hooks、Git LFS、自定义 checkout filters 或 submodule 初始化，也不会修改用户 Git 配置。

托管工作树存放在 Breath 的应用支持目录，由工作区 ID 和工作会话 ID 唯一定位。Breath 负责其创建、可用性验证、归档保留、一次性导出为分支、代码风险检查、永久删除、工作区移除、启动对账和失败清理。创建和删除必须遵守路径验证、Git 锁、worktree lock、符号链接和重新检查规则，确保既不静默丢失代码，也不因损坏的持久化路径删除 Breath 托管根目录之外的内容。

## User Stories

1. 作为日常使用 Breath 的开发者，我希望普通“新建工作会话”继续创建本地会话，从而不改变我已有的默认工作流。
2. 作为使用侧栏快捷操作的开发者，我希望工作区旁的 `+` 继续创建本地会话，从而不会因一次点击意外创建额外 Git worktree。
3. 作为键盘用户，我希望 `⌘T` 继续创建本地会话，从而保持现有快捷键语义。
4. 作为需要代码隔离的开发者，我希望从工作区选项菜单明确选择“新建工作树会话”，从而知道自己正在创建独立检出。
5. 作为谨慎的用户，我希望工作树会话首版没有独立快捷键，从而避免误触需要 Git 检查和确认的创建流程。
6. 作为同时运行多个 Agent 的开发者，我希望每个工作树会话拥有独立文件状态，从而避免 Agent 互相覆盖修改。
7. 作为组织任务的开发者，我希望工作树属于工作会话而不是 Agent，从而可以在同一个任务中自由更换或组合 Agent CLI。
8. 作为使用分屏的开发者，我希望同一工作树会话的所有终端窗格共享同一个会话工作目录，从而围绕同一份代码协作。
9. 作为使用分屏的开发者，我希望不同终端窗格仍拥有独立进程、环境增量和 Agent 对话，从而不会因共享代码目录而共享运行时状态。
10. 作为使用多个工作会话的开发者，我希望每个工作树会话只拥有一个专属托管工作树，从而保持任务、终端布局、Agent 对话和代码状态边界一致。
11. 作为查看会话树的用户，我希望工作树会话通过分支形状图标与本地会话区分，从而无需增加新的侧栏层级。
12. 作为查看会话树的用户，我希望新建工作树会话仍使用“新会话 · HH:mm”占位标题，从而保持现有命名规则。
13. 作为使用 Agent 原生标题的用户，我希望工作树会话获得第一个 Agent 原生标题后照常替换占位标题，从而保持本地会话和工作树会话一致。
14. 作为首次创建工作树会话的用户，我希望创建期间在工作区下看到“正在创建工作树…”临时行和进度，从而知道操作正在进行。
15. 作为创建工作树会话的用户，我希望临时行不可选择，从而不会进入尚未完成的会话。
16. 作为创建工作树会话的用户，我希望创建成功后临时行原地成为实际会话并自动选中，从而自然进入新的隔离环境。
17. 作为创建失败的用户，我希望临时行被移除并看到清晰错误，从而不会留下看似可用的半成品会话。
18. 作为创建工作树会话的用户，我希望创建过程中不提供强制取消，从而避免 Git 元数据和目录处于不确定的中间状态。
19. 作为在 Git 仓库根目录工作的用户，我希望可以直接创建工作树会话，从而并行处理不同目标。
20. 作为把仓库子目录添加为工作区的用户，我希望 Breath 为整个仓库创建 worktree，但从其中对应子目录启动终端，从而保持工作区边界。
21. 作为把 linked worktree 中的目录添加为工作区的用户，我希望 Breath 仍能找到共享仓库并创建新的托管工作树，从而不限制我的现有 Git 布局。
22. 作为使用多个 Git 仓库子项目的用户，我希望只有工作区目录自身属于某个 Git 仓库时才能创建工作树会话，从而避免 Breath 猜测内部仓库。
23. 作为工作区只包含多个内部仓库的用户，我希望 Breath 不扫描并弹出仓库选择器，从而保持创建语义明确。
24. 作为非 Git 工作区用户，我希望“新建工作树会话”禁用并说明原因，从而仍可继续创建本地会话。
25. 作为尚未产生第一次提交的仓库用户，我希望工作树入口禁用并提示先创建提交，从而避免不明确的 unborn branch 语义。
26. 作为 bare repository 用户，我希望工作树入口禁用，从而不会把没有正常工作目录的仓库当作项目工作区。
27. 作为 sparse checkout 用户，我希望首版工作树入口禁用并说明暂不支持，从而避免意外检出整个大型仓库。
28. 作为使用旧版系统 Git 的用户，我希望 Breath 明确提示 Git 版本不足，而不是执行到一半失败。
29. 作为 macOS 用户，我希望 Breath 固定使用系统 `/usr/bin/git`，从而不受 Shell `PATH`、版本管理器或启动脚本影响。
30. 作为需要可预测行为的用户，我希望 Breath 只依赖 Git 2.20 已有的成熟 worktree 能力，从而获得稳定兼容边界。
31. 作为创建工作树会话的用户，我希望 Breath 在创建开始时捕获当前 `HEAD` commit，从而拥有明确且可追溯的创建基线。
32. 作为仓库同时被其他工具操作的用户，我希望 Breath 使用已经捕获的 commit 创建工作树，而不是稍后悄悄使用新的 `HEAD`。
33. 作为创建基线已不可访问的用户，我希望创建失败并提示重试，从而不会得到与确认时不同的代码。
34. 作为并行工作的用户，我希望新工作树初始处于 detached HEAD，从而不占用本地检出的当前分支。
35. 作为需要多个并行会话的用户，我希望可以从同一个 commit 创建多个 detached worktree，从而不污染分支列表。
36. 作为本地检出存在 staged 修改的用户，我希望创建前看到 staged 文件数量，从而知道这些修改不会进入工作树。
37. 作为本地检出存在 unstaged 修改的用户，我希望创建前看到 unstaged 文件数量，从而知道这些修改不会进入工作树。
38. 作为本地检出存在 untracked 文件的用户，我希望创建前看到 untracked 文件数量，从而知道这些文件不会进入工作树。
39. 作为文件同时包含 staged 与 unstaged 修改的用户，我希望看到两个分类以及按路径去重的受影响文件合计，从而正确理解风险。
40. 作为查看创建提示的用户，我希望提示不展示文件名和 diff，从而减少不必要的代码内容暴露。
41. 作为经常创建工作树的用户，我希望每次本地检出不干净时都明确确认，从而不会因“以后不再提示”而忘记复制边界。
42. 作为隐私敏感用户，我希望 Breath 不复制 `.env`、密钥、ignored 文件或本地配置，从而避免敏感数据进入新工作树。
43. 作为依赖本地配置的用户，我希望首版明确不支持 `.worktreeinclude`，从而不会误以为 ignored 文件已经被复制。
44. 作为 Git LFS 仓库用户，我希望创建工作树时不自动下载 LFS 对象，从而避免隐式网络、凭据请求和大文件下载。
45. 作为 Git LFS 仓库用户，我希望 LFS 文件保持指针状态，从而可以在终端中自行决定何时执行 `git lfs pull`。
46. 作为包含 submodule 的仓库用户，我希望 Breath 不自动初始化 submodule，从而避免隐式网络和大量磁盘写入。
47. 作为包含 checkout hooks 的仓库用户，我希望 Breath 创建 worktree 时不执行这些 hooks，从而不会隐式运行仓库代码。
48. 作为包含自定义 smudge 或 process filter 的仓库用户，我希望创建时不执行这些 filter，从而不会隐式启动外部程序。
49. 作为声明 required checkout filter 的仓库用户，我希望 Breath 安全失败而不是回退执行 filter，从而保持“创建不执行仓库代码”的边界。
50. 作为已有 Git 配置的用户，我希望 Breath 不修改仓库、全局或系统 Git config，从而不影响其他检出和工具。
51. 作为项目维护者，我希望 Breath 的托管目录不位于项目内或仓库旁，从而不会污染项目、触发项目文件监听或要求修改 `.gitignore`。
52. 作为管理本机存储的用户，我希望托管工作树按工作区和工作会话稳定存放在 Breath 应用支持目录，从而能够定位和清理。
53. 作为使用 Time Machine 的用户，我希望 Breath 托管工作树不进入系统备份，从而避免备份大量缓存和恢复无效 linked-worktree 元数据。
54. 作为有未提交工作树修改的用户，我希望理解系统备份不是唯一保护手段，从而主动提交并导出需要长期保存的成果。
55. 作为长期归档会话的用户，我希望 Breath 不因时间或数量上限自动删除仍绑定会话的工作树，从而不会静默丢失代码。
56. 作为磁盘空间敏感用户，我希望只有永久删除会话或移除工作区才清理绑定的工作树，从而能够预测数据生命周期。
57. 作为同时对一个仓库发起多个操作的用户，我希望 Breath 将该仓库的创建、删除和导出操作串行执行，从而减少共享 Git 元数据冲突。
58. 作为使用不同仓库的用户，我希望不同仓库的工作树操作可以并行，从而不会因无关项目互相等待。
59. 作为在终端中运行外部 Git 命令的用户，我希望 Breath 不试图锁住或终止这些进程，从而保持终端工作流独立。
60. 作为遭遇外部 Git 锁冲突的用户，我希望 Breath 安全失败并提示稍后重试，从而不会自动删除锁文件。
61. 作为创建工作树会话的用户，我希望会话只有在工作树、持久化和第一个终端全部成功后才出现，从而不会看到半成品。
62. 作为创建过程中发生错误的用户，我希望 Breath 停止已启动终端并回滚已创建内容，从而恢复到创建前状态。
63. 作为回滚清理失败的用户，我希望 Breath 保存“待清理工作树”记录和路径，从而不会遗忘磁盘残留。
64. 作为重启 Breath 的用户，我希望应用核对托管目录与会话记录，从而识别创建中断留下的孤儿工作树。
65. 作为重启 Breath 的用户，我希望只有 Breath 自身托管目录中的孤儿工作树会被自动清理，从而不会影响外部 worktree。
66. 作为清理再次失败的用户，我希望在设置中看到待清理工作树、最近错误和近似占用，从而可以诊断和重试。
67. 作为管理待清理项的用户，我希望可以重试清理、在 Finder 中显示和复制路径，从而处理异常情况。
68. 作为管理待清理项的用户，我希望不能简单忽略并删除记录，从而不会制造 Breath 明知存在却不再管理的孤儿目录。
69. 作为创建工作树会话的用户，我希望第一个终端从会话工作目录启动，从而立即操作隔离代码。
70. 作为分屏用户，我希望新终端也从同一个会话工作目录启动，从而不会错误回到本地检出。
71. 作为冷启动恢复用户，我希望工作树会话的终端和 Agent 对话从原托管工作树恢复，从而继续原有代码状态。
72. 作为使用 Agent hooks 的用户，我希望工作区、工作会话和终端窗格关联信息保持稳定，同时 Agent 的 cwd 反映工作树目录，从而正确关联事件。
73. 作为查看 Git 状态的用户，我希望选中工作树会话后状态栏读取该工作树，而不是原始工作区目录。
74. 作为查看 Git Diff 的用户，我希望 Diff 读取该工作树中的修改，从而看到 Agent 实际产生的代码。
75. 作为使用完整 Git 工作台的用户，我希望 Git 目标由当前工作会话的会话工作目录解析，从而在本地会话和工作树会话之间正确切换。
76. 作为关注领域边界的维护者，我希望 Git 工作台仍与 Agent 状态、Agent 生命周期和终端窗格解耦，从而保持普通 Git 行为。
77. 作为使用已安装编辑器的用户，我希望“用编辑器打开”打开工作树会话目录，从而在常用 IDE 中检查代码。
78. 作为使用 Finder 的用户，我希望可以显示工作树目录，从而检查磁盘内容和占用。
79. 作为需要粘贴路径的用户，我希望可以复制工作树路径，从而在其他工具中使用。
80. 作为查看 detached worktree 的用户，我希望状态栏显示 `detached @ <短 hash>`，从而理解当前没有签出分支。
81. 作为在终端中切换到分支的用户，我希望 Breath 显示实际分支名，从而尊重我的 Git 操作。
82. 作为在终端中创建分支的用户，我希望 Breath 不强制切回 detached HEAD，从而不与用户操作争夺 Git 状态。
83. 作为在终端中执行 rebase 或 reset 的用户，我希望 Breath 重新读取实际历史，从而不依据过期假设判断风险。
84. 作为历史已偏离创建基线的用户，我希望看到明确警告，从而知道提交统计不能按普通线性关系理解。
85. 作为选中工作树会话的用户，我希望 Git 状态约每 3 秒刷新，从而及时看到文件、分支和提交变化。
86. 作为拥有很多后台会话的用户，我希望未选中的工作树不持续执行 Git 轮询，从而避免无意义的资源消耗。
87. 作为切换到工作树会话的用户，我希望选择时立即刷新可用性和 Git 状态，从而不先看到陈旧信息。
88. 作为重新激活 Breath 的用户，我希望当前工作树立即校验，从而感知其他工具产生的变化。
89. 作为打开会话菜单或危险确认的用户，我希望 Breath 在操作前重新读取真实 Git 状态，从而不会依赖三秒前的缓存。
90. 作为工作树目录被外部删除的用户，我希望会话标记为“工作树不可用”而不是自动重建，从而不会把旧修改已丢失的事实隐藏起来。
91. 作为 Git 元数据损坏的用户，我希望 Breath 不自动执行 repair 或重新注册，从而保留故障现场并避免错误恢复。
92. 作为目录仍存在但不再登记在 worktree 列表中的用户，我希望它也被视为不可用，从而不会把普通目录误认为有效 worktree。
93. 作为查看不可用会话的用户，我希望看到橙色警告图标和路径，从而快速识别问题。
94. 作为工作树不可用的用户，我希望 Breath 不启动新终端、不恢复 Agent、不允许新分屏或导出分支，从而避免在错误目录中工作。
95. 作为工作树运行期间才发生损坏的用户，我希望 Breath 不突然终止现有终端或 Agent，从而有机会检查和保存当前进程中的信息。
96. 作为工作树运行期间才发生损坏的用户，我希望退出、归档或进程结束后不再自动恢复终端，从而不会把不可用状态延续为正常会话。
97. 作为原始工作区目录暂时不可用的用户，我希望有效的托管工作树会话仍能运行，从而不因本地检出问题中断隔离工作。
98. 作为原始工作区被移动导致 linked metadata 失效的用户，我希望 Breath 按实际 Git 有效性判定不可用，从而不作无法兑现的继续运行承诺。
99. 作为使用外部工具创建 worktree 的用户，我希望 Breath 不显示、导入或清理它们，从而保持工具所有权边界。
100. 作为希望在外部 worktree 使用 Breath 的用户，我希望可以把该目录添加为普通工作区，从而使用现有本地会话能力。
101. 作为工作树会话用户，我希望会话行提供统一的 `…` 菜单，从而不会堆放多个操作图标。
102. 作为本地会话用户，我希望统一菜单仍提供归档，从而保持现有能力。
103. 作为可用工作树会话用户，我希望菜单提供 Finder、编辑器、复制路径和导出分支，从而完成常用管理。
104. 作为不可用工作树用户，我希望菜单只提供仍安全可执行的路径查看、复制和归档，从而避免误操作。
105. 作为希望保存提交成果的用户，我希望把工作树当前 `HEAD` 一次性导出为新分支，从而在本地检出中继续处理。
106. 作为导出分支的用户，我希望默认获得 `breath/<会话短 ID>` 建议名，从而快速得到合法且可识别的名称。
107. 作为使用自定义分支命名规范的用户，我希望输入完整分支名并接受 Git 格式校验，从而遵守仓库约定。
108. 作为仓库中已有同名分支的用户，我希望 Breath 拒绝覆盖或移动它，从而保护现有引用。
109. 作为导出完成的用户，我希望工作树保持原有 detached 或实际分支状态，从而不发生隐式 checkout。
110. 作为继续在 detached worktree 提交的用户，我希望理解已导出分支不会自动前进，从而不会误以为后续提交已经受到保护。
111. 作为工作树存在未提交修改的用户，我希望仍可导出当前 `HEAD`，从而保存已经提交的成果。
112. 作为工作树存在未提交修改的用户，我希望导出前看到这些修改不会包含在分支中，从而不误判导出范围。
113. 作为已经签出目标分支的用户，我希望 Breath 提示无需导出，从而避免重复创建引用。
114. 作为删除过已导出分支的用户，我希望删除风险重新读取当前本地分支和标签，从而不把历史提示当成永久保护。
115. 作为使用远端分支的用户，我希望远端引用不成为唯一保护依据，从而避免本地提交因远端状态不确定而被误判安全。
116. 作为希望把工作带回本地检出的用户，我希望首版通过提交、导出分支、切换、合并或 cherry-pick 完成，从而使用标准 Git 工作流。
117. 作为首版用户，我希望 Breath 不提供自动 Handoff，从而避免未提交修改、冲突、终端重启和 Agent 恢复带来的额外风险。
118. 作为归档工作树会话的用户，我希望归档停止终端但保留托管工作树，从而之后能够继续原代码状态。
119. 作为归档仍有 Agent 回合或前台进程的用户，我希望沿用现有停止确认，从而避免误停工作。
120. 作为归档代码尚未提交的用户，我希望归档不要求 Git clean，也不进行删除风险扫描，从而把归档与删除清晰区分。
121. 作为恢复归档工作树会话的用户，我希望它重新出现在会话树但不立即启动进程，从而遵守现有按需恢复规则。
122. 作为后来选择已恢复会话的用户，我希望终端从原托管工作树启动，从而继续原来的文件状态。
123. 作为永久删除本地会话的用户，我希望删除仍只影响 Breath 元数据，从而不改变工作区文件。
124. 作为永久删除安全工作树会话的用户，我希望普通确认后清理托管目录，从而释放磁盘空间。
125. 作为工作树存在 staged、unstaged 或 untracked 修改的用户，我希望永久删除升级为高风险确认，从而不会轻易丢失代码。
126. 作为工作树包含新增提交的用户，我希望只有未被任何本地分支或标签保护的提交触发高风险，从而准确识别可能丢失的成果。
127. 作为提交已经由本地分支或标签保护的用户，我希望它不再计入可能丢失提交，从而避免不必要的警告。
128. 作为历史与创建基线异常的用户，我希望删除一律升级为高风险确认，从而应对无法可靠解释的提交关系。
129. 作为查看删除确认的用户，我希望看到 staged、unstaged、untracked、去重文件合计、未保护提交、路径和近似占用，从而理解删除影响。
130. 作为删除包含 ignored 构建产物的用户，我希望这些文件不触发代码丢失警告但计入磁盘占用，从而区分代码风险和空间回收。
131. 作为工作树很大的用户，我希望磁盘占用按需后台计算并标记为近似值，从而不让所有会话持续扫描磁盘。
132. 作为磁盘统计失败的用户，我希望看到“大小未知”但仍能继续删除，从而不会被非关键指标阻塞。
133. 作为删除单个高风险工作树会话的用户，我希望必须输入会话标题，从而明确确认删除对象。
134. 作为移除包含高风险工作树的工作区用户，我希望必须输入工作区名称，从而明确确认聚合影响。
135. 作为输入名称不匹配的用户，我希望删除按钮保持禁用，从而降低误删风险。
136. 作为最终确认删除的用户，我希望 Breath 先停止相关终端再重新检查 Git 状态，从而捕获 Agent 在确认期间产生的新修改。
137. 作为停止后风险增加的用户，我希望删除被取消并要求重新确认，从而不会让旧确认覆盖新代码。
138. 作为停止后风险降低的用户，我希望 Breath 可以继续删除，从而不要求无意义的重复确认。
139. 作为工作树目录已经不存在的用户，我希望普通确认后删除会话记录并清理残留 Git 元数据，从而移除失效记录。
140. 作为目录存在但 Git 元数据损坏的用户，我希望高风险确认明确提示无法验证代码，从而不会把未知状态当作安全。
141. 作为工作树被外部锁定的用户，我希望 Breath 拒绝删除并显示锁定原因，从而尊重其他工具或用户的保护。
142. 作为工作树被外部锁定的用户，我希望 Breath 不自动 unlock 或提供强制绕过，从而不替我撤销显式保护。
143. 作为删除工作树的用户，我希望 Breath 只删除验证位于自身托管根目录的路径，从而不会因数据库损坏删除其他目录。
144. 作为安全敏感用户，我希望托管根路径的任一级符号链接都导致自动删除被拒绝，从而防止路径逃逸。
145. 作为工作树内部包含符号链接的用户，我希望磁盘扫描和删除不跟随链接目标，从而不会访问或删除外部内容。
146. 作为清理工作树的用户，我希望 Breath 先请求 Git 移除 linked worktree，再删除经过验证的残留文件，从而保持共享元数据一致。
147. 作为持久化状态损坏的用户，我希望任意绝对路径不能直接成为递归删除目标，从而维持硬性安全边界。
148. 作为普通使用者，我希望状态刷新不自动执行 `git worktree prune`，从而不会在只读观察时修改共享仓库元数据。
149. 作为使用 Finder 外部删除目录的用户，我希望 Breath 只在删除会话、移除工作区或启动清理时处理残留 worktree 元数据，从而保持操作可预期。
150. 作为移除整个工作区的用户，我希望 Breath 汇总全部托管工作树的风险，从而一次理解所有受影响代码。
151. 作为移除工作区的用户，我希望原始工作区目录始终不被修改，从而安全管理 Breath 元数据与托管目录。
152. 作为移除工作区的用户，我希望 Breath 停止全部相关终端并在停止后复检风险，从而避免确认期间的新修改。
153. 作为移除工作区的用户，我希望只有所有托管工作树删除成功后才删除工作区元数据，从而不会留下无法从 Breath 管理的残留。
154. 作为工作区移除中途失败的用户，我希望剩余记录保留并可重试，从而不会丢失管理入口。
155. 作为工作区移除中已有工作树删除成功的用户，我希望对应会话标记为不可用而不是伪造恢复，从而准确反映磁盘状态。
156. 作为把同一仓库不同子目录添加成多个工作区的用户，我希望移除一个工作区只清理它自己拥有的工作树，从而不影响另一个工作区。
157. 作为正常退出 Breath 的用户，我希望应用等待正在进行的工作树写操作完成，从而不在 Git 元数据更新中途退出。
158. 作为退出等待中的用户，我希望看到“正在完成工作树操作”并且不能再启动新操作，从而理解退出延迟。
159. 作为系统强制终止应用的用户，我希望 Breath 不声称能够保证完整清理，从而对崩溃边界有正确预期。
160. 作为升级已有 Breath 数据的用户，我希望所有旧工作会话自动视为本地会话，从而保持当前目录和恢复行为。
161. 作为隐私敏感用户，我希望 Breath 只持久化路径、仓库关联、创建基线、相对目录、最近导出提示和生命周期状态，从而最小化工作树元数据。
162. 作为隐私敏感用户，我希望 Breath 不保存工作树 diff、文件名列表或提交消息，从而不把代码内容写入数据库。
163. 作为查看 Git 错误的用户，我希望默认看到经过清理的简短原因和退出码，从而快速理解失败。
164. 作为需要诊断的用户，我希望可以展开或复制完整 Git stderr 和命令参数，从而排查复杂错误。
165. 作为安全敏感用户，我希望详细错误不包含进程环境变量，从而避免泄露敏感配置。
166. 作为远端 URL 可能含凭据的用户，我希望用户名、密码和 token 在展示前遮蔽，从而降低诊断信息泄露风险。
167. 作为本地优先用户，我希望 Git 错误详情不写入数据库也不上传，从而保持 Breath 的隐私边界。
168. 作为 VoiceOver 用户，我希望工作树、本地、不可用、进行中和危险确认都有明确可访问语义，从而不依赖图标或颜色。
169. 作为键盘用户，我希望工作区和会话菜单中的工作树操作可以完整聚焦和执行，从而无需鼠标。
170. 作为维护 Breath 的开发者，我希望工作树生命周期通过稳定用例和服务边界表达，从而可以测试外部行为而不绑定具体 Git 命令拼接。

## Implementation Decisions

- 领域模型为每个工作会话增加“会话工作目录”概念，并明确区分本地会话与工作树会话。终端窗格不单独保存工作树路径；其工作目录始终由所属工作会话解析。
- 工作会话保存可向后兼容解码的目录类型。旧数据缺少新字段时默认迁移为本地会话，继续使用工作区目录。
- 托管工作树元数据包含工作树路径、稳定仓库关联、创建基线 commit、工作区相对仓库根目录的路径、最近一次导出的分支名和生命周期状态。
- 工作树生命周期至少区分创建中、可用、不可用和待清理。创建中的临时侧栏行属于当前操作呈现；待清理必须持久化，以支持重启恢复。
- 新增独立的 Git Worktree Service，用于仓库发现、能力预检、创建、验证、状态检查、风险检查、分支导出、删除、残留元数据清理和启动对账。
- Workbench 用例层拥有工作会话生命周期编排，通过稳定 Git Worktree Service 接口协调持久化和终端运行时，不让 SwiftUI 视图直接执行 Git 或删除目录。
- App Shell 负责展示创建进度、会话图标、菜单、不可用状态、导出对话框和风险确认，但所有最终判断必须来自重新读取的领域状态与 Git 状态。
- Git 工作台领域继续与 Agent 状态、Agent 生命周期和终端窗格解耦。App Shell 根据当前选中工作会话解析一个稳定 Git 目标；本地会话解析到本地检出，工作树会话解析到托管工作树。现有仅传入 Workspace 路径的目标解析必须相应调整。
- 固定使用 macOS `/usr/bin/git`，最低版本为 2.20。能力预检失败时禁用工作树创建入口并提供具体原因。
- 仓库发现只检查工作区目录自身及其祖先 Git 关系，不扫描子目录。仓库根目录、仓库子目录以及 linked worktree 内的目录受支持。
- bare repository、unborn `HEAD`、sparse checkout 和不属于 Git 仓库的工作区不支持工作树会话。
- 创建流程开始时解析并捕获完整 `HEAD` commit hash，后续始终以该 commit 作为创建基线；不得在执行阶段重新读取并静默改用另一个 `HEAD`。
- 创建使用 detached worktree，不提供分支选择器。用户之后在终端中主动切换或创建分支时，Breath 尊重实际 Git 状态。
- 创建前读取 staged、unstaged、untracked 数量以及按路径去重的受影响文件合计。本地检出不干净时每次都要求确认，不保存跳过提示偏好。
- 创建内容只来自 Git 对象，不复制 staged、unstaged、untracked 或 ignored 文件，也不提供 `.worktreeinclude`。
- 创建 Git 进程使用一次性的空 hooks 目录覆盖 checkout hooks，并临时禁用所有自定义 checkout smudge/process filters。Git LFS 保持指针，不自动初始化 submodule。
- required checkout filter 无法安全禁用时，创建失败；不得为了兼容而执行仓库代码。
- Breath 不修改仓库、worktree、全局或系统 Git config，也不启用 `extensions.worktreeConfig`。
- 托管根目录位于 Breath 的应用支持目录，下一级按 Workspace ID 和 Work Session ID 组织。工作区子目录通过保存的仓库相对路径映射到新 worktree 内的会话工作目录。
- 托管根目录排除系统备份。Breath 不自动删除仍绑定活跃或已归档工作会话的 worktree，也不设置保留数量上限。
- 同一 Git common directory 的工作树写操作通过仓库级队列串行执行；不同 common directory 的操作可以并行。外部 Git 进程不受 Breath 队列控制。
- 创建是跨 Git、持久化和终端运行时的原子用例：只有工作树创建与验证、会话保存和第一个终端启动全部成功后，实际会话才对用户可见。
- 创建失败时按逆序停止终端、撤销会话状态和删除 worktree。清理失败时生成待清理记录，不暴露半成品会话。
- 启动对账扫描 Breath 托管根目录和持久化记录。无对应会话的 Breath 托管目录视为中断创建的孤儿并清理；清理失败转为待清理记录。不得处理外部 worktree。
- 待清理记录在设置的归档管理区域下方展示，支持重试、Finder 和复制路径，不支持忽略后删除记录。
- 创建、分屏、普通 Shell 启动、Agent 恢复、Git 状态、Git Diff、Finder 和编辑器入口统一解析会话工作目录，不再假设工作目录永远等于 Workspace 路径。
- 工作树会话的可用性通过实际目录、Git 元数据和 `worktree list` 登记共同验证。目录缺失、元数据损坏或未登记均为不可用。
- Breath 不自动执行 `worktree repair`、重新注册或重建不可用工作树。原始工作区不可用不必然导致工作树会话不可用，但共享 Git 元数据损坏会按实际结果标记。
- 运行中的终端检测到工作树不可用时不自动终止；禁止后续分屏、导出和恢复。终端结束、归档或应用退出后不再恢复。
- 工作树图标仅表达会话类型；不可用状态使用警告图标和可访问文本。后台会话不持续轮询 clean/dirty 状态。
- 选中会话每三秒刷新 Git 状态；选择会话、应用激活、打开菜单、归档删除页以及执行导出或删除前立即刷新。
- detached 状态显示短 commit；实际签出分支时显示分支名。相对基线提交统计与历史偏离警告只用于呈现和风险辅助，不取代实时引用检查。
- 会话行使用统一选项菜单。工作树会话增加 Finder、编辑器、复制路径和导出为分支；不可用会话只显示仍安全可执行的操作。
- “导出为分支”是一次性 `HEAD` 快照。默认建议 `breath/<会话短 ID>`，使用 Git 分支格式校验，拒绝已有分支，不 checkout 新分支，也不让分支持续追踪后续提交。
- 工作树存在未提交修改时仍允许导出，但必须提示这些修改不属于导出分支。最近导出分支名仅用于历史提示，不能作为删除安全依据。
- 首版不实现工作树与本地检出之间的自动 Handoff。
- 归档停止终端并保留 worktree、布局和 Agent 恢复信息，不要求 clean，也不执行代码删除风险检查。恢复只撤销归档，实际选择会话时才按需启动。
- 永久删除本地会话继续只删除 Breath 元数据。永久删除工作树会话同时删除其托管 worktree 和其中全部文件。
- 删除风险检查读取 staged、unstaged、untracked、去重文件合计、当前历史关系以及从当前 `HEAD` 可达但不被任何本地分支或标签引用的提交。
- 远端引用不能作为唯一提交保护依据。最近导出提示也不能代替实时本地引用检查。
- ignored 文件、依赖和构建缓存不触发代码风险，但计入按需计算的近似磁盘占用，并随 worktree 删除。
- 高风险删除要求输入对象名称：单个会话输入会话标题，移除工作区输入工作区名称。普通安全删除只使用普通确认。
- 最终确认后先停止终端并复检。出现新的修改、未保护提交或更高不确定性时中止删除并要求重新确认。
- 不可用 worktree 的目录已消失时可普通删除记录并尽力清理 Git 元数据；目录存在但状态无法验证时必须使用高风险确认。
- 外部 `worktree lock` 是不可绕过的删除阻塞。Breath 不自动 unlock。
- 移除工作区先聚合风险，确认后停止终端并复检，再逐个删除托管 worktree；只有全部成功后才删除会话和工作区元数据。
- 移除工作区中途失败时保留管理记录。已经删除 worktree 的会话标记为不可用，不重新创建；尚未处理的 worktree 保持原状。
- 多个 Workspace 即使共享同一个 Git common directory，也只拥有和清理各自创建的 worktree。
- 路径删除必须重新构造并验证 Breath 托管根、Workspace ID 与 Work Session ID。持久化绝对路径只能用于诊断和一致性比较，不能直接成为递归删除目标。
- 托管根及父路径存在符号链接、规范化路径逃出托管根或 ID 路径组件不匹配时，自动删除必须拒绝。
- 删除工作树内部内容和计算占用时不跟随符号链接；只删除链接本身。
- 清理先通过 Git 移除 linked worktree，再删除经过验证的托管根内残留。普通状态刷新不执行 `worktree prune`。
- Git lock、gc、repack 或外部 worktree 操作冲突时，不删除锁文件、不强制写入、不自动重试写操作。只读检查允许一次短暂重试。
- 正常退出等待当前工作树操作完成并禁止新操作，之后才进入终端保存与停止流程。强制退出不承诺完整回滚。
- Git 错误默认显示清理后的摘要和退出码；详细信息可包含参数与 stderr，但必须移除环境变量并遮蔽远端 URL 中的凭据。
- Git 错误详情不持久化、不上传。工作树持久化也不保存 diff、文件名列表或提交消息。
- 所有新增用户可见文案、图标状态、确认框和菜单必须提供中英文本地化和 VoiceOver 语义。

## Testing Decisions

- 主要测试 Seam 是 Workbench 用例边界。测试通过公开工作会话用例创建 Workspace、创建本地或工作树会话、分屏、归档、恢复、导出、删除和移除工作区，并观察持久化快照、终端启动目录、Git 仓库真实状态以及最终文件系统状态。
- 主要用例测试使用临时真实 Git 仓库和临时 Breath 托管根，同时使用内存 Workbench Repository 与记录型 Terminal Runtime。这样可从最高可行接缝覆盖业务编排和真实 Git 行为，而不是只断言内部命令字符串。
- 创建测试覆盖仓库根目录、仓库子目录、linked worktree 中目录、非 Git、unborn `HEAD`、bare、sparse checkout、Git 版本不足和同一仓库多 Workspace。
- 创建基线测试在捕获 `HEAD` 后改变当前分支或引用，验证实际 worktree 仍来自捕获 commit；捕获 commit 不可访问时验证安全失败。
- 本地修改提示测试覆盖 staged、unstaged、untracked、同一路径同时 staged/unstaged、renamed、copied 和冲突状态，并验证去重合计。
- 安全创建测试在临时仓库中安装会写 sentinel 文件的 post-checkout hook、自定义 filter、Git LFS 配置和 submodule，验证 Breath 创建不会执行或初始化它们。
- required filter 测试验证创建失败且不会执行 filter。测试观察文件和进程外部效果，不依赖具体 Git 参数排列。
- 原子创建测试在 Git 创建后、持久化时和终端启动时分别注入失败，验证不存在可见半成品会话、已启动终端停止、worktree 回滚或生成待清理记录。
- 启动对账测试覆盖有效会话目录、无会话孤儿目录、待清理失败、外部 worktree 和托管根之外目录，验证只处理 Breath 所有内容。
- 会话工作目录测试覆盖首个终端、分屏、冷启动恢复、Agent 恢复、Git 状态、Git Diff、Finder 与编辑器目标，验证都使用同一解析结果。
- 可用性测试覆盖目录删除、Git 元数据损坏、worktree 登记缺失、原始本地检出不可用和已运行终端后的失效，验证状态与进程行为。
- 状态刷新测试验证选中会话定时刷新，选择、激活和操作前立即刷新，后台会话不持续轮询。测试关注可观察读取次数和呈现结果，不依赖定时器内部实现。
- 分支导出测试覆盖默认建议名、合法性校验、同名拒绝、dirty worktree、detached、已经签出分支、后续提交不推进导出分支以及外部删除导出分支后的风险重算。
- 归档与恢复测试验证 worktree 目录和修改保持不变，归档不执行 Git 风险扫描，恢复仍按需启动原目录。
- 删除风险测试覆盖 clean worktree、staged、unstaged、untracked、ignored、受本地分支保护提交、受标签保护提交、仅远端引用提交、未保护提交和历史偏离。
- 删除确认测试验证安全删除、名称输入高风险确认、停止终端后风险复检、风险增加后的再次确认和风险降低后的继续执行。
- 不可用删除测试覆盖目录缺失、目录存在但元数据损坏、内容不可验证和 Git 元数据残留。
- 路径安全测试覆盖规范化路径逃逸、托管根父级符号链接、工作树内部符号链接、持久化路径篡改、Workspace/Session ID 不匹配和外部目录，验证不会越界删除。
- worktree lock 与 Git lock 测试验证 Breath 拒绝强制删除、不会 unlock、不会删除锁文件，并保留可重试状态。
- 工作区移除测试使用多个本地会话、多个工作树会话和多个共享 common directory 的 Workspace，验证风险聚合、停止顺序、逐个清理、部分失败和元数据保留。
- 并发测试验证同一 common directory 的 Breath 写操作串行、不同仓库可以并行，外部 Git 冲突表现为安全错误而不是锁文件清理。
- 退出协调测试验证正常退出等待工作树操作、等待期间拒绝新操作，并在操作结束后继续现有终端保存流程。
- 持久化测试验证工作树元数据 round trip、旧快照默认迁移为本地会话、待清理记录跨重启保留，以及数据库不包含 diff、文件名或提交消息。
- 错误清理测试验证摘要、详细 stderr、参数、环境变量排除、远端 URL 凭据遮蔽和错误不持久化。
- App Shell 测试覆盖工作区菜单入口、`⌘T` 默认本地、创建临时行、工作树与不可用图标、统一会话菜单、待清理区域和高风险输入确认。
- 可访问性测试覆盖工作树类型、不可用状态、进行中状态、菜单项、禁用原因和高风险确认，避免只用颜色或图标表达。
- 现有 `Workbench` 用例测试是工作会话生命周期的主要先例；现有 Git working-tree 状态和 Diff 测试提供临时真实仓库模式；现有 SQLite round-trip 测试提供兼容迁移先例；现有 App 命令与呈现测试提供菜单、快捷键和状态展示先例。
- 测试只断言外部行为、真实 Git/文件系统结果、持久化状态和用户可见呈现。除纯解析器、路径验证器和错误清理器外，不直接测试私有辅助方法或具体命令拼接实现。
- 人工验收至少覆盖：大型含 ignored 缓存的仓库、系统 `/usr/bin/git`、Finder 外部删除、JetBrains/终端并行 Git 操作、VoiceOver、正常退出等待和真实编辑器打开。

## Out of Scope

- 自动把工作树会话 Hand off 到本地检出，或反向把本地会话迁移到工作树。
- 创建时选择源分支、remote branch、tag 或任意 commit；首版只使用捕获的当前 `HEAD`。
- 把本地检出的 staged、unstaged、untracked 或 ignored 文件复制到新工作树。
- `.worktreeinclude`、`.env` 复制、依赖复制或项目初始化模板。
- 自动执行 checkout hooks、自定义 checkout filters、Git LFS 下载或 submodule 初始化。
- 支持 required checkout filter、sparse checkout、bare repository 或 unborn `HEAD`。
- 自定义 Git 可执行文件或读取用户 Shell `PATH`。
- 修改仓库、worktree、全局或系统 Git config。
- 导入、展示、归档、删除或修复用户通过其他工具创建的外部 worktree。
- 自动执行 `git worktree repair`、自动重新注册或自动重建不可用 worktree。
- 自动清理仍绑定活跃或已归档工作会话的托管 worktree。
- 基于时间、数量或磁盘阈值的 worktree 淘汰策略。
- 自动提交、stash、merge、rebase、cherry-pick 或 push 工作树成果。
- 让导出分支持续跟随 detached worktree 的后续提交。
- 把远端分支作为提交受到保护的唯一证据。
- 备份托管工作树到 Time Machine、iCloud、Breath 后端或云同步。
- 保存工作树 diff、文件名列表、提交消息、终端内容或 Agent 对话内容。
- 扫描工作区内部并让用户选择多个嵌套 Git 仓库。
- 把工作树作为会话树中的新层级，或让单个终端窗格拥有独立 worktree。
- 改变 Agent CLI 支持矩阵、Agent 状态模型、原生标题规则或一窗格一对话绑定。
- 完整 Git 工作台中的提交、分支、历史、合并、变基等通用 Git GUI 能力；本 PRD 只规定其目标必须解析到会话工作目录。

## Further Notes

- 本 PRD 使用项目术语“工作区”“工作会话”“会话工作目录”“本地会话”“工作树会话”“托管工作树”“不可用工作树”和“导出为分支”，避免使用“Agent 工作树”“隔离会话”或“保留为分支”等易误导名称。
- 本 PRD 遵守已确认的架构决策：工作树由工作会话独占、创建必须原子化、删除只允许经过验证的 Breath 托管路径、托管工作树不进入系统备份。
- Git 工作台保持独立领域模块，不读取 Agent 上下文或终端状态；但其 App Shell 目标解析必须从当前 Work Session 的 Session Working Directory 获取实际路径。现有 Git 工作台规格中“只传 Workspace 路径”的表述需要在实现前按此协调。
- “未受保护提交”是删除风险概念，不等同于“相对创建基线的所有新增提交”。最终判断必须基于当前 `HEAD` 可达集合与实时本地分支、标签引用。
- “工作树不可用”不表示会话已删除，也不表示可以安全重建。它是需要用户决定归档、诊断或高风险删除的独立状态。
- ignored 文件不构成 Git 代码风险，但永久删除仍会清理它们；近似磁盘占用用于让用户理解这一影响。
- 正常创建和删除不应产生网络访问。用户之后在终端中主动运行 Git、LFS、submodule 或项目脚本时，遵循其原有环境和配置。
- 本 PRD 已完成产品与技术边界确认，可直接进入票据拆分；本次任务不包含实现。
