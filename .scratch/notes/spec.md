# Breath 全局 Markdown 笔记库与笔记 Agent 抽屉

Status: ready-for-agent

## Problem Statement

Breath 当前以 Workspace、Work Session 和 Terminal Pane 为核心，适合围绕代码目录组织终端工作，但缺少一个轻量、全局、与 Workspace 解耦的知识记录入口。程序员仍需在 Breath 与 Typora、文件管理器、终端和 Agent CLI 之间切换，才能完成 Markdown 写作、文件整理、全文检索和基于整座笔记库的 Agent 对话。

这个缺口不能通过把笔记库伪装成 Workspace 来填补。笔记是跨项目的全局资料，生命周期、导航结构、快捷键、保存语义和 Agent 交互都不同于代码工作区。若复用 Workspace 身份，会污染 Session Tree、Git Workbench、恢复模型和 Agent 事件关联，也会让用户误以为笔记库具有 Work Session 语义。

目标用户熟悉 Markdown，期待接近 Typora 的单画布所见即所得体验，而不是带格式工具栏的富文本编辑器，也不是左右分栏预览。与此同时，`.md` 文件必须继续是唯一可信源：无改动打开并保存时应保持字节不变，局部编辑不应重写无关区域，外部工具和 Git 应能看到普通、可移植的 Markdown。

笔记还需要与本机 Agent CLI 协作。这个能力必须是一台真实终端，以笔记库为当前目录，复用 Breath 已有的 Agent 检测、恢复和终端基础设施；但它不能出现在 Workspace 或 Session Tree 中，也不能在抽屉关闭后意外终止长期对话。

## Solution

在 Activity Bar 增加全局“笔记”入口。首次进入时，用户选择一个现有本地目录或创建新目录作为唯一的全局 Note Library。该目录中的文件始终是事实来源；Breath 只持久化库引用、界面状态、可重建搜索索引和崩溃恢复数据。

笔记页由三个主要区域组成：

- 左侧可调宽度的文件/大纲侧边栏，支持文件夹层级、文件操作、文件名过滤和标题大纲。

- 顶部 Note Tab Bar，以 VS Code 风格展示所有已打开文件；未保存的标签标题带 `*`。

- 中央单画布 Markdown 编辑器。编辑器使用一个共享的 `WKWebView`，内置固定版本的 Tiptap Core 和 Breath 自有 Markdown 源码保真层，实现 Typora 风格所见即所得与源码模式切换。

Markdown 文件采用显式保存：编辑后只修改内存缓冲区并显示 `*`，按 `Cmd-S` 后通过原子写入更新源文件并清除 `*`。崩溃恢复快照独立存放，不等同于自动保存，也不覆盖源文件。普通关闭、批量关闭、退出应用和切换笔记库会按明确规则处理未保存内容；在文件树中删除文件则直接丢弃对应内存改动并把磁盘版本移入废纸篓。

编辑器支持 CommonMark、GFM 和 Typora 常用扩展，包括 Front Matter、脚注、TOC、数学公式、Mermaid、任务列表、表格、删除线、自动链接和受限 HTML。内置 GitHub、Gothic、Newsprint、Night、Pixyll、Whitey 六套主题，自动适配 Breath 当前 Light/Dark 外观，资源完全随应用离线发布，不提供导入和自动更新。

笔记页右上角提供 Agent 按钮，打开有最大宽度限制的右侧抽屉。用户从已安装且受支持的 Agent CLI 中显式选择一个，Breath 在原生终端中以 Note Library 根目录为当前目录启动它。抽屉隐藏、切换页面或关闭窗口不会停止会话；只有用户明确“结束对话”或退出 Breath 才会停止。Breath 只保存 Agent 类型和官方 Session ID 用于下次继续，不保存提示词、回复、工具输入输出或对话转录。

## User Stories

### 入口与笔记库

1. 作为使用 Breath 的开发者，我可以在最左侧 Activity Bar 看到独立的“笔记”入口，以便从任何 Workspace 状态进入全局笔记库。

2. 作为用户，当我选择“笔记”入口时，Session Tree 会隐藏，笔记页占据 Activity Bar 右侧的主要空间，以便笔记不会被误解为当前 Workspace 的一部分。

3. 作为首次使用笔记功能的用户，我可以选择一个现有本地目录或创建一个新目录作为 Note Library，以便继续使用普通文件系统和已有资料。

4. 作为用户，我在整个 Breath 中只有一个当前 Note Library，以便跨 Workspace 使用同一套全局笔记。

5. 作为用户，我不会在 Workspace 列表、Session Tree 或 Git Workbench 中看到 Note Library，以便其始终保持独立的产品语义。

6. 作为用户，我可以在“设置 → 笔记”中切换 Note Library，以便在需要时改用另一个目录。

7. 作为切换笔记库的用户，我会先处理所有未保存标签，然后才完成切换，以免丢失未决编辑。

8. 作为切换笔记库的用户，我知道 Breath 只会切换目录引用，不会移动、复制或删除原目录中的任何数据。

9. 作为使用外置磁盘或云盘目录的用户，当 Note Library 暂时不可访问时，我会看到当前路径以及“重试”“在 Finder 中显示”和“更换目录”等恢复动作。

10. 作为目录暂时不可访问的用户，Breath 不会在旧路径自动创建空目录，也不会擅自迁移数据，以免掩盖挂载或同步问题。

11. 作为用户，我的 Markdown、文本和附件始终以真实文件形式存在于 Note Library 中，以便可由 Finder、Git 和其他工具直接访问。

12. 作为关注数据可移植性的用户，我知道数据库中的笔记数据只承担元数据、缓存、界面恢复和崩溃恢复职责，而不是文件内容的权威副本。

### 文件树与文件操作

13. 作为用户，我可以在左侧侧边栏按文件夹层级浏览 Note Library，以便组织大量笔记和附件。

14. 作为用户，我可以在侧边栏的“文件”和“大纲”之间切换，以便在库导航和当前文档结构导航之间快速切换。

15. 作为用户，我可以拖动侧边栏边缘调整宽度，且 Breath 会记住合适的宽度。

16. 作为用户，我能看到文件夹、Markdown 文件、文本文件和普通附件，但看不到任何点文件，以减少与笔记无关的噪声。

17. 作为安全优先的用户，我在文件树中看不到符号链接，Breath 也不会遍历符号链接，以免越过 Note Library 边界。

18. 作为用户，我默认看到文件夹优先、名称自然排序的文件树，以便 `note2` 排在 `note10` 前。

19. 作为用户，我可以按名称、修改时间或创建时间排序，并选择升序或降序，以便适配不同整理方式。

20. 作为用户，我可以按名称快速过滤当前文件树，以便迅速找到已知文件。

21. 作为用户，我可以新建 Markdown 文件，Breath 会立即在当前目录创建 `未命名.md` 并进入行内重命名。

22. 作为用户，当 `未命名.md` 已存在时，新文件会使用不冲突的编号名称，以免覆盖已有文件。

23. 作为用户，我可以在当前目录新建文件夹并立即重命名。

24. 作为用户，我可以直接重命名文件或文件夹，包括编辑始终可见的文件扩展名。

25. 作为用户，我可以在 Note Library 内移动文件和文件夹。

26. 作为用户，我可以将树中的项目拖到另一个库内文件夹，且该操作语义是移动。

27. 作为用户，我可以从 Finder 把文件或文件夹拖入 Note Library，且该操作语义是复制，不会移动原始内容。

28. 作为用户，当 Finder 复制产生名称冲突时，我可以选择“保留两者”“替换”或“取消”。

29. 作为用户，我可以多选文件和文件夹，并批量移动、复制、删除或在 Finder 中显示。

30. 作为用户，我删除库内文件或文件夹时，内容会移入 macOS 废纸篓，而不是被永久删除。

31. 作为用户，我不会在笔记界面看到“永久删除”入口，以降低不可恢复的数据损失风险。

32. 作为用户，当我从文件树删除已打开且有未保存改动的文件时，Breath 会直接丢弃内存改动、关闭相关标签，并把磁盘版本移入废纸篓，不再弹出保存确认。

33. 作为用户，当我删除一个包含多个打开文件的文件夹时，所有相关标签和未保存缓冲区都会按同一删除语义关闭。

34. 作为用户，我可以在本次应用运行期间撤销新建、重命名、移动、复制和删除等文件树操作。

35. 作为用户，当焦点在文件树上时，`Cmd-Z` 撤销最近的文件操作；当焦点在编辑器中时，它只撤销文本编辑。

36. 作为用户，我理解文件操作撤销栈不会跨应用重启持久化。

37. 作为用户，我重命名或移动 Markdown 文件前会看到受影响相对链接的数量预览，以便理解操作范围。

38. 作为用户，我确认重命名或移动后，Breath 会原子更新整个 Note Library 中指向该文件的相对 Markdown 链接。

39. 作为用户，如果链接更新会触及仍有未保存改动的文件，操作会被阻止并提示我先保存或丢弃这些改动。

40. 作为用户，由重命名或移动自动完成的链接更新会直接写入磁盘，不会让相关标签出现 `*`。

### 文件类型、附件与链接

41. 作为用户，我打开 `.md` 或 `.markdown` 文件时，会进入所见即所得 Markdown 编辑器。

42. 作为用户，我打开 `.txt` 文件时，会进入纯文本源码编辑状态，而不会套用 Markdown 渲染。

43. 作为用户，我打开图片时，可以在 Breath 中预览图片。

44. 作为用户，我打开 PDF 或其他附件时，Breath 会交给 macOS 默认应用处理。

45. 作为用户，我不能使用 Breath 编辑 Note Library 之外的 Markdown 文件；外部文件由系统默认应用打开。

46. 作为用户，如果要把外部 Markdown 纳入笔记库，我可以把它拖入或复制到 Note Library。

47. 作为用户，我可以在 Markdown 中使用标准相对链接，并通过 `Cmd` 点击打开库内已有目标。

48. 作为用户，我不会得到 Obsidian 风格 `[[wikilinks]]`、双链面板或反向链接索引，以保持与 Typora 的定位一致。

49. 作为用户，当点击的 Markdown 链接目标不存在时，无论解析结果位于库内还是库外，我只会收到“目标不存在”提示，Breath 不会自动创建文件。

50. 作为用户，当链接指向 Note Library 之外且目标确实存在时，Breath 会按系统行为打开，而不会把外部文件纳入可编辑笔记标签。

51. 作为用户，我把图片或附件粘贴、拖入编辑器时，Breath 会把内容复制到 Note Library 根目录的 `_attachments/`。

52. 作为用户，当附件名称冲突时，Breath 会生成不冲突的文件名，并插入正确的相对路径。

53. 作为用户，我移动 Markdown 文件后，Breath 会更新其中指向 `_attachments/` 或其他库内资源的相对路径。

54. 作为用户，删除引用附件的笔记时，Breath 不会自动删除可能成为孤儿的附件，以免误删共享资源。

55. 作为用户，我不会在首个版本中看到“清理未使用附件”命令。

56. 作为用户，普通粘贴富文本或 HTML 时，Breath 会将其转换为干净 Markdown，并把内嵌附件存入 `_attachments/`。

57. 作为用户，我可以用 `Cmd-Shift-V` 只粘贴纯文本，以便绕过富文本转换。

### Markdown 编辑与源码保真

58. 作为熟悉 Markdown 的开发者，我在默认状态下使用接近 Typora 的单画布所见即所得编辑体验，而不是左右分栏预览。

59. 作为用户，我编辑当前结构时能看到必要的 Markdown 标记，光标离开后内容恢复为排版结果，以便兼顾源码意识和阅读体验。

60. 作为用户，我可以用 `Cmd-/` 在所见即所得和完整源码模式之间切换。

61. 作为用户，显示模式只属于当前标签；重新打开应用或文件时默认回到所见即所得模式。

62. 作为用户，我可以使用完整 CommonMark 语法。

63. 作为用户，我可以使用 GFM 表格、任务列表、删除线和自动链接。

64. 作为用户，我可以使用 YAML Front Matter，且字段顺序和原始排版不会因无关编辑被重写。

65. 作为用户，我可以使用脚注和 Typora 风格目录标记。

66. 作为用户，我可以使用行内与块级 LaTeX 数学公式。

67. 作为用户，我可以使用 Mermaid 图表。

68. 作为用户，我可以在 Markdown 中保留受支持的安全 HTML。

69. 作为用户，当语法暂未被所见即所得层理解时，原始源码仍会被保留，并且我随时可以在源码模式中编辑它。

70. 作为重视版本控制的用户，我打开一个文件后不做改动再保存，文件字节应保持完全不变。

71. 作为重视最小差异的用户，我只修改一个段落时，未修改区域的空行、标记风格、缩进、代码围栏、引用链接和 Front Matter 排列应保持字节一致。

72. 作为用户，Breath 会尽可能保留原文件的换行风格、编码和 BOM；新建 Markdown 文件使用明确且一致的 UTF-8 默认值。

73. 作为用户，我在编辑后会看到标签标题旁的 `*`，以便知道内容尚未保存到源文件。

74. 作为用户，我按 `Cmd-S` 后，Breath 会原子写入当前文件；成功时清除 `*`，失败时保留缓冲区、标签和错误提示。

75. 作为用户，如果撤销使内容精确回到上次保存状态，`*` 会自动消失；重做改动后它会重新出现。

76. 作为用户，我的源文件不会被自动保存，Markdown 编辑始终遵循显式保存语义。

77. 作为发生应用崩溃的用户，我可以在重启后恢复未保存标签和内容，且这些恢复快照从未提前覆盖源文件。

78. 作为用户，我保存或明确丢弃恢复内容后，对应的私有恢复快照会被清理。

79. 作为用户，当文档超过经测量确定的安全所见即所得阈值时，Breath 会默认以源码模式打开并解释原因，而不是拒绝、截断或静默丢失内容。

80. 作为大文档用户，我仍可以手动尝试切回所见即所得模式。

81. 作为用户，Markdown 中的脚本、事件处理器、iframe 和其他主动内容会被阻止或净化。

82. 作为用户，Mermaid 以严格安全模式运行，只执行随应用内置的受信脚本。

83. 作为用户，编辑器只能访问 Note Library 和应用内置资源，不能借助任意文件 URL 读取其他本地目录。

84. 作为用户，Markdown 中的 HTTPS 远程图片和内容可以加载，并遵循 Breath 的 Network Proxy 配置。

85. 作为用户，主题、字体、脚本和其他编辑器运行资源从应用包离线加载，不依赖运行时 CDN。

### 编辑交互

86. 作为用户，我可以在代码围栏中按语言获得语法高亮。

87. 作为用户，我把鼠标移到代码块上时可以复制整个代码块。

88. 作为用户，我可以在笔记设置中开启代码块行号，默认关闭，且该显示设置不会改写 Markdown。

89. 作为用户，我可以在所见即所得状态下编辑表格。

90. 作为用户，我在表格单元格中按 `Tab` 可以移动到下一单元格，并在末尾按需新增一行。

91. 作为用户，我可以从表格右键菜单添加或删除行列并调整对齐方式，而不需要常驻格式工具栏。

92. 作为用户，我可以直接点击任务列表复选框；该操作会修改文档并显示 `*`，直到显式保存。

93. 作为用户，当数学公式或 Mermaid 语法有误时，我会看到紧凑的行内错误和可编辑源码，且错误不会阻止保存或自动改写我的输入。

94. 作为用户，图片保持自然宽高比并受正文宽度约束，不提供拖拽缩放手柄；若需要精确尺寸，我可以使用 HTML 源码。

95. 作为用户，我会看到正文拼写错误下划线，但 Breath 不会自动更正文字。

96. 作为用户，拼写检查会忽略代码、链接、Front Matter、数学公式和 Mermaid 内容。

97. 作为用户，我可以在笔记设置中关闭拼写检查。

98. 作为开发者用户，我不会看到粗体、标题、列表等常驻或悬浮格式工具栏，因为可以直接输入 Markdown。

### 标签、保存与恢复

99. 作为用户，我打开文件时，会在编辑器顶部得到一个固定 Note Tab，而不是临时预览标签。

100. 作为用户，同一个文件最多只有一个标签；再次点击该文件只会聚焦已有标签。

101. 作为用户，我可以拖动标签改变顺序，且应用重启后恢复该顺序和当前选中标签。

102. 作为用户，当标签超过可用宽度时，我可以水平滚动或通过溢出入口定位标签。

103. 作为用户，我可以使用标签上的关闭按钮关闭文件，但不支持鼠标中键关闭。

104. 作为用户，我可以在标签右键菜单选择“关闭”“关闭其他”“关闭左侧”“关闭右侧”或“全部关闭”。

105. 作为用户，关闭一个有未保存改动的普通标签时，我可以选择“保存”“不保存”或“取消”。

106. 作为用户，批量关闭多个脏标签时，我会看到一次汇总确认，并可选择“全部保存”“全部不保存”或“取消”。

107. 作为用户，批量保存中写入失败的文件会保持打开和未保存状态，而不会被当作成功关闭。

108. 作为退出 Breath 或切换 Note Library 的用户，我必须处理全部未保存标签；流程可以取消，防止意外丢失。

109. 作为用户，当两个打开文件同名时，标签会显示能消除歧义的最短父目录路径，悬停时显示完整路径。

110. 作为重启应用的用户，我会恢复上次打开的干净标签、顺序和选中项。

111. 作为用户，当恢复标签对应的文件已缺失或移动时，我会看到不可用标签，并可关闭它或将可恢复缓冲区另存为新文件。

112. 作为用户，当一个没有未保存改动的打开文件被外部工具修改时，Breath 会自动重新加载磁盘内容。

113. 作为用户，当有未保存改动的打开文件又被外部修改时，我会看到冲突提示，并可选择“比较”“用我的版本覆盖”或“重新加载磁盘版本”。

114. 作为用户，我选择“比较”时能看懂内存版本与磁盘版本的差异，然后再决定处理方式。

115. 作为用户，当打开文件被外部删除或移动时，Breath 会保留内存内容，并允许我另存为，而不是立即丢弃。

116. 作为用户，我不会在首个版本中看到标签分组、固定标签或编辑器分屏。

### 搜索、快捷键与设置

117. 作为用户，我可以使用当前文件搜索快速定位匹配内容。

## Implementation Decisions

### 领域边界

- 引入独立的 Notes 领域模块，负责 Note Library、文件清单、Note Tab、草稿、脏状态、恢复、冲突、搜索和 Note Agent Conversation 的用例与协议。领域层不依赖 SwiftUI、AppKit、WebKit 或 GRDB 类型。

- Note Library 是一个用户选择的、全局唯一的真实本地目录。它不是 Workspace，也不能通过创建隐藏 Workspace、Work Session 或 Terminal Pane 来复用既有身份。

- Note Document 的文件内容是唯一事实来源。数据库可以持久化库引用、界面状态、文件元数据、可重建全文索引、恢复快照和 Agent 恢复绑定，但不能成为源内容的权威副本。

- Note Tab 表示一个文件的打开状态、内存缓冲区、最后保存基线、脏状态、显示模式和冲突状态。同一规范化文件身份最多对应一个标签。

- Note Agent Conversation 是一个以 Note Library 为范围的独立 Agent 会话身份。它复用 Agent Adapter、官方 Agent Session ID 和事件语义，但不从属于 Work Session 或 Terminal Pane。

### 应用外壳与导航

- 在现有 Activity Bar 路由中增加 Notes 模式。Notes 与 Automation、Skills、Settings 等全局页面一致，不显示 Session Tree。

- Notes 页面保持原生 SwiftUI/AppKit 外壳：Activity Bar、文件树、标签栏、搜索结果、对话框、设置和抽屉布局均不放入 WebView。

- Notes 相关快捷键只在 Notes 命令上下文生效。事件路由必须基于当前页面和焦点区分文件操作撤销、编辑器撤销及现有 Workspace 快捷键。

- 应用退出协调器同时处理未保存 Note Tab 和仍在运行的 Note Agent；退出可以因用户取消保存流程而中止。

### 文件系统与持久化

- 文件清单以 Note Library 的实时文件系统状态为准，并使用目录事件监控合并外部变更。监控必须防抖、可重建，并能区分 Breath 自己完成的原子操作与真正外部写入。

- 目录遍历明确跳过点文件和所有符号链接。每个文件操作都要在执行时再次验证规范化目标仍在 Note Library 允许边界内，以防竞态越界。

- 保存采用同目录临时文件、同步落盘和原子替换策略；写入失败不得清除脏状态或恢复快照。

- 文件删除调用 macOS 废纸篓能力。永久删除不属于此功能。

- 本次运行中的文件操作撤销使用内存命令栈，记录足以逆转新建、重命名、移动、复制和移入废纸篓的操作信息；应用退出后丢弃该栈。

- 库内重命名和移动通过一个事务式文件操作协调器执行：先扫描并预览相对链接影响，验证受影响文件无未保存缓冲区，暂存所有修改，再提交文件操作和链接更新；失败时回滚到一致状态。

- `_attachments/` 固定在 Note Library 根目录。附件导入使用安全文件名和冲突后缀，先完成复制再插入相对链接。

- Notes 元数据、恢复快照和搜索索引通过现有持久化边界接入 GRDB，并遵循既有迁移、文件权限和隐私约束。切换笔记库时清除旧库的可重建索引与不再需要的恢复绑定。

- 全文搜索使用本地 FTS 索引。索引是派生数据，必须支持全量重建；结果保留文件身份、路径、片段和可定位的行信息。

### 编辑器架构

- 整个 Markdown 编辑画布使用一个共享 `WKWebView`；切换 Note Tab 时只切换文档状态，不为每个标签创建独立 WebView。这样可以限制内存、进程和脚本运行成本。

- 编辑内核固定为 Tiptap Core 加 Breath 自有 Markdown 源码保真层和必要扩展，不依赖 Tiptap Cloud 或付费能力。所有 JavaScript、CSS、字体和渲染依赖固定版本并打包进应用。

- Markdown 源字符串是唯一编辑事实来源。所见即所得层维护源码区间与结构节点之间的映射，编辑时只为受影响区间生成补丁；未触及区间直接沿用原字节。

- 源码保真层必须显式建模换行、空行、围栏、缩进、标记选择、引用式链接、Front Matter 和未知语法。不能用“把整个文档解析成抽象树再全部序列化”作为保存主路径。

- 源码模式与所见即所得模式共享同一内存文档和撤销历史；切换模式不得隐式保存、规范化或产生额外差异。

- 编辑器与原生层之间使用窄而可版本化的消息协议，至少覆盖载入、补丁、选择区、撤销状态、脏状态、保存快照、链接动作、附件导入、当前搜索、主题、外观和错误。消息必须验证文档身份和递增版本，拒绝旧标签的迟到响应。

- WebView 使用受控本地资源入口，只允许访问应用打包资源与当前 Note Library 中经验证的文件。远程 HTTPS 内容通过 Breath 可控的网络加载边界获取，以应用 Network Proxy 和安全策略为准，而不是向页面开放任意网络或本地文件权限。

- HTML 净化和 Mermaid 严格模式属于保存与展示的共同安全边界。任何主动内容都不能通过所见即所得预览获得脚本执行或任意导航能力。

- 大文档阈值必须由基准测试确定，并同时考虑文件大小、节点数、表格规模、数学公式、Mermaid 和内嵌 HTML 等复杂度。超过阈值只改变默认展示模式，不改变完整加载和保存能力。

- `.txt` 复用同一画布的纯文本源码能力，但不启用 Markdown 结构、主题渲染或 Markdown 自动转换。

- 图片预览和系统附件打开由原生层负责。编辑器发出的链接与附件动作先交由原生层解析和验证边界。

### Markdown 能力与主题

- 兼容基线为 CommonMark、GFM 和已确认的 Typora 常用扩展。每一种扩展都要定义源码解析、所见即所得显示、编辑、撤销、保存和错误降级行为。

- 未支持或解析失败的 Markdown 片段必须作为不透明源码保留，不能在加载或保存时删除、转义或改写。

- 富文本粘贴先净化 HTML，再转换为 Markdown；二进制附件交给原生附件服务落盘。纯文本粘贴完全绕过转换。

- 代码高亮、Mermaid 和数学渲染仅使用打包依赖。渲染失败显示局部错误，不影响源文件保存。

- 六套内置主题以 Breath 自有、可离线发布的资源包交付。若 Typora 原始主题资源的许可证不允许直接分发，则按可观察视觉特征重新实现，不复制受限 CSS、字体或图片。

- Light/Dark 分类在构建或资源注册阶段自动生成并由测试验证，不提供用户手工分类。每种外观分别记住用户选择，默认组合为 GitHub Light 和 Night Dark。

- Markdown 主题与 Terminal Settings 严格分离；Agent 抽屉只消费 Terminal Settings。

### 标签、恢复与冲突

- 脏状态通过当前源码内容与最后成功保存基线的精确比较得出，不能只依赖“发生过编辑”布尔值，因此撤销回保存点时 `*` 可以消失。

- 普通应用运行中不自动写源文件。恢复服务可以节流写入私有恢复快照，但快照必须包含源文件身份、基线指纹和足够的恢复数据，并与权威文件明确分离。

- 应用启动先恢复 Note Library 引用和标签元数据，再验证文件身份；只有存在恢复快照的标签恢复未保存缓冲区。

- 正常关闭单个或多个标签走原生保存确认。文件树删除是一条明确例外路径：它不询问保存，先丢弃相关缓冲区，再对磁盘版本执行移入废纸篓。

- 外部变更通过最后加载指纹与当前脏状态分类。干净标签自动重载；脏标签冻结自动覆盖并进入冲突状态；外部删除或移动保留内存缓冲区并提供另存为。

- “比较”使用面向 Markdown 用户的只读差异视图，展示磁盘版本与当前缓冲区，不引入替换或通用代码编辑器能力。

### Agent 终端

- Agent 选择器复用现有“已安装的受支持 Agent CLI”检测和 Adapter 注册信息，并沿用外部编辑器启动器的主按钮加菜单交互形式。

- Note Agent 启动复用现有原生终端引擎，但终端运行时必须支持独立的 Note Agent 所有者类型；禁止生成虚假的 WorkspaceID、WorkSessionID 或 TerminalPaneID。

- Agent 事件关联协议扩展为可区分的会话范围：现有 Terminal Pane 范围保持不变，新增 Note Library 范围。两者继续共享 Agent 类型、Agent Session ID、状态、通知级别和最小事件语义。

- 任一时刻只允许一个 Note Agent Conversation。隐藏抽屉只改变视图可见性，不改变进程所有权或生命周期。

- 显式结束使用已有 Agent 适配器和终端进程终止流程，清除 Breath 的继续绑定，但不操作 CLI 自有的转录或历史存储。

- 恢复信息只包含 Agent 类型与官方 Session ID。重新启动应用后必须由用户选择继续或新建，不能自动派生进程。

- Note Agent 不自动注入当前文档上下文。进程只获得经验证的 Note Library 工作目录以及用户终端环境。

- 抽屉宽度采用默认 420pt、最小 340pt、最大 `min(笔记页宽度 × 45%, 720pt)` 的约束，并保存经过约束后的用户偏好。

- 抽屉隐藏时只在按钮上呈现状态和无障碍描述，不自动展示 UI、抢焦点或发送系统通知。

### 隐私、网络与可观测性

- 延续最小 Agent 数据原则：Breath 不记录提示词、回复、工具调用输入输出、转录或终端滚屏内容。

- Notes 不引入账户、后端、遥测或 Breath 云同步。搜索索引和恢复快照只保存在本机。

- Markdown 远程 HTTPS 资源属于 Breath 内建网络请求，应用 Network Proxy 对其生效；Agent 终端中的网络命令仍属于用户 CLI 进程，不自动继承该代理设置。

- 日志只记录可诊断的状态和不含内容的标识信息，例如文件操作阶段、索引状态、编辑器协议版本、Agent 类型与生命周期结果。不得记录笔记正文、搜索查询、Markdown 片段或 Agent 内容。

- 所有原生控件和关键编辑状态需要 VoiceOver 标签、键盘焦点顺序和不依赖颜色的状态表达。

## Testing Decisions

### 主要测试接缝

最高价值的测试接缝是 Notes 应用用例层，而不是逐个 SwiftUI View 或逐个 WebView 消息处理器。建立一个 Notes 功能测试驱动器，组合真实临时 Note Library、真实 Notes 持久化、真实文件监控/文件操作实现和可控时钟，同时用测试替身替代终端进程及 Agent 外部事件。测试从用户动作出发，例如“打开文件、编辑、保存、移动、搜索、收到外部变更、启动 Agent、退出应用”，并观察：

- 磁盘上的真实文件、目录、链接和附件结果。

- Note Tab 顺序、选中项、脏状态、冲突状态和恢复状态。

- 索引结果及切库后的派生数据清理。

- 文件操作撤销与删除例外语义。

- Agent 启动参数、生命周期、恢复绑定和退出协调结果。

选择这一接缝是因为绝大多数风险来自跨组件状态机：文件系统、标签缓冲区、持久化、外部变更和终端生命周期之间必须保持一致。若只测 ViewModel 或单个仓库，会错过真实原子写入、文件身份变化、恢复顺序和竞态；若主要依赖端到端 UI 测试，反馈会过慢且难以穷举失败分支。

该驱动器至少覆盖以下场景族：

- 首次建库、启动恢复、目录不可访问、切换库及旧索引清理。

- 新建、重命名、移动、复制、外部拖入、冲突选择、废纸篓删除及运行期撤销。

- 链接影响预览、脏文件阻塞、原子链接更新和附件路径更新。

- 单标签与批量保存确认、保存失败、删除无确认、崩溃恢复及另存为。

- 干净外部修改、脏冲突、外部删除、事件合并及 Breath 自写事件去重。

- 文件名过滤、全文索引、重建索引、片段与行定位。

- Note Agent 的选择、启动目录、单实例切换、隐藏不停止、显式结束、应用退出和下次继续。

### 编辑器不可替代契约测试

源码保真和输入法行为无法由用例层测试替身证明，因此增加一套小而强的真实编辑器契约测试。测试在打包后的同一 Tiptap/Markdown 资源和真实 `WKWebView` 协议上运行，并使用固定 Markdown 语料库。它必须验证：

- 每种受支持语法的加载、所见即所得显示、源码切换、局部编辑、撤销、重做和保存。

- 未改动打开再保存为逐字节零差异。

- 单一区间编辑只改变预期字节范围，保留 CRLF/LF、BOM、空行、围栏、缩进、引用链接和 Front Matter 顺序。

- 未支持语法和解析错误能往返保留。

- 中文及其他组合输入法的 composition、候选确认、撤销边界和光标位置。

- 表格键盘操作、任务复选框、富文本/纯文本粘贴、数学和 Mermaid 错误降级。

- HTML 净化、本地文件访问边界、远程资源代理入口和迟到消息版本拒绝。

- 标签快速切换时共享 WebView 不串文档、不丢选择区、不把旧响应应用到新标签。

- 大文档阈值和手动尝试所见即所得的降级行为。

这套契约测试是发布门槛；不能用纯 JavaScript 单元测试或 mocked WebView 替代，因为 macOS WebKit、IME 和原生消息桥本身就是风险的一部分。

### 原生外壳与终端边界

复用现有应用外壳测试驱动器，增加少量原生冒烟测试，验证 Activity Bar 路由、Session Tree 隐藏、标签可访问名称、快捷键上下文、保存对话框、Agent 状态按钮和抽屉宽度约束。避免重复验证已经由主要用例接缝覆盖的文件业务规则。

复用现有终端运行时契约，增加 Note Agent 所有者类型的测试，验证：

- 启动 `cwd` 为 Note Library，且不会创建 Workspace、Work Session 或 Terminal Pane。

- 原生终端输入、调整尺寸、终止和应用退出仍符合现有运行时契约。

- Agent 事件可按 Note Agent Conversation 关联，同时不改变现有 Terminal Pane 事件关联。

- 恢复只依赖 Agent 类型和官方 Session ID，不持久化对话内容。

### 持久化、迁移与隐私

扩展真实 SQLite 仓库测试，覆盖 Notes 设置、标签恢复、草稿恢复、搜索索引、Agent 恢复绑定、模式迁移和损坏恢复。继续执行数据库原始字节隐私扫描，确保未意外写入 Agent 提示词、回复或终端内容；对笔记正文只允许出现在明确批准的恢复快照和可重建全文索引中。

增加打包资源测试，确认固定版本的编辑器依赖和六套主题均可离线加载、没有 CDN 引用、Light/Dark 分类完整，且发布包只包含通过许可证审计的资源。

### 性能与可靠性门槛

以代表性小文档、长文档、大表格、重 Mermaid/数学文档和大型目录建立基准。记录首次打开、标签切换、键入响应、保存、全文搜索、索引重建和目录变更收敛时间，并据此确定而不是猜测大文档降级阈值。

在可控故障注入下验证磁盘写满、权限变化、文件被并发移动、索引损坏、WebView 进程重启和 Agent 进程异常退出。任何故障都不能导致源文件静默截断、未保存缓冲区丢失、链接半更新或虚假的保存成功状态。

## Out of Scope

- 多个同时挂载的 Note Library、每 Workspace 笔记库或把 Note Library 转换成 Workspace。

- Breath 账户、云端后端、内建同步、协作编辑或遥测。用户可自行把目录放入 iCloud、Dropbox 或 Git。

- Obsidian wikilinks、双链、反向链接、关系图谱、标签数据库或标签专用 UI。

- 编辑 Note Library 外部的 Markdown 文件、通用代码编辑器能力或文件类型插件系统。

- 搜索替换、跨文件替换和任何“仅替换”模式。

- 常驻格式工具栏、悬浮格式按钮和面向不熟悉 Markdown 用户的写作引导。

- 预览标签、固定标签、标签组、编辑器分屏和 `Cmd-1` 至 `Cmd-9` 切换。

- 自动保存源文件。崩溃恢复快照不视为自动保存。

- 永久删除、跨重启的文件操作撤销历史和 Note Library 内建版本历史。

- 自动清理孤儿附件或首个版本中的附件管理器。

- PDF/HTML 导出、打印和发布功能。

- Notes 页面内的 Git 状态、提交、分支或 Git Workbench 集成。需要 Git 工作流时，用户可以把同一目录显式添加为 Workspace。

- Typora 主题文件导入、社区主题市场、自定义 CSS、运行时下载或主题自动更新。

- 应用级 AI 聊天 UI、Web 聊天、多个 Note Agent 终端、终端分屏或自动注入当前笔记上下文。

- 将 Note Agent 展示在 Workspace、Session Tree、Work Session 或 Git Workbench 中。

- Note Agent 状态触发的自动展开、抢焦点或 macOS 系统通知。

- 由 Breath 替代 Agent CLI 自身的权限、沙箱、认证、历史记录或网络代理策略。

## Further Notes

### 需要加入领域词汇表的术语

- **Note Library**：用户选择的、全局唯一的真实本地目录，是所有 Note Document 的文件系统边界；不属于 Workspace。

- **Note Document**：Note Library 内可由 Notes 功能打开的文件。对 Markdown 和文本文件，磁盘文件是内容事实来源。

- **Note Tab**：一个 Note Document 在 Breath 中的打开与编辑状态，包括内存缓冲区、保存基线、脏状态、冲突和恢复信息。

- **Note Agent Conversation**：从 Notes 抽屉启动、范围为 Note Library 的单一 Agent 对话。它拥有 Agent 类型与官方 Agent Session ID，但不属于 Work Session 或 Terminal Pane。

- **Note Agent Terminal**：承载 Note Agent Conversation 的真实原生终端运行时。它是 Notes 功能私有的终端所有者类型，不出现在 Session Tree。

### 架构决策门槛

- 现有 ADR 0006 将“产品整体不使用 WebView”作为原生外壳决策。本 PRD 已明确选择 `WKWebView` 承载 Markdown 编辑画布，因此实现前必须新增一份替代或补充 ADR：把例外严格限定在 Notes Markdown 编辑画布，并记录为何源码保真、复杂 Markdown、Mermaid 与 Typora 式交互使该折中成立。外壳和 Agent 终端仍保持原生。

- 现有 ADR 0010 和 0017 将 Agent 事件及 Agent Conversation 绑定到 Workspace/Work Session/Terminal Pane。本功能要求独立的 Note Agent Conversation，因此实现前必须通过 ADR 定义可区分的 Agent 会话范围和事件关联键，且明确禁止伪造既有 ID。

- ADR 0011 的最小 Agent 数据原则继续生效：只存 Agent 类型、官方 Session ID 和不含内容的生命周期状态。

- ADR 0012 的本地优先、无账号、无后端、无同步和无遥测原则继续生效。

- ADR 0013 的持久化边界继续生效：视图只依赖领域与仓库接口，不直接依赖数据库记录。

### 发布门槛与开放风险

- Tiptap Core、Markdown 扩展、语法高亮、数学、Mermaid、主题 CSS、字体和图片都必须固定版本、离线打包，并在发布前完成许可证与归属审计。

- “兼容 Typora 主题”指六套已确认主题的用户可观察外观和 Light/Dark 使用体验，不代表可以在许可证不允许时逐字复制 Typora 主题资源。

- 源码保真是产品验收条件，不是后续优化。若某种已承诺语法无法满足“零改动零差异、局部改动最小差异”，该语法不得以会重写整篇文档的方式仓促上线。

- WebView 性能风险通过单共享实例、轻量标签状态、基准确定的大文档降级和真实 WebKit 契约测试控制。不能仅以简单 Markdown demo 的帧率判断可发布性。

- 外部同步工具可能产生原子替换、临时文件、批量事件和冲突副本。文件监控设计必须以最终文件系统状态收敛为目标，而不是假定每个事件都对应一次用户操作。

- Note Agent 可以修改整个 Note Library，这一能力应在首次启动时清楚说明；Breath 不额外限制 CLI 权限，但仍必须安全验证启动目录并避免符号链接越界。

- 本 PRD 已达到 `ready-for-agent`，下一步应先完成两项 ADR，再按“领域与持久化 → 文件用例与测试驱动器 → 编辑器源码保真原型与契约 → 原生页面 → Agent 抽屉 → 性能/安全/许可证发布门槛”的依赖顺序拆分实现任务。
