# 安全重命名和移动文件并改写相对链接

Status: implemented

## Parent

[Breath 全局 Markdown 笔记库与笔记 Agent 抽屉](../spec.md)

## What to build

交付链接感知的库内重命名和移动：在真正修改文件系统前扫描整个 Note Library 的标准相对 Markdown 链接，向用户预览影响，阻止会覆盖未保存缓冲区的操作，并以可回滚的方式提交路径变化和链接补丁。该切片同时把重命名和移动纳入运行期文件操作撤销。

本切片覆盖 PRD User Stories 24–26、34–40、53。

## Acceptance criteria

- [ ] 用户可以行内重命名文件和文件夹，文件扩展名始终可见且可编辑
- [ ] 用户可以通过菜单、批量操作或库内拖放移动文件和文件夹；库内拖放语义始终是移动
- [ ] 执行前扫描 Markdown 行内链接、图片链接和引用式链接，按规范化文件身份计算受影响文件与链接数量
- [ ] 确认界面展示路径变化和影响计数，不展示或支持 Obsidian `[[wikilinks]]` 更新
- [ ] 若任一待改写文件存在未保存 Note Tab，操作被阻止并引导用户先保存或丢弃，不使用磁盘旧版本覆盖内存
- [ ] 重命名或移动与所有相对链接改写作为一个可回滚操作提交；任何阶段失败都不会留下半更新路径或链接
- [ ] 未触及的 Markdown 区域保持字节一致，链接补丁只修改需要变化的目标范围
- [ ] 打开的目标文件在成功后保持同一个 Note Tab 身份并更新路径、标题和同名消歧信息
- [ ] 自动改写磁盘文件后，干净的已打开标签同步新基线且不出现 `*`
- [ ] 移动 Note Document 时同步改写其内部指向 `_attachments/` 和其他库内资源的相对路径
- [ ] 运行期撤销可以逆转重命名、移动和链接补丁；焦点与不可跨重启规则沿用既有文件操作撤销契约
- [ ] 文件夹操作正确处理深层子项、同名冲突、循环目标和被外部并发修改的文件
- [ ] 使用真实临时目录和包含多种链接风格的固定语料验证影响预览、原子提交、故障回滚、脏文件阻塞、最小差异和撤销
- [ ] App Shell 验证覆盖拖放目标、影响确认、阻塞原因、失败恢复、键盘和 VoiceOver 状态
