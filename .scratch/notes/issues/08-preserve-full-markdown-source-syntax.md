# 保真支持完整 Markdown 源码语法

Status: implemented

## Parent

[Breath 全局 Markdown 笔记库与笔记 Agent 抽屉](../spec.md)

## What to build

把第一条基础编辑路径扩展为完整、源码保真的 Markdown 文档模型。用户可以编辑 CommonMark、GFM、YAML Front Matter、脚注和 TOC；不认识的语法仍原样保留。保存以源码区间补丁为核心，不允许通过整篇重新序列化制造无关差异。

本切片覆盖 PRD User Stories 62–65、69–72，并建立所有后续结构化编辑和复杂渲染共用的固定语料契约。

## Acceptance criteria

- [ ] 支持完整 CommonMark 块级与行内语法，并在所见即所得和源码模式之间共享同一文档与撤销历史
- [ ] 支持 GFM 删除线、自动链接、表格和任务列表的解析、显示与源码往返；高级交互由后续切片补充
- [ ] 支持 YAML Front Matter，保持键顺序、注释、空行、引号和原始排版，不把它解释成 Notes 标签数据库
- [ ] 支持脚注定义、引用和 Typora 常见 TOC 标记，并在编辑后保持可移植 Markdown
- [ ] 未支持、解析失败或未来扩展语法作为不透明源码区间保留，用户可以在源码模式中编辑
- [ ] 打开文档后不做改动再保存，输出与输入逐字节一致
- [ ] 修改一个结构节点时只替换对应源码区间，未触及区域的空行、标记选择、缩进、围栏和引用式链接保持字节一致
- [ ] 保存尽可能保留原文件编码、BOM 和 LF/CRLF 换行；新文件使用一致的 UTF-8 默认值
- [ ] 源码模式和所见即所得模式切换不隐式保存、规范化内容或产生 `*`
- [ ] 编辑器消息带文档身份和递增版本，快速切换标签后拒绝旧解析或旧补丁结果
- [ ] Tiptap Core、解析扩展和转换依赖固定版本并离线打包，不使用 Tiptap Cloud、付费扩展或运行时 CDN
- [ ] 编辑器不提供常驻或悬浮格式工具栏，所有结构仍可通过 Markdown 输入和上下文交互编辑
- [ ] 固定语料覆盖 CommonMark、GFM、Front Matter、脚注、TOC、未知语法、混合换行、BOM 和不同标记风格
- [ ] 真实 WebKit 契约逐字节验证零改动零差异、局部改动最小差异、模式切换、撤销重做和标签快速切换
- [ ] 应用用例测试验证成功保存、失败保留、脏状态和链接更新可以消费同一源码补丁契约
