# 创建、导入、删除并撤销文件操作

Status: implemented

## Parent

[Breath 全局 Markdown 笔记库与笔记 Agent 抽屉](../spec.md)

## What to build

让用户在文件树中创建、导入、复制、批量选择和删除真实文件，并在当前应用运行期间撤销这些操作。删除明确采用 macOS 废纸篓语义，即使相关 Note Tab 有未保存修改也直接丢弃内存版本，不弹出普通关闭保存确认。

本切片覆盖 PRD User Stories 21–23、27–36、125。重命名、库内移动及其链接更新由后续切片扩展。

## Acceptance criteria

- [ ] `Cmd-N` 和文件树新建操作立即在选中目录创建 `未命名.md` 并进入行内重命名；冲突时使用稳定编号且不覆盖已有文件
- [ ] 用户可以在选中目录创建文件夹并立即进入行内重命名
- [ ] Finder 拖入文件或文件夹执行复制而非移动，复制前验证目标边界并保留原始内容
- [ ] 复制名称冲突时提供“保留两者”“替换”或“取消”，批量操作对每类冲突使用明确且一致的选择
- [ ] 文件树支持多选，并对所选项目执行复制、删除和在 Finder 中显示；嵌套选择不会重复处理子项
- [ ] 删除文件或文件夹使用 macOS 废纸篓，不提供永久删除入口
- [ ] 删除已打开文件或包含已打开文件的文件夹时，直接丢弃对应内存改动、关闭标签并把磁盘版本移入废纸篓，不显示保存确认
- [ ] 若任一删除目标不能安全移入废纸篓，失败项目保持原状并向用户展示逐项结果，不伪报整体成功
- [ ] 当前运行中的文件操作撤销栈可以逆转新建、复制和移入废纸篓，并在可逆性失效时返回明确原因
- [ ] 焦点在文件树时 `Cmd-Z` 撤销文件操作；焦点在编辑器时只撤销文本，两个撤销历史不会互相消费
- [ ] 文件操作撤销栈不持久化，应用重启后不展示或尝试恢复旧命令
- [ ] 每次写操作在执行时重新验证规范化源和目标，不跟随符号链接，也不越过 Note Library
- [ ] 使用临时真实目录覆盖名称冲突、嵌套批量选择、复制失败、删除脏标签、废纸篓适配器失败、撤销和焦点路由
- [ ] App Shell 验证覆盖行内重命名、多选、拖放、冲突对话框、删除例外提示、撤销状态、键盘和 VoiceOver 反馈
