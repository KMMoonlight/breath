# Breath 全局 Skills 管理

Status: implemented

## Problem Statement

Breath 用户同时使用多个 Agent CLI，但每个 Agent 的全局 Skill 分散在不同的用户目录中。用户无法在 Breath 内统一确认自己已经安装了哪些 Skill、同一个 Skill 覆盖了哪些 Agent、内容是否被外部修改、是否存在可用更新，也无法从一个可信且可审阅的流程把新 Skill 分发到自己明确选择的 Agent。

现有安装方式还要求用户理解 ZIP 结构、GitHub Repo 布局、skills.sh 命令、各 Agent 目录和符号链接行为。安装来源可能包含多个 Skill，也可能带有格式错误、危险路径、脚本或同名内容；直接复制或执行第三方安装器会增加静默覆盖、部分写入、来源丢失、遥测和工具依赖风险。

用户需要一个全局、原生、可审阅的 Skills 管理入口。它必须以各 Agent 目录的实际文件为事实来源，尊重用户通过其他工具安装和修改的内容，在所有写入前明确展示影响，并保持 Breath 既有的本地优先、无账户、无自建后端和无遥测边界。

## Solution

Breath 在主窗口侧栏底部栏增加全局 Skills 入口。该页面不属于任何工作区，即使没有工作区也可访问；它扫描所有受支持且已安装 Agent CLI 的实际全局 Skill 目录，将内容一致的跨 Agent 副本聚合展示，并把同名但内容不同的 Skill 作为独立条目，通过 `description`、来源和真实路径区分。

用户可以通过 ZIP、指定公开 GitHub Repo 或 skills.sh 关键词搜索发现候选 Skill。所有来源进入同一个分步安装流程：解析来源、多选候选 Skill、明确选择 Skill 安装目标、查看文件与 `SKILL.md`、审阅已有同名内容和安全提示，然后确认写入。Breath 使用 Swift 原生完成解析、校验和文件操作，不依赖 Node.js 或 `npx skills`，也不执行来源中的脚本。

Breath 把完整 Skill 文件直接安装到每个 Skill 安装目标的真实全局目录，不保存中心副本、不创建分发符号链接，也不向第三方 Skill 目录写入私有元数据。远程来源关联保存在 Breath 的本地 SQLite 安装记录中；磁盘内容始终决定是否已安装，数据库只负责可验证上游和更新能力。

GitHub 和 skills.sh 来源的 Skill 可以在打开 Skills 页面时检查更新。更新必须逐个 Skill 审阅并由用户确认；ZIP 和来源未知 Skill 不提供更新。用户可以按 Agent 卸载，普通目录移入 macOS 废纸篓，外部符号链接只移除链接。批量安装、更新和卸载允许部分成功，每个“Skill × Skill 安装目标”独立报告结果，同时保证单个目标不会留下不完整目录。

## User Stories

1. 作为使用多个 Agent CLI 的开发者，我希望在一个页面查看全部全局 Skill，从而不必逐个检查不同 Agent 的用户目录。
2. 作为没有添加工作区的用户，我希望仍能进入 Skills 页面，从而在开始项目工作前配置全局能力。
3. 作为正在查看 Skills 的用户，我希望选择任一工作会话后返回终端，从而保持现有主窗口导航习惯。
4. 作为熟悉底部栏的用户，我希望 Skills 入口与任务视图相邻，从而把它理解为全局主内容页而不是应用配置。
5. 作为键盘用户，我希望 Skills 入口和页面操作具有完整键盘语义，从而无需鼠标完成管理。
6. 作为 VoiceOver 用户，我希望入口、状态、按钮和结果都有明确名称，从而不依赖图标或颜色理解界面。
7. 作为中英文环境用户，我希望 Skills 页面、安装流程和错误信息遵循应用语言，从而获得一致体验。
8. 作为使用系统深浅外观的用户，我希望 Skills 页面继承当前主题，从而不出现脱节的系统浅色弹窗。
9. 作为安装过 Codex Skills 的用户，我希望 Breath 扫描 Codex 的实际全局目录，从而看到已有内容。
10. 作为安装过 Claude Code Skills 的用户，我希望 Breath 扫描 Claude Code 的实际全局目录，从而看到已有内容。
11. 作为使用 Gemini CLI 的用户，我希望其全局 Skill 与其他 Agent 一起展示，从而统一管理。
12. 作为使用 GitHub Copilot CLI 的用户，我希望其全局 Skill 进入同一列表，从而无需记忆专属目录。
13. 作为使用 Qwen Code 的用户，我希望其全局 Skill 进入同一列表，从而获得相同管理能力。
14. 作为使用 Cursor Agent 的用户，我希望其全局 Skill 进入同一列表，从而获得相同管理能力。
15. 作为使用 Factory Droid 的用户，我希望其全局 Skill 进入同一列表，从而获得相同管理能力。
16. 作为使用 OpenCode 的用户，我希望 Breath 尊重实际配置根目录，从而不会扫描或写入错误位置。
17. 作为使用 Pi 的用户，我希望其全局 Skill 进入同一列表，从而获得相同管理能力。
18. 作为未来新增 Agent 的用户，我希望 Skills 能力随 Breath 支持矩阵同步增加，从而不会出现 Agent 已支持但 Skills 页面缺席。
19. 作为未安装某个 Agent 的用户，我希望它在目标选择器中标明“未安装”并禁止选择，从而不会创建无意义目录。
20. 作为使用自定义 Agent 配置目录的用户，我希望 Breath 展示并使用解析后的真实目录，从而不会静默写入默认位置。
21. 作为配置目录无法确认的用户，我希望该 Agent 被禁用并说明原因，从而避免 Breath 猜测路径。
22. 作为初次打开 Skills 页面的用户，我希望先立即看到本地扫描结果，从而不被网络请求阻塞。
23. 作为通过其他工具安装 Skill 的用户，我希望 Breath 仍能展示它，从而不形成只看得到 Breath 安装项的孤岛。
24. 作为手动复制过 Skill 的用户，我希望 Breath 根据实际文件识别它，从而不依赖专属安装记录。
25. 作为使用外部符号链接安装器的用户，我希望链接 Skill 正常展示，从而不丢失已有生态安装。
26. 作为在多个 Agent 安装相同内容的用户，我希望列表把它们聚合为一行并展示 Agent，从而减少重复信息。

117. 作为想完全移除某条 Skill 的用户，我希望可以选择全部安装目标，从而一次清理所有副本。
118. 作为卸载普通目录的用户，我希望内容移入 macOS 废纸篓，从而能够恢复误操作。
119. 作为卸载符号链接的用户，我希望只移除链接而不删除共享目标，从而不影响其他工具和 Agent。
120. 作为卸载部分失败的用户，我希望成功目标保持已移除并看到失败原因，从而可以单独重试。
121. 作为卸载 Skill 的用户，我希望原始 ZIP、GitHub Repo 和 skills.sh 条目不受影响，从而保持来源完整。
122. 作为卸载完成的用户，我希望对应来源记录被移除并立即刷新列表，从而看到真实最终状态。
123. 作为隐私敏感用户，我希望 Breath 不上传 Skill 内容、目录、Agent 列表或搜索历史，从而保持本地数据私密。
124. 作为不使用 Node.js 的用户，我希望仍能使用全部管理能力，从而不安装额外运行时。
125. 作为拒绝第三方 CLI 遥测的用户，我希望 Breath 不调用 `npx skills`，从而不触发其默认遥测。
126. 作为维护 Breath 的开发者，我希望 skills.sh 被隔离成可替换 Provider，从而在接口变化时只影响在线搜索。
127. 作为维护 Breath 的开发者，我希望 Skill 写操作按 Agent 目录串行，从而避免安装、更新和卸载相互覆盖。
128. 作为使用不同 Agent 的用户，我希望不同目标可以并行处理，从而不因无关目录互相等待。
129. 作为遇到错误的用户，我希望看到简短可操作原因并能复制清理后的详情，从而方便诊断且不泄露凭据。
130. 作为项目维护者，我希望新增受支持 Agent 时缺少 Skills 契约会让测试失败，从而防止支持矩阵漂移。

## Implementation Decisions

- Skills 是主窗口全局内容模式，不是设置页、应用配置、终端配置或工作区子页面；入口位于侧栏底部栏右侧并与任务视图同级。
- 选择工作会话会把详情模式切回会话终端；Skills 页面在没有工作区时仍可使用。
- 页面采用高密度原生“列表 + 详情”布局，顶部提供搜索、Agent/来源/状态筛选、刷新和安装入口；窄窗口使用独立详情页。
- 全局 Skill、候选 Skill、Skill 安装目标、Skill 来源、Skill 上游、Skill 安装记录、Skill 安装预览、Skill 安全审计、Skill 更新、本地修改 Skill、Skill 卸载、Skill 安装结果和无法识别的 Skill 项目使用项目词汇表中的定义。
- 新建独立 Skills 模块，拥有领域类型、Agent Skill 目录注册、扫描、来源解析、校验、内容摘要、安装、更新、卸载、对账和目录监听。
- App Shell 只负责导航、列表、详情、安装向导、预览和结果展示，不直接实现文件系统、网络或持久化规则。
- Persistence 模块增加 Skill 安装记录 schema migration 与 repository；记录保存来源分类，只有远程记录包含上游关联元数据，不保存 Skill 文件内容。
- Agent 描述符增加全局 Skill 能力与目录解析契约。新增受支持 Agent 时必须同时提供该契约和完整测试，避免维护第二份 Agent 名单。
- 当前受支持的 Codex、Claude Code、Gemini CLI、GitHub Copilot CLI、Qwen Code、Cursor Agent、Factory Droid、OpenCode 和 Pi 都进入 Skill 支持矩阵。
- Skill 安装目标必须是受支持、已安装、版本兼容且能可靠解析实际全局 Skill 目录的 Agent；未满足条件的目标显示但禁用。
- 目录解析尊重 Agent 的有效配置根覆盖。无法确认时禁止写入，不能回退猜测默认目录。
- 本地扫描以 Agent 目录的实际文件为事实来源，数据库不能制造磁盘上不存在的已安装项。
- 扫描支持普通目录和外部符号链接，并防止链接循环、不可读越界和失控目录遍历。
- 解析器读取 `SKILL.md` 的必要和可选 frontmatter；缺少 `SKILL.md`、`name` 或 `description` 是不可安装错误，非致命规范偏差是可继续警告。
- 无法解析的现有目录进入单独诊断区域，不计入正常 Skill，也不由首版 UI 直接删除。
- 列表使用 `name + 规范化内容摘要` 聚合内容一致的跨 Agent 副本；摘要忽略文件系统噪声，但覆盖会影响 Skill 行为的全部真实文件。
- 名称相同但内容不同的 Skill 分开显示，不增加“同名冲突”标签；同一个 Agent 内只能安装一个给定 `name`。
- 同 Agent 已有同名同内容时安装为 no-op；同名不同内容时进入覆盖/跳过选择，默认跳过，不自动改名。
- “安装 Skill…”是统一分步流程：选择 ZIP 或在线来源、解析候选、多选 Skill、选择 Skill 安装目标、内容预览、确认、逐目标结果。
- 每次安装目标默认全部不选，不自动全选，也不记忆上一次选择。
- ZIP 使用原生选择器和受控临时目录；实现压缩包大小、解压总量、文件数、目录深度和候选数上限，并拒绝路径越界、危险链接、设备文件和其他特殊文件。
- ZIP、Repo 和目录扫描优先识别标准 Skill 位置；没有结果时只做排除版本控制、依赖和构建产物的有界递归扫描。
- GitHub 首版只支持无需认证的公开来源，接受 Repo、简写、分支、Tag、Commit 和 Skill 子目录定位；不搜索整个 GitHub，不读取登录、Token 或 Git 凭据。
- 普通 Repo 跟随默认分支，分支定位跟随指定分支，Tag 与 Commit 是固定版本；安装记录保存解析后的实际 Commit 和 Skill 相对位置。
- skills.sh 搜索封装为可替换 Provider。搜索失败只影响在线发现，不能阻塞本地列表、ZIP、指定 GitHub 来源、更新记录或卸载。
- skills.sh 搜索结果至少包含名称、说明、来源和安装量；安全审计有结果时展示风险与检查时间，未知不能显示为安全。
- 高风险和严重风险候选需要额外确认，但不永久硬拦截；任何审计结果都不能跳过实际文件和 `SKILL.md` 预览。
- 所有来源共享强制 Skill 安装预览，展示来源、引用、说明、文件、兼容性、许可证、工具声明、Skill 安装目标、真实目录和覆盖影响。
- 解析、预览和安装绝不执行来源脚本、Hook、构建命令或其他代码；脚本作为 Skill 文件保留供 Agent 后续按正常权限使用。
- Breath 使用 Swift 原生实现，不调用 `npx skills`，不要求 Node.js，不引入 Breath 后端、账户或遥测。
- Breath 自己安装的每个 Agent 副本都是对应 Agent 目录中的完整实体目录；不在 Breath 应用数据中保存规范 Skill 副本，不创建分发符号链接。
- Breath 不向 Skill 目录写入私有 sidecar、扩展属性或其他来源之外文件。
- 每个“候选 Skill × Skill 安装目标”是独立操作与结果单元。不同单元允许部分成功，失败项不回滚其他成功项。
- 单个操作单元在目标文件系统暂存完整目录，覆盖时建立临时回滚副本，再以原子替换提交；成功后清理临时副本，失败时恢复旧内容。
- 写入前重新检查目录、同名占用和内容摘要，避免基于过期预览覆盖外部变化。
- 每个 Agent 全局目录内的写操作串行化；不同 Agent 目录可以并行。
- Skill 安装记录至少保存 Agent、安装路径、名称、来源类型和标识、Repo、来源相对位置、跟随或固定引用、安装 Commit、安装时内容摘要和时间信息。
- 安装记录位于 Breath SQLite；删除记录或数据库不会删除实际 Skill，只会使上游与更新能力不可确认。
- 对账时，路径与 Skill 身份一致但内容变化标记为本地修改并保留上游；路径被其他 Skill 占用或身份无法确认时降级为来源未知。
- Breath 可以只读利用能安全匹配的生态兼容清单，但不修改其他工具清单，也不按名称猜测上游。
- 只有具有可验证 GitHub 或 skills.sh 上游的 Skill 提供更新；ZIP、固定 Tag/Commit 和来源未知 Skill 不检查更新。
- 更新检查只在打开 Skills 页面或手动刷新时发生；先展示本地状态，再异步查询并使用会话缓存。未打开页面时不后台联网。
- 只有 Skill 目录内容变化才形成可用更新，Repo 无关提交不产生更新提示。
- 首版逐个 Skill 更新，不提供更新全部。不同上游分别更新，不能混在一次操作中。
- 同一上游、存在更新且未本地修改的 Agent 副本默认选中；本地修改副本默认不选，必须主动选择。
- 更新复用安装预览，展示旧、新 Commit、文件变化、说明变化和将被覆盖的本地修改；失败目标保留旧版本。
- 外部符号链接正常扫描且不自动迁移。卸载只移除所选链接；显式更新时将所选 Agent 链接替换为独立新版目录，不修改共享目标或其他链接。
- 卸载允许选择一个、多个或全部 Agent 副本。普通目录移入 macOS 废纸篓，符号链接只移除链接，不删除来源与未选择副本。
- 安装、更新和卸载都按 Agent 独立报告成功和失败；成功卸载后移除相应安装记录并刷新实际列表。
- Skills 操作不重启 Agent、不停止终端、不改变工作会话，也不向现有 Agent 对话注入内容；结果提示可能需要新会话后生效。
- 错误默认展示简短可操作原因，并可复制经过清理的详情；不得包含进程环境变量、凭据、敏感 URL 查询参数或无关本地路径。
- 网络请求只发送完成 GitHub 解析或 skills.sh 查询所需信息，不上传 Skill 内容、安装目录、Agent 列表或搜索历史。
- 实现遵守 ADR 0032 的原生无 Node/无后端边界、ADR 0033 的直接 Agent 目录副本边界、ADR 0034 的非侵入式 SQLite 来源记录边界，以及 ADR 0035 的来源分类与远程上游分离边界。

## Testing Decisions

- 主要测试 Seam 是公开的全局 Skills 用例服务。测试通过扫描、解析来源、安装、检查更新、更新、卸载和对账等公开用例驱动完整行为，并观察最终目录、聚合快照、安装记录与逐目标结果，而不是断言私有辅助方法。
- 主要测试使用临时真实用户根目录和真实文件树，配合可注入的 Agent 支持矩阵、GitHub/skills.sh Provider、时钟、文件监听和安装记录 repository。这样可以从一个最高可行接缝覆盖大多数业务编排与真实文件系统行为。
- ZIP 测试使用真实压缩包，覆盖单 Skill、多 Skill、标准目录、递归回退、资源上限、绝对路径、`..` 越界、链接逃逸、特殊文件、损坏压缩包和部分有效候选。
- GitHub 来源测试使用记录型或本地协议 Provider，覆盖 Repo、简写、子目录、默认分支、指定分支、Tag、Commit、404、私有来源拒绝、限流和网络失败；测试关注解析结果与用户错误，不绑定具体 HTTP 请求实现。
- skills.sh Provider 测试覆盖关键词搜索、说明与安装量映射、安全审计安全/未知/高风险状态、结果选择、不可用、超时和接口错误隔离。
- Skill 解析测试覆盖最小合法 frontmatter、可选字段、YAML 错误、缺少必要字段、名称格式警告、目录名偏差、资源文件和未执行脚本 sentinel。
- 扫描测试覆盖当前九个 Agent、未安装 Agent、无法解析目录、自定义配置根、普通目录、外部符号链接、断链、循环链接、权限错误和无法识别项目。
- 聚合测试覆盖同名同内容跨 Agent 合并、同名不同内容分行、同内容不同来源、文件系统噪声忽略和真实资源变化触发不同摘要。
- 目录监听测试覆盖外部创建、修改、删除和快速连续变化，验证节流后刷新真实快照；应用重新激活和手动刷新执行完整对账。
- 安装向导的服务状态测试覆盖返回上一步保留选择、取消零写入、候选多选、默认无 Agent、禁用目标和至少一个目标约束。
- 安装预览测试覆盖来源、引用、说明、文件、目标路径、格式警告、兼容性、许可证、工具声明、审计和现有同名内容。
- 同名行为测试覆盖同名同内容 no-op、同名不同内容默认跳过、显式覆盖、不同 Agent 独立选择和写入前外部变化导致重新确认或安全失败。
- 安全测试在候选脚本、Hook 和构建文件中放置 sentinel，验证扫描、预览和安装均不执行内容。
- 直接副本测试验证每个目标得到完整实体目录，Breath 不创建中心内容副本、不创建分发链接、不写入 sidecar 或扩展元数据。
- 单目标原子性测试在暂存、覆盖、数据库写入和提交阶段注入失败，验证旧目录恢复、新目录不残缺且返回清晰失败。
- 批量结果测试同时提供可写、无权限、磁盘失败和外部竞态目标，验证成功项保留、失败项单独报告且不发生跨目标回滚。
- 并发测试验证同一 Agent 目录的安装、更新、卸载串行，不同 Agent 可以并行，文件监听不会与写操作制造重复或陈旧状态。
- 安装记录测试验证 SQLite round trip、schema migration、删除数据库不影响实际 Skill、记录存在但目录缺失、内容本地修改、路径被其他 Skill 占用和来源未知降级。
- 兼容清单测试验证只读匹配、错误名称不建立上游、内容或路径无法验证时不关联，以及 Breath 不修改外部清单。
- 更新检查测试覆盖只在页面打开/手动刷新时请求、先发布本地快照、会话缓存、离线保留列表、默认分支、指定分支、固定 Tag/Commit 和 Repo 无关提交。
- 更新选择测试覆盖未修改目标默认选择、本地修改目标默认不选、不同上游分开、无更新、来源未知和不提供更新全部。
- 更新写入测试覆盖完整预览、覆盖本地修改确认、成功替换、单目标失败保留旧版本和多 Agent 部分成功。
- 外部符号链接测试覆盖列表展示、卸载只移除链接、共享目标保持不变、显式更新将选中链接转为实体副本且不影响其他链接。
- 卸载测试覆盖选择单个/多个/全部 Agent、普通目录进入废纸篓、链接只解除、来源保持、部分失败和安装记录刷新。
- 运行时边界测试验证安装、更新和卸载不会调用终端停止、Agent 重启、工作会话修改或 Agent 对话注入，并返回生效提示。
- 隐私与错误测试验证不发送 Skill 内容、目录或 Agent 列表，不触发 CLI 遥测；错误详情排除环境变量、凭据和敏感 URL 信息。
- App Shell 测试覆盖底部栏入口、无工作区可达、选择工作会话返回、列表/详情窄宽布局、筛选、安装向导、预览、部分结果、诊断区域和安静空状态。
- 可访问性测试覆盖入口选中态、列表行说明、Agent 与来源状态、禁用原因、警告、高风险确认、更新、卸载、结果和焦点顺序，确保状态不只依赖颜色。
- 本地化测试覆盖新增中英文键集合完整、参数化错误、复数/数量、Agent 名称和来源名称不被错误翻译。
- Agent 支持矩阵契约测试遍历每个受支持 Agent，要求安装检测、真实 Skill 目录解析、扫描、安装、更新、卸载和生效提示齐全；新增 Agent 缺少任何一项即失败。
- 现有 Git 工作台服务测试提供“高层服务 + 临时真实目录 + 可注入依赖 + 外部行为断言”的主要先例；现有 SQLite repository round-trip 测试提供 migration 与重启先例；现有 App Shell 布局和可访问性测试提供入口、导航和语义先例。
- 除纯 ZIP/YAML/路径解析和内容摘要算法外，不直接测试私有 helper、具体 Swift 类型布局、网络请求拼接或文件操作调用顺序。
- 人工验收至少覆盖九个真实 Agent、一个自定义配置根、Finder 外部编辑、`npx skills` 产生的链接、真实 skills.sh 搜索、公开 GitHub 多 Skill Repo、大型 ZIP、VoiceOver、键盘导航、离线模式和 macOS 废纸篓恢复。

## Out of Scope

- 项目 Skill、工作区 Skill 或把 Skill 提交到项目仓库。
- 私有 GitHub Repo、GitHub OAuth、Personal Access Token、SSH 凭据或 Git credential helper 集成。
- 搜索整个 GitHub 或建立 Breath 自有 Skill 索引。
- Skill 创建、编辑、复制、导出、发布、评分或评论。
- 在 Breath 内运行、试运行或调试 Skill 脚本。
- 自动改写 Skill 的 `name`、`description` 或目录名以解决冲突。
- 同一个 Agent 内同时保留两个同名 Skill；后安装项只能覆盖或跳过。
- 一键更新全部、后台自动更新、定时轮询更新或未打开 Skills 页面时联网。
- 为 ZIP 或来源未知 Skill 猜测上游。
- 自动合并远程更新与本地修改。
- 长期保存被替换 Skill 的历史版本或提供 Breath 内置版本回滚；卸载恢复依赖 macOS 废纸篓。
- Breath 中心 Skill 仓库、跨设备同步、账户、服务端、云备份或遥测。
- 向 Skill 目录写入 Breath sidecar、扩展属性或其他私有元数据。
- 将 Breath 自己安装的 Skill 作为符号链接分发。
- 自动迁移现有外部符号链接；只有用户显式更新所选 Agent 时才转换。
- 自动重启 Agent、终端或应用，热加载 Skill，或保证当前 Agent 对话立即感知变化。
- 改变 Agent 集成、Agent 适配器生命周期事件、工作会话、终端状态、Git 工作台或应用更新行为。
- 让未安装、版本不兼容或全局目录无法确认的 Agent 成为安装目标。

- Agent Skills 格式以开放 Agent Skills 规范为基线；对必要字段严格，对现实生态中的非致命命名偏差宽容并显示警告。
- skills.sh 审计是辅助风险信号而不是安全认证。任何来源都必须经过本地内容预览，未知状态不能显示为安全。
- skills.sh Provider 是易变的外部集成边界。若未来官方访问方式必须依赖服务端或账户，需要新的产品、架构和隐私决策，不能在本功能中隐式引入。

- 本 PRD 已完整综合已确认设计，可直接交给 Agent 拆分或实现；本次发布不包含功能实现。
