# 检查并安装单个 Skill 更新

Status: implemented

## Parent

[Breath 全局 Skills 管理](../spec.md)

## What to build

为具有可验证 GitHub 或 skills.sh 上游的 Skill 提供按页触发的更新检查和逐 Skill 更新流程。用户先看到本地列表，再异步获知内容变化；每次更新都审阅具体差异和目标副本，不提供后台轮询或一键全部更新。

本切片覆盖 PRD User Stories 32、101–115、127、129。

## Acceptance criteria

- [x] 打开 Skills 页面时先发布本地扫描结果，再异步检查具有可验证上游的 Skill；未打开页面时不执行后台更新请求
- [x] 手动刷新可以重新查询远程状态，同一页面会话使用缓存；离线或远程失败保留本地列表并展示可重试状态
- [x] 默认分支和指定分支按照记录的跟随引用检查，固定 Tag、固定 Commit、ZIP 和来源未知 Skill 明确不提供更新
- [x] 只有目标 Skill 目录内容摘要变化才显示更新，Repo 其他路径的提交不会产生更新提示
- [x] 列表和筛选可以区分有更新、本地已修改、已是最新、固定版本和来源未知状态
- [x] 更新入口按单个 Skill 工作，不提供“更新全部”；同一聚合行包含不同上游时必须分开处理
- [x] 更新预览展示旧、新 Commit、`description` 和文件变化，以及每个 Agent 副本的本地修改和符号链接影响
- [x] 同一上游且未本地修改的过期副本默认选中，本地已修改副本默认不选；用户必须主动选择并确认覆盖本地修改
- [x] 更新复用每 Agent 串行、跨 Agent 可并行的原子安装机制；单目标失败保留旧版本，其他成功目标不回滚
- [x] 更新外部符号链接前明确提示所选 Agent 将变成实体目录；提交后只替换所选链接，不修改共享目标或其他 Agent 链接
- [x] 更新结果立即重新扫描真实目录和来源记录，并分别显示成功、跳过和失败目标及经过清理的错误详情
- [x] 测试覆盖页面触发边界、会话缓存、离线、默认/指定分支、固定引用、无关提交、本地修改选择、不同上游、原子失败、部分成功和符号链接脱离
