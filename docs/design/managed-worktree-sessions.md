# 分支型托管工作树会话设计

状态：首版已实现
日期：2026-07-23

## 1. 目标

Breath 允许多个 Agent 在同一 Git 仓库的独立分支检出中并行工作，同时保持现有“工作区 → 工作会话 → 终端窗格”结构。设计采用 Orca 的分支优先工作方式，并保留 Breath 的会话所有权、固定托管路径、持久化恢复和安全删除边界。工作树属于工作会话，不属于 Agent 或单个终端窗格；同一工作会话的全部窗格始终共享一个会话工作目录。

## 2. 会话类型与创建入口

- 普通“新建工作会话”、侧栏 `+` 和 `⌘T` 始终创建本地会话，工作目录是工作区本地检出。
- 只有工作区 `…` 菜单提供“新建 Worktree 会话…”；首版不提供独立快捷键。
- 创建弹窗使用带搜索的选择器列出本地分支和已有远程跟踪分支，不允许用户通过自由输入指定分支。
- 选择器默认选中工作区当前分支；用户可以搜索并选择其他本地分支或远程跟踪分支作为起始分支。
- 起始分支只确定新工作树的基线提交。Breath 为每个工作树会话自动创建 `breath/<work-session-id>` 会话分支，并在新 Worktree 中检出该分支。
- 任务视图接入后，Task 可以提供明确的任务分支，但仍不能让两个 Worktree 同时检出同一个本地分支。
- 创建期间，工作区下显示不可选择的“正在创建 Worktree…”临时行，并禁用该工作区的新建 Worktree 操作。
- 创建成功后生成实际会话并自动选中；失败时保留创建弹窗并显示错误。
- 创建流程不提供取消操作。

## 3. 仓库发现与支持边界

Breath 使用固定的 `/usr/bin/git`。创建时验证以下条件：

- 工作区目录自身位于一个具有有效提交、且 `HEAD` 正附着于分支的非 bare Git 仓库内；detached HEAD 不受支持。
- 仓库没有启用 sparse checkout。
- 工作区可以是仓库根目录、仓库内的子目录，或另一个有效 linked worktree 中的目录。
- 工作区若只是包含若干内部仓库、但自身不属于任何 Git 仓库，则不提供工作树会话；用户应分别添加内部仓库。

Breath 保存 Git common directory 作为恢复和删除依据。首版在 Git 服务层通过显式操作闸门串行执行全部工作树创建、验证和删除操作；后续可以按 common directory 拆分闸门以提高不同仓库的并行度，但同一仓库的写操作必须始终串行。

首版不显示、导入或清理用户通过命令行、JetBrains 等其他工具创建的外部 worktree。外部 worktree 可以作为普通工作区单独添加。

## 4. 起始分支、会话分支与检出安全

创建弹窗只提交完全限定的 `refs/heads/*` 或 `refs/remotes/*` 起始引用。Breath 在创建开始时把所选引用解析为完整 commit hash，使用 `git check-ref-format --branch` 校验自动生成的会话分支，再以“引用必须不存在”为前置条件创建无 upstream 的本地会话分支：

```text
git update-ref refs/heads/breath/<work-session-id> <captured-commit> <zero-oid>
git worktree add <managed-path> breath/<work-session-id>
```

- 被选中的起始分支即使已经由原工作区或另一个 Worktree 检出，也不影响创建，因为新 Worktree 检出的是独立会话分支。
- 会话分支的引用创建使用 compare-and-swap；若另一个 Git 进程抢先创建同名分支，本次操作失败且绝不删除对方分支。
- 工作树从创建起就绑定会话分支，Agent 提交会持续推进该分支，不使用 detached HEAD。
- 首版创建弹窗不提供“复用已有本地分支”。未来若提供，必须先确认该分支没有被任何其他 Worktree 检出，并在删除时保留该分支。
- staged、unstaged、untracked 和 ignored 内容都不复制到工作树。
- 原检出的 staged、unstaged、untracked 和 ignored 内容不会进入新 Worktree；创建弹窗明确提示这一点。
- `git worktree add` 返回后再次解析新工作树的 `HEAD`；若它不再等于捕获的 commit，创建失败并进入补偿清理，不接受外部 Git 进程移动后的引用。
- 如果捕获的 commit 在执行时已不可访问，创建失败，不改用新的 `HEAD`。

创建不得隐式执行仓库代码或网络操作：

- 使用一次性的 Breath 空 hooks 目录覆盖 `core.hooksPath`，禁用本次 checkout hooks。
- 临时禁用所有自定义 checkout smudge/process filters；Git LFS 文件保持指针状态。
- 必需的 checkout filter 无法安全禁用时，创建失败，不回退执行该 filter。
- 不初始化 submodule。
- 不复制 `.env`、依赖目录或其他 ignored 文件，不支持 `.worktreeinclude`。
- 不修改仓库、全局或系统 Git config，包括不启用 `extensions.worktreeConfig`。

## 5. 托管路径

托管工作树统一位于：

```text
~/Library/Application Support/Breath/worktrees/<workspace-id>/<work-session-id>/
```

如果工作区是仓库子目录，例如 `/repo/apps/frontend`，Breath 为整个仓库创建工作树，但会话终端从新工作树内的 `apps/frontend` 启动。

`worktrees/` 根目录标记为不进入 Time Machine 和 iCloud 风格的系统备份。Breath 不自动清理仍绑定活跃或已归档会话的工作树，也不设置“最近 N 个”上限。

## 6. 分阶段创建与补偿清理

Worktree 创建和清理跨越 Git 引用、Git Worktree 元数据、文件系统、终端进程和 Breath 持久层，不构成原子事务。Breath 使用“保持不可见直到完成”的分阶段发布，并在失败时执行补偿操作。工作树会话只有在以下步骤全部成功后才对用户可见：

1. 验证仓库与捕获创建基线。
2. 创建并验证托管工作树。
3. 启动第一个终端，此时会话仍未持久化或公开。
4. 在会话仍不可见时持久化完整快照，成功后再一次性发布工作会话及工作树元数据。

任一步失败都先停止已经部分启动的终端，再尝试补偿清理尚未发布的工作树。若持久化冲突期间已写入过尚未发布的候选快照，后续保存失败时先把持久层补偿为当前已发布快照，再清理 Worktree；若持久化补偿也失败，则同时报告两个错误并保留 Worktree，避免持久层中的 Session 指向已删除目录。其他补偿失败也必须同时报告工作树路径、原始失败原因和清理失败原因，不能把整个流程描述成已经回滚的事务。`git worktree add` 可能在返回失败前留下工作树或 Git 元数据；此时允许在精确校验受管路径后，对这个从未发布的创建中间态执行强制清理。若失败操作新建了会话分支，仅在分支仍指向捕获基线时删除该分支。正常会话删除不使用强制清理，并始终保留会话分支。

启动时仍只验证已持久化 Worktree，不自动清理或重试。设置中的 Worktree 库存按需扫描 Breath 托管根目录，显示没有会话记录的孤儿目录；扫描只读，不写入仓库索引，也不把发现结果自动转成删除操作。

## 7. 持久化模型

每个工作会话保存其会话目录类型：

- `local`：目录由工作区本地检出派生。
- `managedWorktree`：目录由工作树元数据派生。

托管工作树只保存运行所需元数据：

- 工作树绝对路径。
- 规范化 Git common directory 或稳定仓库标识。
- 创建基线 commit hash。
- 工作区相对仓库根目录的路径。
- 会话分支名。
- 会话分支是否由本次创建操作新建，用于发布前失败时的精确补偿清理。
- 所属工作区 ID 与工作会话 ID。
- 可用或不可用生命周期状态。

不保存 diff、文件名列表、提交消息或终端内容。修改数量、提交风险和磁盘占用按需实时计算。

升级前缺少这些字段的工作会话全部迁移为本地会话，继续使用原工作区目录，不创建工作树，也不改变恢复行为。

## 8. 运行与恢复

- 本地会话依赖原始工作区目录。
- 工作树会话依赖托管工作树自身仍是有效且已登记的 Git worktree，不简单继承原始工作区的目录状态。
- 同一工作树会话的创建、分屏、冷启动恢复和 Agent 恢复都从同一个会话工作目录启动。
- 用户可以在终端中切换分支；Breath 尊重实际 Git 状态，但会话标识仍显示创建时生成的会话分支。
- 工作树目录缺失、Git 元数据损坏或已不在 `git worktree list --porcelain` 中时，标记为“工作树不可用”，不自动重建、repair 或重新注册。
- 工作树不可用时不启动或恢复新终端，也禁止新分屏。
- 如果终端已在运行后工作树才变得不可用，Breath 不自动终止进程；下一次分屏、恢复等需要校验会话目录的操作会将其标记为不可用并显示橙色警告，现有终端可以继续，退出、归档或进程结束后不再恢复。
- 原始工作区目录移动或不可用时，只要托管工作树自身仍然有效，已存在的工作树会话仍可运行；需要共享 Git 元数据的操作按实际可执行性开放。

正常退出等待所有正在进行的工作树操作完成，并在等待期间禁止启动新操作。系统强制退出不作保证。

## 9. 状态刷新与界面

- 工作树会话标题前显示 `arrow.triangle.branch`；悬停显示会话分支；不可用时显示橙色警告图标。
- 会话仍使用 `新会话 · HH:mm` 占位标题，之后可由第一个 Agent 原生标题替换。
- 悬停提示工作树路径和创建基线短 hash。
- 左侧活动栏的 Git 入口默认使用当前选中会话的会话工作目录；没有选中会话时仍可打开 Git 页面，目录选择器显示“请选择”。
- Git 工作台、Finder 和标签栏右侧编辑器入口都使用会话工作目录，而不是固定使用工作区路径。
- 设置提供独立的 Worktree 库存页，按仓库列出 Breath 会话分支和托管目录，并明确区分会话使用中、工作树不可用、仅剩分支、目录残留和未关联会话。
- 库存扫描同时使用当前工作区、已知工作树元数据和托管根目录；部分仓库读取失败时保留其他扫描结果，并在列表内显示失败原因，不能把失败伪装成空库存。
- Breath 在用户明确创建 Worktree 时，于托管根目录保存只包含 Git common directory、仓库显示路径和名称的本地仓库索引；移除 Git 工作区前也会补录索引，以覆盖升级前已存在的 Worktree 和分支。这样工作区移除后仍能发现保留的 `breath/<work-session-id>` 分支。打开库存页和刷新库存不会写入索引；索引不保存凭证、Diff 或提交内容。
- 原工作区路径不可用时，移除前补录从该工作区已知 Worktree 的 Git common directory 恢复仓库索引。索引路径或内容不可安全读取、托管根被替换为符号链接、或索引无法持久化时，中止 Git 工作区移除并显示错误；这是防止保留分支失去可见性的事务前置条件。非 Git 工作区不需要索引。
- 只有严格匹配自动生成格式 `breath/<UUID>` 的本地分支才作为无目录的 Breath 会话分支列出；位于 Breath 托管根目录内的实际检出则无论当前分支名如何都可见。
- 库存行的右键菜单提供显式清理：只有“仅剩分支”可以删除分支；操作前重新确认该分支没有被任何 Worktree 检出，并通过带旧值的 `update-ref -d` 原子删除。分支删除需要二次确认，不提供自动批量清理。
- “未关联会话”的 Git Worktree 目录只有在所有权、仓库身份、Git 登记、锁、未提交修改和提交保护检查全部通过后，才通过普通 `git worktree remove` 删除并保留分支。“目录残留”在确认它不再是有效 Git Worktree 后移入 macOS 废纸篓。会话使用中或工作树不可用的项目不提供库存清理操作。

工作会话行统一使用 `…` 菜单：

- 所有会话：归档。
- 可用工作树会话：在 Finder 中显示、复制路径。
- 不可用工作树：显示路径、复制路径、归档。

## 10. 会话分支生命周期

- 托管工作树与会话分支从创建开始就是同一份持续演进的代码成果，不需要“导出为分支”。
- 归档工作会话保留工作树和会话分支。
- 永久删除工作树会话只删除 linked worktree 和 Breath 元数据，不删除会话分支。
- Breath 不推断合并目标，也不自动合并。用户自行决定是否以及何时通过 Git 工作台、命令行或远程 PR 合并会话分支。
- 首版不实现 Local/Worktree Handoff。

## 11. 归档

- 归档停止终端并保留托管工作树、布局和 Agent 恢复信息。
- 归档不需要二次确认；即使 Agent 回合运行中或存在其他前台进程，也会直接停止相关进程。
- 归档不要求 Git clean，也不执行代码风险扫描。
- 恢复后仍使用原来的托管工作树。

## 12. 删除安全

永久删除本地会话仍只删除 Breath 元数据。永久删除工作树会话会删除托管 Worktree 和 Breath 元数据，但保留会话分支。

首版采取保守删除策略，不提供 Force：

- `git status --porcelain` 非空时拒绝删除，包括 staged、unstaged 和 untracked 内容。
- 当前 `HEAD` 不被任何本地分支或标签保护时拒绝删除。
- Worktree 被 `git worktree lock` 锁定时拒绝删除并显示锁定原因。
- 所属 ID、托管路径、Git common directory 或 Git 状态无法验证时拒绝删除。
- 目录已不存在时只允许清理 Breath 工作会话记录；因为无法从 Worktree 自身验证仓库身份，不再使用持久化的 Git common directory 清理 Git 元数据。

通过检查后由 Git 执行普通 `worktree remove`。提交仍保留在会话分支上；Breath 不使用 `--force`，也不自动解锁。

## 13. 移除工作区

移除工作区先验证其全部工作树会话。任一 Worktree 不满足保守删除条件时，整个操作中止。原始工作区目录始终不修改。

执行顺序：

1. 完成全部 Worktree 的安全检查和用户确认。
2. 停止该工作区全部终端。
3. 逐个删除托管工作树；每次删除都会再次执行安全检查，任一失败即停止。
4. 全部工作树删除成功后，删除 Breath 工作会话和工作区元数据。

中途失败时，已经删除的工作树对应会话标记为不可用，其余记录保留以便重试；不重新创建已经删除的工作树。

多个 Breath 工作区即使属于同一 Git common directory，也只清理各自拥有的托管工作树。

## 14. 路径和清理安全

Breath 只递归删除能够证明属于自己的路径：

- 规范化后仍位于 Breath `worktrees/` 根目录内。
- workspace ID 与 work-session ID 路径组件和持久化数据一致。
- 托管根目录先解析为规范路径，workspace/session 两级目标不能是符号链接。
- 会话工作目录从 Worktree 根逐级解析；工作区相对路径中的任一组件是符号链接，或最终路径逃出 Worktree 根时，拒绝启动终端或 Agent。
- 删除前从 Worktree 根重新解析 Git common directory，并要求它与持久化记录指向同一真实目录。
- 不把数据库中的任意绝对路径直接作为递归删除目标。

正常删除通过 Git 移除 linked worktree，再只清理已经为空的 workspace/session 托管目录，不对任意残留目录执行递归强删。只有从未发布的创建中间态允许在精确校验路径后递归清理对应 Session 目录。

普通状态刷新和删除都不自动执行全局 `git worktree prune`。

Git lock、gc、repack 或其他外部冲突发生时，Breath 不删除锁文件，不强制写入，也不自动重试写操作；保留状态并提示稍后重试。只读检查可以短暂重试一次。

## 15. Git 错误诊断

- 默认显示经过清理的简短原因和退出码。
- “显示详细信息/复制详细信息”可以包含完整 Git stderr 和命令参数，但不包含进程环境变量。
- 远端 URL 中可能存在的用户名、密码和 token 在展示前遮蔽。
- 错误详情不持久化到数据库，也不上传。

## 16. 非目标

首版不包含：

- 本地检出与工作树之间的自动 Handoff。
- 复制本地检出的未提交修改。
- `.worktreeinclude` 或 ignored 文件复制。
- submodule 自动初始化。
- Git LFS 或自定义 checkout filter 自动执行。
- sparse checkout、bare repository、unborn 或 detached `HEAD` 支持。
- 外部 worktree 导入、展示或清理。
- 自定义 Git 可执行文件。
- 自动清理仍绑定工作会话的托管工作树。
- 自动合并会话分支或自动删除会话分支。
- 自动清理孤儿目录、持久化待清理状态和失败重试操作。
- 对脏 Worktree 的强制删除与高风险输入确认。
- 创建前的本地修改数量统计和仓库资格预检。

## 17. 验收标准

1. 普通新建和 `⌘T` 继续创建本地会话；只有工作区菜单可以明确创建工作树会话。
2. 工作区根目录、仓库子目录和 linked worktree 中的目录都能列出本地与远程跟踪分支；创建弹窗默认选择当前分支，并支持搜索选择其他起始分支。非 Git、unborn、detached、bare 和 sparse 仓库在加载或创建时给出明确错误。
3. 每个用户创建的 Worktree 会话都严格从所选起始分支解析出的 commit hash 创建独立 `breath/<work-session-id>` 会话分支；即使起始分支已被其他 Worktree 检出也能创建。新 Worktree 不包含本地未提交或 ignored 文件，不执行 hooks、filters、LFS 下载或 submodule 初始化。
4. 同一工作树会话的全部窗格、Git 工作台、Finder、编辑器和 Agent 恢复都使用会话工作目录。
5. 创建工作树、启动终端或持久化失败时，不会持久化或暴露半成品会话；清理失败会明确报告，不会静默遗留。
6. 归档保留工作树；恢复继续使用原目录。
7. Worktree 中的提交持续推进会话分支；删除 Worktree 后会话分支仍然存在。
8. 删除会拒绝未提交修改、未受本地引用保护的提交、锁定和不可验证状态。
9. 移除工作区只有在所有托管工作树删除成功后才删除元数据。
10. 路径校验、符号链接、外部锁和 Git 锁冲突不会导致越界删除或强制修改仓库。
11. 旧数据库中的工作会话全部兼容迁移为本地会话。
12. Breath 重启可以识别已持久化 Worktree 的有效和不可用状态，并且不处理外部 worktree。

## 18. 后续阶段

- 为库存中的残留项设计经过所有权复核的删除、待清理记录和失败重试流程。
- 在创建弹窗打开前异步预检仓库资格，并显示原检出的修改数量。
- 如果确有需求，再单独设计可审计的高风险 Force 删除流程；首版不会为了方便而越过 Git 和数据保护边界。
