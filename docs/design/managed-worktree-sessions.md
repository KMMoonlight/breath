# 托管工作树会话设计

状态：待最终确认  
日期：2026-07-16

## 1. 目标

Breath 允许多个 Agent 在同一 Git 仓库的独立检出中并行工作，同时保持现有“工作区 → 工作会话 → 终端窗格”结构。工作树属于工作会话，不属于 Agent 或单个终端窗格；同一工作会话的全部窗格始终共享一个会话工作目录。

## 2. 会话类型与创建入口

- 普通“新建工作会话”、侧栏 `+` 和 `⌘T` 始终创建本地会话，工作目录是工作区本地检出。
- 只有工作区 `…` 菜单提供“新建工作树会话”；首版不提供独立快捷键。
- 创建期间，工作区下显示不可选择的“正在创建工作树…”临时行；同仓库的工作树写操作期间禁用新的工作树操作。
- 创建成功后，临时行原地成为实际会话并自动选中；失败时移除临时行并显示可复制的错误详情。
- 创建流程不提供取消操作。

## 3. 仓库发现与支持边界

Breath 使用固定的 `/usr/bin/git`，要求 Git 2.20 或以上。工作树入口仅在以下条件全部成立时可用：

- 工作区目录自身位于一个具有有效 `HEAD` 的非 bare Git 仓库内。
- 仓库没有启用 sparse checkout。
- 工作区可以是仓库根目录、仓库内的子目录，或另一个有效 linked worktree 中的目录。
- 工作区若只是包含若干内部仓库、但自身不属于任何 Git 仓库，则不提供工作树会话；用户应分别添加内部仓库。

Breath 通过 Git common directory 识别共享仓库。同一仓库内不同子目录可以分别成为 Breath 工作区，但其工作树创建、删除和导出操作串行执行；不同仓库可以并行。

首版不显示、导入或清理用户通过命令行、JetBrains 等其他工具创建的外部 worktree。外部 worktree 可以作为普通工作区单独添加。

## 4. 创建基线与检出安全

创建开始时，Breath 捕获工作区当前 `HEAD` 的完整 commit hash，并始终以该 hash 创建工作树：

```text
git worktree add --detach <managed-path> <captured-commit>
```

- 工作树初始处于 detached HEAD。
- 不提供分支选择器。
- staged、unstaged、untracked 和 ignored 内容都不复制到工作树。
- 本地检出存在未提交修改时，创建前显示 staged、unstaged、untracked 数量及去重后的受影响文件合计；不显示文件名或 diff，也不提供永久忽略提示。
- 如果捕获的 commit 在执行时已不可访问，创建失败，不改用新的 `HEAD`。

创建不得隐式执行仓库代码或网络操作：

- 使用一次性的 Breath 空 hooks 目录覆盖 `core.hooksPath`，禁用本次 checkout hooks。
- 临时禁用所有自定义 checkout smudge/process filters；Git LFS 文件保持指针状态。
- 必需的 checkout filter 无法安全禁用时，创建失败，不回退执行该 filter。
- 不初始化 submodule。
- 不复制 `.env`、依赖目录或其他 ignored 文件，不支持 `.worktreeinclude`。
- 不修改仓库、全局或系统 Git config，包括不启用 `extensions.worktreeConfig`。

## 5. 托管路径

托管工作树统一位于：

```text
~/Library/Application Support/Breath/worktrees/<workspace-id>/<work-session-id>/
```

如果工作区是仓库子目录，例如 `/repo/apps/frontend`，Breath 为整个仓库创建工作树，但会话终端从新工作树内的 `apps/frontend` 启动。

`worktrees/` 根目录标记为不进入 Time Machine 和 iCloud 风格的系统备份。Breath 不自动清理仍绑定活跃或已归档会话的工作树，也不设置“最近 N 个”上限。

## 6. 原子创建与失败恢复

工作树会话只有在以下步骤全部成功后才对用户可见：

1. 验证仓库与捕获创建基线。
2. 创建并验证托管工作树。
3. 持久化工作会话及工作树元数据。
4. 启动第一个终端。

任一步失败都停止已启动终端并回滚工作树和会话状态。如果工作树清理失败，不暴露半成品会话，而是持久化“待清理工作树”记录。

启动时 Breath 对账自身 `worktrees/` 目录与持久化会话：

- 有对应会话的目录继续验证。
- 没有对应会话的目录视为创建中断产生的孤儿工作树并自动清理。
- 清理失败时转成待清理记录并向用户报告。
- 对账只处理 Breath 自身托管根目录。

“设置 → 已归档”底部提供“待清理工作树”区域，显示路径、近似占用和最近错误，并提供重试清理、在 Finder 中显示和复制路径；不允许忽略并移除记录。启动时自动重试一次。

## 7. 持久化模型

每个工作会话保存其会话目录类型：

- `local`：目录由工作区本地检出派生。
- `managedWorktree`：目录由工作树元数据派生。

托管工作树只保存运行所需元数据：

- 工作树绝对路径。
- 规范化 Git common directory 或稳定仓库标识。
- 创建基线 commit hash。
- 工作区相对仓库根目录的路径。
- 最近一次导出的分支名，仅作历史提示。
- 创建、可用、不可用和待清理等生命周期状态。

不保存 diff、文件名列表、提交消息或终端内容。修改数量、提交风险和磁盘占用按需实时计算。

升级前缺少这些字段的工作会话全部迁移为本地会话，继续使用原工作区目录，不创建工作树，也不改变恢复行为。

## 8. 运行与恢复

- 本地会话依赖原始工作区目录。
- 工作树会话依赖托管工作树自身仍是有效且已登记的 Git worktree，不简单继承原始工作区的目录状态。
- 同一工作树会话的创建、分屏、冷启动恢复和 Agent 恢复都从同一个会话工作目录启动。
- 用户可以在终端中切换分支；Breath 尊重实际 Git 状态，不强制切回 detached HEAD。
- 工作树目录缺失、Git 元数据损坏或已不在 `git worktree list --porcelain` 中时，标记为“工作树不可用”，不自动重建、repair 或重新注册。
- 工作树不可用时不启动或恢复新终端，也禁止新分屏和导出分支。
- 如果终端已在运行后工作树才变得不可用，Breath 不自动终止进程；显示橙色警告，现有终端可以继续，退出、归档或进程结束后不再恢复。
- 原始工作区目录移动或不可用时，只要托管工作树自身仍然有效，已存在的工作树会话仍可运行；需要共享 Git 元数据的操作按实际可执行性开放。

正常退出等待所有正在进行的工作树操作完成，并在等待期间禁止启动新操作。系统强制退出不作保证。

## 9. 状态刷新与界面

- 工作树会话标题前显示 `arrow.triangle.branch`；不可用时显示橙色警告图标。
- 会话仍使用 `新会话 · HH:mm` 占位标题，之后可由第一个 Agent 原生标题替换。
- 悬停提示工作树路径和创建基线短 hash。
- 选中的会话沿用 Git 状态栏，每 3 秒刷新。
- 选择会话、应用重新激活、打开会话菜单以及执行导出或删除前立即重新检查。
- 后台会话不持续轮询 Git 状态。
- detached 状态显示 `detached @ abc1234`；用户切换分支后显示实际分支名。
- 工作树状态栏显示相对创建基线的提交数；历史偏离基线时显示警告。
- Git Diff、状态栏、Finder 和编辑器操作都使用会话工作目录，而不是固定使用工作区路径。

工作会话行统一使用 `…` 菜单：

- 所有会话：归档。
- 可用工作树会话：在 Finder 中显示、用编辑器打开、复制路径、导出为分支…
- 不可用工作树：显示路径、复制路径、归档。

## 10. 导出为分支

“导出为分支…”为操作当时的工作树 `HEAD` 创建一次性本地分支引用：

- 默认建议名为 `breath/<会话短 ID>`。
- 用户输入完整分支名，使用 `git check-ref-format --branch` 校验。
- 已存在的分支名被拒绝，不覆盖或移动已有引用。
- 工作树保持 detached HEAD；后续提交不推进已导出的分支。
- 工作树存在未提交修改时仍可导出，但对话框明确说明这些修改不属于导出分支，并显示修改数量。
- 用户若已经在终端中切换到分支，Breath 尊重该状态；目标名等于当前分支时提示无需导出。
- “最近导出到 `<branch>`”只是历史提示。删除安全检查始终重新读取实际本地分支和标签。

首版不实现 Local/Worktree Handoff。用户通过提交、导出分支，再在本地检出中切换、合并或 cherry-pick 来转移成果。

## 11. 归档

- 归档停止终端并保留托管工作树、布局和 Agent 恢复信息。
- Agent 回合运行中或存在其他前台进程时沿用现有停止确认。
- 归档不要求 Git clean，也不执行代码风险扫描。
- 恢复后仍使用原来的托管工作树。

## 12. 删除安全

永久删除本地会话仍只删除 Breath 元数据。永久删除工作树会话会删除托管工作树及其全部文件。

删除前按需计算：

- staged、unstaged、untracked 数量。
- 按路径去重的受影响文件合计。
- 从当前 `HEAD` 可达、但不被任何本地分支或标签引用的提交数。
- 与创建基线的历史关系。
- 不跟随符号链接的近似磁盘占用。

ignored 文件和构建缓存不触发代码丢失警告，但包含在近似磁盘占用中并随工作树删除。统计超时或权限不足时显示“大小未知”，不阻止流程。

如果没有未提交修改、没有未受本地引用保护的提交、历史未异常，则使用普通确认。否则使用高风险确认：

- 删除单个会话时必须输入会话标题。
- 移除工作区时必须输入工作区名称。
- 对话框显示修改数量、提交数量、工作树路径和近似占用。
- 输入完全匹配后才允许继续。

用户最终确认后，Breath 先停止相关终端，再重新检查风险：

- 风险没有增加时继续。
- 出现新的修改或未受保护提交时取消删除并要求再次确认。
- 状态变得更安全时可以继续。

目录已不存在时，普通确认后删除会话记录并尽力清理 Git 元数据。目录存在但 Git 元数据损坏或无法验证内容时，一律使用高风险确认，提示无法验证是否有未保存代码。

如果 worktree 被 `git worktree lock` 锁定，Breath 拒绝删除并显示锁定原因，不自动解锁或绕过。

## 13. 移除工作区

移除工作区聚合检查其全部工作树会话。任一工作树存在风险时升级为高风险确认。原始工作区目录始终不修改。

执行顺序：

1. 完成风险检查和最终确认。
2. 停止该工作区全部终端。
3. 停止后复检风险。
4. 逐个删除托管工作树；任一失败即停止。
5. 全部工作树删除成功后，删除 Breath 工作会话和工作区元数据。

中途失败时，已经删除的工作树对应会话标记为不可用，其余记录保留以便重试；不重新创建已经删除的工作树。

多个 Breath 工作区即使属于同一 Git common directory，也只清理各自拥有的托管工作树。

## 14. 路径和清理安全

Breath 只递归删除能够证明属于自己的路径：

- 规范化后仍位于 Breath `worktrees/` 根目录内。
- workspace ID 与 work-session ID 路径组件和持久化数据一致。
- 根目录及其父路径任一级都不是符号链接。
- 不把数据库中的任意绝对路径直接作为递归删除目标。

删除先请求 Git 移除 linked worktree，再删除托管根目录内经过验证的残留文件。工作树内部的符号链接只删除链接本身，磁盘统计和删除都不跟随链接目标。

普通状态刷新不自动执行 `git worktree prune`。只有删除会话、移除工作区、启动对账或待清理重试时才处理残留 Git 元数据。

Git lock、gc、repack 或其他外部冲突发生时，Breath 不删除锁文件，不强制写入，也不自动重试写操作；保留状态并提示稍后重试。只读检查可以短暂重试一次。

## 15. Git 错误诊断

- 默认显示经过清理的简短原因和退出码。
- “显示详细信息/复制详细信息”可以包含完整 Git stderr 和命令参数，但不包含进程环境变量。
- 远端 URL 中可能存在的用户名、密码和 token 在展示前遮蔽。
- 错误详情不持久化到数据库，也不上传。

## 16. 非目标

首版不包含：

- 本地检出与工作树之间的自动 Handoff。
- 创建时选择分支或复制未提交修改。
- `.worktreeinclude` 或 ignored 文件复制。
- submodule 自动初始化。
- Git LFS 或自定义 checkout filter 自动执行。
- sparse checkout、bare repository 或 unborn `HEAD` 支持。
- 外部 worktree 导入、展示或清理。
- 自定义 Git 可执行文件。
- 自动清理仍绑定工作会话的托管工作树。

## 17. 验收标准

1. 普通新建和 `⌘T` 继续创建本地会话；只有工作区菜单可以明确创建工作树会话。
2. 工作区根目录、仓库子目录和 linked worktree 中的目录都能创建托管工作树；非 Git、unborn、bare 和 sparse 仓库正确禁用。
3. 创建内容严格来自捕获的 commit hash，不包含本地未提交或 ignored 文件，不执行 hooks、filters、LFS 下载或 submodule 初始化。
4. 同一工作树会话的全部窗格、Git 状态、Diff、Finder、编辑器和 Agent 恢复都使用会话工作目录。
5. 创建失败不会暴露半成品会话；清理失败生成可重试的待清理记录。
6. 归档保留工作树；恢复继续使用原目录。
7. 导出分支只创建一次性 `HEAD` 快照，不覆盖已有分支，也不包含未提交修改。
8. 安全删除和高风险删除正确区分未提交修改、未受本地引用保护的提交、历史偏离和不可验证状态。
9. 删除前停止终端并复检；移除工作区只有在所有托管工作树删除成功后才删除元数据。
10. 路径校验、符号链接、外部锁和 Git 锁冲突不会导致越界删除或强制修改仓库。
11. 旧数据库中的工作会话全部兼容迁移为本地会话。
12. Breath 重启可以识别有效、不可用、孤儿和待清理工作树，并且不处理外部 worktree。
