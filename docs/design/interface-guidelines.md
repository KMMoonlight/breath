# Breath 界面设计规范

## 流程页面的信息层级

- 流程页面不得使用超大提示标题承载常规说明、来源选择或下一步操作。
- `ContentUnavailableView` 只用于真正没有内容、且当前区域无法继续工作的空状态，不得作为表单、向导或来源选择页的主体布局。
- 主工作区或详情面板尚未选择对象时属于被动状态，不使用带大图标和大标题的 `ContentUnavailableView`；使用次要色 `.caption` 提示，或直接留白。
- 向导中的常规标题使用紧凑的 `.headline` 或正文层级，解释入口使用次要色信息图标，主要操作紧邻相关字段。
- 三个及以上平级来源使用明确命名的 Tab 切换，每个 Tab 只展示该来源需要的输入、解释入口和结果，不依赖输入内容猜测来源。
- 用户可以在当前页面修正的输入错误、网络错误和来源不可用状态应就近内联展示。Alert 只用于必须中断当前流程的确认或无法继续的意外错误。

## 解释文字

- 用于补充字段含义、工作原理、前置条件或背景信息的静态解释文字，不得作为正文、页脚或空状态描述直接展示。
- 解释文字统一放在 `info.circle` 信息图标的悬浮提示中，并同时提供完整的 VoiceOver 提示。
- `info.circle` 承载的解释提示统一在指针停留 300ms 后出现。
- 解释提示使用不透明常规底色的自定义浮层，完整换行展示全部文字，不使用系统 Popover 的液态玻璃样式。
- `info.circle` 不得单独、悬空展示；必须与其解释的可见标题、字段、状态或操作文字组成同一个 `ExplanationLabel`。
- 解释提示只由 `info.circle` 触发，并以该图标作为弹出锚点；关联文字只负责提供上下文，不扩大悬停触发区域。
- 按钮、菜单和工具栏图标的功能提示不属于解释文字，继续使用系统原生 `.help`，不得套用 `ExplanationLabel` 或自定义解释 Popover。
- 每条解释应紧邻对应内容；不得把多个无关区域的解释合并到一个页面级提示中。
- 操作结果、进度、错误、警告和当前状态不是解释文字，必须在相关位置直接展示。
- 破坏性操作确认中的对象、范围和后果属于决策信息，必须在确认界面直接展示，不得隐藏到悬浮提示。

## 明确触发外部操作

- 会访问网络下载内容或写入磁盘的操作，必须使用包含明确动作动词的文字按钮，不得仅依赖图标或整行点击。
- 不得使用导航箭头、整行点击或其他看似“查看详情”的控件触发下载、安装、覆盖、卸载等操作。
- 远程 Skill 使用“安装”进入下载与内容检查流程。skills.sh 搜索结果只有在目录条目 ID 与本机安装记录或受支持的共享清单精确一致时，才可以展示已安装 Agent；不得根据名称、提交者或 Repo 猜测已安装。
- 精确匹配的 Skill 尚有可用 Agent 未安装时，操作使用无省略号的“安装到其他 Agent”，并从本机已安装副本准备内容，不再次下载；所有可用 Agent 均已安装时只展示状态，不提供安装操作。
- 相同内容、同名占用和是否覆盖仍只在解析实际候选后的安装预览中确认。只有最终安装确认才允许写入 Agent 目录。
- 长时间操作的进度反馈应贴近触发按钮，显示“正在下载”或“正在安装”等具体状态，不使用缺少上下文的独立加载图标。

以上规则适用于 Skills 安装向导及后续新增的同类分步流程。
