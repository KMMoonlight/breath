# Constrain managed-worktree deletion to verified Breath-owned paths

Breath deletes a managed worktree only when its canonical path remains inside Breath's application-support `worktrees/` root, its workspace and session path components match persisted identifiers, and no path component resolves through a symbolic link. Cleanup asks Git to remove the linked worktree first and may delete only verified residual files inside that root; an arbitrary absolute path from persisted metadata is never accepted as a recursive-deletion target. This deliberately rejects some recoverable-looking cleanup cases in exchange for preventing corrupted state from deleting user-owned directories.
