# Constrain managed-worktree deletion to verified Breath-owned paths

Breath deletes a managed worktree only when its canonical path remains inside Breath's application-support `worktrees/` root, its workspace and session path components match persisted identifiers, and no managed path component resolves through a symbolic link. Before deletion, Breath resolves `--git-common-dir` again from the checkout itself and requires it to match the persisted repository identity. The session working directory is also resolved component by component: a symbolic link or a final path outside the managed checkout makes the Worktree unavailable and blocks deletion. If the checkout directory has already disappeared, Breath may forget its own Work Session record but does not use the unverified persisted common directory to mutate Git metadata. Cleanup asks Git to remove the linked worktree first and may delete only verified residual files inside that root; an arbitrary absolute path from persisted metadata is never accepted as a recursive-deletion target. This deliberately rejects some recoverable-looking cleanup cases in exchange for preventing corrupted state from deleting user-owned directories or acting through the wrong repository.
