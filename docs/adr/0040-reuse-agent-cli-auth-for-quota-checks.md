# 复用 Agent CLI 登录身份查询额度

额度检查复用各 Agent CLI 当前已登录的身份，不在 Breath 中新增 OAuth 登录或 API Key 输入。查询优先通过服务商官方网络接口完成：先使用公开 API 或官方协议；没有公开 API 时，可以从官方客户端行为确认额度私有接口，并仅在服务商未禁止且这种使用已获授权时调用。找不到可用网络接口时，再使用官方 CLI。只有服务商允许第三方复用 CLI 凭据时，Breath 才可以只读获取现有令牌，并仅在请求内存中调用该服务商的官方 HTTPS 域名；若官方 OAuth 契约会轮换刷新令牌，则只允许按官方客户端的锁和同目录原子替换约定更新同一份 CLI 凭据。除这次原子替换所需的同目录临时文件外，令牌不得复制到 Breath 的数据库、配置、缓存或临时文件，不得进入日志、错误、崩溃报告和界面，也不得发送给第三方。服务商明确禁止第三方复用凭据，或 Breath 无法确认这种使用已获授权时，不通过逆向私有接口绕过；若也没有合规的官方 CLI 或协议，则将该 Agent 标记为“不支持查询”。这个选择优先获得无需启动 CLI 的查询体验，同时接受私有接口可能随服务商变化而失效，并保留服务商的认证边界。

当前接入依据必须可在实现测试中审计：Codex 首选官方 `app-server` 的 `account/rateLimits/read` 协议，仅在该协议不可用时尝试官方客户端同源的 ChatGPT 用量接口；Claude 的用量地址、OAuth 请求头与响应字段来自已安装官方 Claude Code 客户端的当前行为，网络查询不可用时降级到官方 `/usage`；Kimi Code 复用官方开源客户端 `KimiOAuthToolkit.getManagedUsage` 的同一条路径，只读加载 `~/.kimi-code/credentials/kimi-code.json`，按官方 OAuth 刷新协议和 `oauth/kimi-code.lock` 协调令牌轮换，再调用固定的 `https://api.kimi.com/coding/v1/usages`；OpenRouter 只调用其公开文档中的 `/api/v1/credits` 和 `/api/v1/key`。所有地址固定为对应服务商 HTTPS 域名，不接受配置覆盖或重定向到第三方。Antigravity CLI 的系统钥匙串凭据不导出或复用，额度通过官方 `/usage` 查询；GitHub Copilot CLI 使用官方 `/clikit quota`；Factory Droid 使用官方 `/limits`。这些交互命令必须运行在 Breath 创建的伪终端中，等待终端完成首屏渲染后再发送只读额度命令，读取额度面板文本后立即退出，不能发送用户提示词、执行工具或修改 Agent 配置。查询的硬超时不能等待不响应取消的 CLI 子任务，取消时必须终止由 Breath 启动的进程并停止伪终端读取。Claude Code 显示 `API Usage Billing` 时只有当前会话的本地费用统计，不是账户订阅额度，因此返回“不支持查询”，不能把会话统计误报为账户额度。

额度能力与 Agent 的全局集成最低版本分别判断：只要 CLI 已安装就允许额度适配器尝试自己的官方只读渠道，再由渠道本身返回“未登录”“不支持”或查询结果，不能因为 Hooks、Skills 等其他集成的版本要求而提前拦截。Qwen Code 的 `/stats`、OpenCode 和 Pi 的本地 token 统计不是账户剩余额度；这三个多 Provider Agent 目前只在当前 Provider 可被确定为 OpenRouter 时查询 OpenRouter 额度。Qwen 的 Provider 解析同时支持当前 `security.auth.selectedType`、`model.baseUrl` 和 `modelProviders` 配置结构。Cursor Agent 在没有确认合规的只读额度路径前保持“不支持查询”。服务商行为或授权边界发生变化时，相关私有路径必须移除或降级为官方 CLI/协议。
