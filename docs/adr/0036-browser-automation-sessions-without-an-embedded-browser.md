# 为每个 Agent 对话提供隔离的浏览器自动化会话

Breath 的浏览器功能以由 Agent 驱动、用户监督的浏览器自动化会话为产品边界。每个 Agent 对话至多拥有一个隔离的浏览器自动化会话，会话可以包含多个具有稳定身份的浏览器页面；同一工作会话中的多个 Agent 对话可以并行操作各自的会话，不能引用彼此的页面、Cookie 或 Local Storage。工作会话管理共享浏览器运行时，首版以一个 Chromium 实例承载多个相互隔离的 Browser Context，从而减少并行 Agent 的启动和内存成本；具体进程拓扑是内部实现，不进入 Agent 协议。

每个 Agent 对话拥有独立且持久的 Browser Profile，Cookie、Local Storage 和登录状态可以跨运行时恢复，但不与其他 Agent 对话共享，并在 Agent 对话或其工作会话永久删除时一并删除。浏览器运行时在该工作会话第一次浏览器操作时按需启动，切换工作会话或关闭主窗口不会停止它，使后台 Agent 可以继续验证；归档工作会话或执行 `⌘Q` 时停止进程，并在之后首次使用时按需恢复各 Agent 上下文。

浏览器自动化会话通过独立浏览器运行时完成结构化网页操作，并在原生应用中呈现必要的状态、截图、日志和操作记录。首版不采用 Computer Use，也不嵌入供用户日常浏览的 WebView 或 Chromium。Agent 只有在用户显式安装可逆的浏览器集成后才能自主发现这项能力；该集成只在 Breath 会话环境与当前本地 Socket 握手同时有效时激活，在普通终端中静默休眠，也不读取 Prompt 或 Transcript。这个边界保留了原生应用外壳，优先优化并行自动验证的资源、token 和执行效率，同时接受无法在 Breath 内直接操作完整实时网页的取舍。
