# Use session-owned managed worktrees outside project directories

Breath creates each managed worktree exclusively for one Work Session. For a user-created Worktree Session, the user selects a local or remote-tracking start branch, defaulting to the workspace's current branch. Breath resolves that branch to a baseline commit and creates a dedicated `breath/<work-session-id>` session branch; it never checks out the selected start branch in the new worktree. Task-created sessions may instead use their explicit task branch. The worktree is stored under `~/Library/Application Support/Breath/worktrees/<workspace-id>/<work-session-id>/`. This keeps parallel Agent work isolated without adding Breath-owned directories to projects, while deleting the worktree preserves its session or task branch.

Creation and cleanup are not atomic across Git, the filesystem, terminal launch, and persistence. Breath instead keeps the Session unpublished while it validates the repository, creates and validates the managed checkout, starts the first terminal, and saves the completed snapshot. A later failure triggers compensating cleanup. If a persistence conflict already wrote an unpublished candidate snapshot, Breath first restores the last published snapshot; if that compensation cannot be saved, it reports both errors and preserves the checkout rather than leaving durable state that points to a deleted directory. A branch created by the failed operation is removed only if it still points to the captured baseline. Cleanup failures surface the affected path and both errors instead of being described as transactional rollback. A partially failed `git worktree add` may use forced removal only for that never-published provisioning artifact; normal Session deletion never forces removal and always preserves the bound branch. Initial creation copies only committed content and never transfers staged, unstaged, untracked, or ignored local files.
