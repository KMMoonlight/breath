# Use session-owned managed worktrees outside project directories

Breath creates each managed worktree exclusively for one Work Session and checks out a user-selected local task branch. If the task branch does not exist, Breath creates it from the workspace repository's captured `HEAD` commit; if it already exists, Breath checks it out without moving it. The worktree is stored under `~/Library/Application Support/Breath/worktrees/<workspace-id>/<work-session-id>/`. This keeps parallel Agent work isolated without adding Breath-owned directories to projects, while commits continuously advance the task branch and deleting the worktree preserves that branch.

Creation is atomic at the use-case boundary: Breath validates the repository and branch, creates and validates the managed checkout, starts the first terminal, and only then persists and publishes the Session. If a later step fails, Breath stops any partially started terminal and synchronously rolls back the unpublished checkout. Cleanup failures surface the affected path together with both the creation and cleanup errors instead of being silently ignored. A partially failed `git worktree add` may use forced removal only for that never-published provisioning artifact; normal Session deletion never forces removal. Initial creation copies only committed content and never transfers staged, unstaged, untracked, or ignored local files.
